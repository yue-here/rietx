# The batch index

Load it when you hold many results fitted as separate jobs and want their diagnostics read as one table rather than one fit at a time.

*A reference file of the `rietx` skill. The body it belongs to is
[`SKILL.md`](../SKILL.md). Generated by `docs/skill/make_api_index.py` from the
installed package, like [`api.md`](api.md), and loaded only by a session doing
this; everything in `rx.` is `import rietx as rx`.*

## Diagnostics over a batch

`rx.diagnostics_summary(results)` counts a batch's diagnostics: each code's count of results fired on, the warning rows a result carries per purpose, and the codes ranked by their share of the warnings. Every level is taken from the view `summary()` prints, so `deliverable=` and `levels=` mean what they mean there. A code that fires on most of a batch is a statement about the model or plan the batch shares (`references/batch.md`, 9c.18).

- `rx.diagnostics_summary(results: Iterable[RefinementResult], deliverable: str | None = None, levels: dict[str, str] | None = None) -> DiagnosticsSummary` — The diagnostics of a batch of results as counts: each code's firing rate, the warning rows a result carries per purpose, and the codes ranked by their share of the warnings (WP-2037).
- `rx.DiagnosticsSummary` — The diagnostics of a batch of results as counts, from `diagnostics_summary`.
  Fields: `n_results: int`, `deliverable: str | None = None`, `levels: dict[str, str] = {}`, `codes: list[CodeTally] = []`, `warnings_per_result: dict[str, float] = {}`, `pareto: list[ParetoRow] = []`
- `rietx.report.batch.CodeTally` — One code's firing over a batch.
  Fields: `code: str`, `n_results: int`, `rate: float`, `n_rows: int`, `n_error: int`, `n_warning: int`, `n_info: int`
- `rietx.report.batch.ParetoRow` — One code's share of a batch's warning rows, in Pareto order.
  Fields: `code: str`, `n_warning: int`, `share: float`, `cumulative: float`
