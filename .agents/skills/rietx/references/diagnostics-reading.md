# 7i. The readers: what was changed, assumed or noticed about your own file

Load it when you passed `diagnostics=[]` to `read_pattern`, `Structure.from_cif`, `RefinementTree.load` or `load_instrument_profile` and something came back, or when one of these codes reached `result.diagnostics`.

*A reference file of the `rietx` skill. The body it belongs to is [`SKILL.md`](../SKILL.md); section numbers are the ones the body cites.*

These fire on **your own** data and structure files, at the read, and each one
is conditional on a quirk that file happens to have. That separates them from
§7, and the channel they arrive on does not: most of them also reach
`result.diagnostics`, and several of §7's own rows are equally the reader's.
They are here because of how often you will meet one. A vendor attenuator, a
scan stored backwards, a dead detector cell: none of these is a thing a fit
does, and a table an agent loads to look up what its fit just said should not
be carrying rows about file quirks it does not have.

They share the readers' rule. A reader may repair a stranger's file only where
it can say that it did, so every repair below is on this channel and none of
them is silent. A reader that cannot establish something **withholds** it, and
two of these rows are about a number you are therefore not being given.

Two families sit elsewhere. Another program's project or recipe file is §7g,
[`diagnostics-projects.md`](diagnostics-projects.md). What a file you *wrote*
could not carry is §7h, [`diagnostics-gsas.md`](diagnostics-gsas.md).

| Code | What it means you must not do |
|---|---|
| `CIF_SPECIES_NORMALISED` | (info — from the reader: pass `Structure.from_cif(..., diagnostics=[])` to collect it; it is not on `result.diagnostics`) Assume the model's species are the file's literal type symbols. Each message names its substitution and `where` lists the atoms it touched. |
| `CIF_CELL_ANGLE_CORRECTED` | (warning — from the reader, same channel as `CIF_SPECIES_NORMALISED`) Assume the cell is the file's. The deviation is information: if it is real, the symmetry is lower than the symbol claims. Past 0.1° nothing is corrected and the read still raises, because the symbol and the angle contradict each other and choosing between them is yours. |
| `CIF_SITE_MULTIPLICITY_DISAGREES` | (warning — from the reader, same channel) Assume the site has the multiplicity its coordinates give. Nothing was moved. (Where a move of up to 1e-3 *does* reach the stated one, the reader moves the site and `SITE_SNAPPED_TO_SPECIAL_POSITION` says so.) ZMV and every weight fraction follow the coordinates. |
| `CIF_SITE_TWINS_MERGED` | (warning — from the reader, same channel as `CIF_SPECIES_NORMALISED`) Assume the site's coordinates are the file's. `value` is the twin distance in Å. |
| `CIF_SITE_LISTED_TWICE` | (warning — same reader, same channel) Assume every listed site is in the phase: one was dropped. A copy that differs in occupancy, displacement, disorder group or moment is refused instead. |
| `DECLARED_RANGE_RESTORED` | (warning, or info when only a unit came back — from the history and instrument-profile readers: pass `diagnostics=[]` to `RefinementTree.load` or `load_instrument_profile`, or read `Project.history_diagnostics` after `Project.open`) Assume a reopened model refines exactly as the run that wrote it did (issue #204, where an Fe Biso reached −165 Å² at unchanged Rwp). A range of your own goes on the `Parameter` explicitly, and wins. |
| `DECLARED_RANGE_NOT_RESTORED` | (warning — the same channel as `DECLARED_RANGE_RESTORED`) Trust that parameter's value, or assume it is bounded. `value` is the first such value and the message names where it is stored. A real measurement outside a default box, such as a coarse neutron line's Caglioti `v` under its floor, needs a range that holds it before the next fit; anything else is the unbounded walk #204 describes and not a number to quote. |
| `PATTERN_SCAN_REVERSED` | (info — from the pattern reader: pass `read_pattern(..., diagnostics=[])` to collect it) Assume the point order in the file is the point order you are fitting. An index into the file is not an index into the pattern. |
| `PATTERN_DUPLICATE_POINTS` | (info — from the reader) Quote the file's point count as the fitted channel count. A repeat with a *different* intensity is not reported here: it raises, because averaging invents a datum and dropping picks one. |
| `PATTERN_ROWS_DROPPED` | (warning — from the reader) Quote the file's line count as its point count. `where` lists the dropped line numbers. PDFgetX2's header put a phantom point at (0, 1) on every file one user had. Only the two/three-column reader counts columns. |
| `PATTERN_MULTISCAN_DEFAULTED` | (warning — from the reader) Read the result as a fit to the file. It is scan 0 of N, for any N. Pass `scan=` (or `list_scans(path)` first) before quoting anything. |
| `PATTERN_X_AXIS_ASSUMED` | (warning — from the reader) Trust the 2θ scale. It fires when the axis name is unrecognised and when the file states no axis. Each format states it somewhere different (`.chi`'s line-2 label, `.ras`'s `*MEAS_SCAN_AXIS_X`, `.uxd`'s `_DRIVE`, `.xrdml`'s `scan/@scanAxis`), and the message names both the field and what it held. The code means **unrecognisable**, never "recognisably not 2θ": an axis that *is* recognisably q, d, ω, χ, φ or a translation is **refused**. Most vendor files are not powder scans (Measured: 4 of the 5 real `.uxd` files obtained are pole figures or rocking curves), and a block marker is not evidence either: a rocking curve is stored under `_2THETACOUNTS` too. |
| `PATTERN_X_AXIS_IMPLAUSIBLE` | (warning — from the reader) Fit the interval it names; `where` carries the interval to exclude. It is checked for every format after the read. Its other half is a **refusal**: an axis running past 180° raises, which is how a file read in centidegrees surfaces, and its message offers the ÷100 reading when the two/three-column reader took the file and the result lands in range. A point at exactly 0° can be a header row with the data's own column count, which `PATTERN_ROWS_DROPPED` cannot see. |
| `PATTERN_INTENSITY_NET` | (info — from the pdCIF reader) Hold the background at zero because the item's name says it was subtracted. The intensities are the file's `_pd_proc_intensity_net` column, which the pdCIF dictionary defines as background-subtracted, and `pattern.metadata["intensity_item"]` names it. A file that also states a total column reads that one instead. Look at the column's minimum before deciding: `PATTERN_NET_HAS_BACKGROUND` fires when it contradicts the label. |
| `PATTERN_NET_HAS_BACKGROUND` | (warning — from the pdCIF reader) Do not hold the background at zero. The file's `_pd_proc_intensity_net` column is labelled background-subtracted but never comes within the threshold of zero in y/σ, so a background is still in it; the code's value is that smallest y/σ. The numbers are read as stated and y is never shifted. Where the file also states `_pd_proc_intensity_bkg_calc`, hold that curve additively (`BackgroundFixedPlusChebyshev`); otherwise refine a Chebyshev background, with a `HumpComponent` for a broad hump. A pattern windowed onto a peak cluster, with no empty baseline in range, can fire it on a column that was subtracted; look at the range before refining a background. |
| `PATTERN_ZERO_WEIGHT_EXCLUDED` | (info — from the pdCIF reader) Assume the pattern's channel count is the fitted count. A `_pd_proc_ls_weight` of zero is the pdCIF dictionary's "not used for refinement", so those points are in `excluded_regions` |
| `GSAS_BANK_COMMENTED` | (info — from the reader) Nothing, if the file is the measurement. A file with a live bank beside a commented one reads the live one and says nothing, since commenting a bank out is also how a bank is disabled. |
| `PATTERN_INTENSITY_SCALED` | (warning — from the reader) Quote esds, χ² or a σ-normalised residual from this fit as if the weights were measured. It fires when the values are not whole numbers, when the unit is unrecognised, and when a rate carries no counting time. The *parameters* are largely unaffected; the uncertainties are not quotable. |
| `PATTERN_SIGMA_CONSTANT` | (warning — from the reader) Quote χ², GoF or a σ-normalised residual as if the weights were measured. A two/three-column file gives up any positive third column, and a PDFgetX2 `.sq` has a constant 1.0 there with its real uncertainty in column four. Set `pattern.sigma = None` for Poisson weights, or re-export with the esd where the reader looks. Checked for every format that reads a σ. |
| `PATTERN_DEAD_CHANNELS` | (warning) Fit a range that contains them, or read the parameters at their bounds as the cause. (Measured: on the ILL D1B file this comes from, two cells at σ = 1.0 sit beside background at σ = 55.1 and carry about 3000 live channels each: Rwp 0.087 against 0.0074 with them excluded, every background model dragged through zero at the top of the range, the Caglioti terms at their bounds, every Biso pinned at zero. None of those fourteen bound hits is the problem.) `where` carries the interval to exclude, and nothing is excluded for you, since `project.fitted_mask` is the caller's. It needs the file's own σ column: under the Poisson fallback a pattern with no esds emits nothing here, and the silence is not an all-clear. Also on `PatternDiagnostics.dead_channels` before any refinement, from `diagnose(data)`, and on the `diagnostics=` list `read_pattern` takes. |
| `RAS_ATTENUATOR_PRESENT` | (warning — from the reader) Compare intensities across the 2θ range this names. The message names the affected points. Contrast `XRDML_ATTENUATOR_APPLIED`, where a real file settles what no Rigaku file can. |
| `XRDML_ATTENUATOR_APPLIED` | (info — from the reader) Nothing. σ = √counts·factor, **not** √y. It is settled, where `RAS_ATTENUATOR_PRESENT` is not: (Measured: a real file shows the raw series *dipping* at exactly the attenuated point of a substrate reflection). A factor of 188 over one point is normal. The case GSAS-II gets wrong, weighting 1/y regardless. |
| `BRML_ABSORBER_ENGAGED` | (info — from the reader) Nothing to the intensities. σ was derived as √(y/a)·a rather than √y. The third answer to one question: `RAS_ATTENUATOR_PRESENT` reports, `XRDML_ATTENUATOR_APPLIED` multiplies, and this one leaves the values alone because one real file shows them continuous (Measured: one file; the convention is applied to every `.brml`). |
| `READER_OPTION_IGNORED` | (info — from the reader) Assume a reader option you passed took effect, above all a `block` or a `scan` you meant to select. Check `identify_format` claimed the reader you expected. |
