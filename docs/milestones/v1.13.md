# v1.13 — the next release

**Accumulating since 2026-11-18** (version → `1.13.0.dev0`), the day 1.12.0 was
cut. This is the record of release 1.13: the narrative of everything landing
on `main` before the cut, and the measured ship block after it (WP-1540). A
milestone's own scope and acceptance live in its named record
([magnetic.md](magnetic.md), [generality.md](generality.md),
[parametric.md](parametric.md), [gui-overhaul.md](gui-overhaul.md) and
[series.md](series.md) for the five open now).

met, and the cut lists the ones it ships.

## How v1.13 is getting here

### 1.12.0 cut and published (closed 2026-11-18)

The sixth weekly cut came fourteen days after 1.11.0 and carried 150 merged pull requests.
The staged notes were far from complete. Of the pull requests that changed source and did not
touch the notes, 61 had no mention, and the cut wrote a note for each one a user can see.

Two staged claims did not hold. The notes said a 1.12 result opens in 1.11.0. Measured both
ways against 1.11.0's PyPI wheel, 1.11.0 refuses every structure, result and project 1.12
writes, and opens its instrument. The notes also gave the kernel floor as 1.4, where the pin
had been 1.5 since #1554. The maintainer ruled that the rebuilt GUI at `/next` is announced,
with its unfinished state stated (2026-11-18).

The nightly dispatched on the release commit passed its three gate jobs. `full` failed on the
swapped minimum WP-1418 tracks, and the macOS job got no runner. Neither gates. The counts are
in [v1.12's appendix](v1.12.md#appendix--acceptance-at-ship-2026-11-18). The version and the
notes merged in #1687.

### WP-1464 a screen reads the batch references first (closed 2026-11-19)

An agent about to run a screen of candidate fits is now sent to the batch references before it
launches, and those references carry what one such screen paid for (#1681). A free cell let an
absent candidate take a present phase's peaks: on the CPD zincite pattern an absent fluorite shrank
its cell 10.8 % and took 14 ± 12 wt %, too little for any code to fire. Pinning the kernel pool to
one thread per worker, which the skill had advised, made a 10-worker screen 1.9-2.8× slower, so
the advice was reversed and the package keeps its default. Then `rietx runs` (#1695, the verb
decided by the maintainer on 2026-11-19) summarises the run directories a batch leaves, one block
per label: runs by state, the wall from first start to last end, and the slowest run against the
median, failed runs timed too. The screen behind the WP had printed a `nan` median, because its
failed jobs carried no time, and never saw its 76-minute failure. Checked while a job runs, the
verb also prints how long its longest live run has gone against that median (the maintainer's
ruling of 2026-11-19), so a runaway shows before it ends.

### WP-2222 the closing stage off by default (closed 2026-11-19)

Users complained of fit time, and Yue ruled TOPAS's accuracy sufficient. A
default plan therefore runs its declared stages alone, at 1.2-1.9× less wall
clock on the measured cases, and its answers move 0.16-2.0 esd from the
closing stage's. `CLOSING_WINDOW_TOL` (1e-3) stays the opt-in for an answer to
publish. Three places keep it on Yue's ruling of the same day, each where an
error spreads beyond one fit: a Pawley series carrying intensities (its Rwp
drifted 0.034 → 0.037 over four patterns without it), the `lab_calibrate`
preset, and the guides that quote numbers. A GUI preview starting from a
default fit shifts by up to 0.13 % of the strongest peak; WP-2226 retunes it.

### A clicked value opens on its full stored value (WP-2223, closed 2026-11-19)

Yue asked how a value drawn as ×10ⁿ looks once clicked, and ruled "go with best practice". The
GUI now follows the spreadsheet model in the Parameters panel and the Interactive tab, on both
pages. A number is drawn rounded and edited to its last digit, and text left as it opened is no
edit. Before, Enter on an unchanged Interactive value moved it by its 13th digit. The drawn
digits typed into a Parameters cell are now an edit, since they are a different number from
the one the editor showed. The Interactive box reads `1.5×10⁻³` as the range fields do.
PR #1709.

### WP-2224 a re-fit of a converged model runs one stage (closed 2026-11-19)

A second `fit` on a model its last fit of the same pattern converged runs one stage,
`warm_refit`, freeing at once what the plan frees. Under WP-2222's default it lands within
0.045 esd of the first fit's answer on the eight comparison standards, at 0.15-0.27 of a staged
re-fit's evaluations. A first fit stays staged: from a cold start one stage reached 20 of 48
starts. On Yue's rulings of the same day a re-fit runs staged when its plan frees a parameter
the converged fit held, since that parameter starts cold (brucite's March-Dollase block landed
2.25 esd off in one stage), and a model swap through `edit` stays staged. A rejected one stage
falls back to the plan with `WARM_REFIT_REJECTED`. `summary()` says which way a re-fit ran.
The GUI still refines staged; WP-2227 gives it a view of how a run went.

### WP-2101 the parametric surface as it stands, in the manual (closed 2026-11-19)

Someone arriving from TOPAS or GSAS-II can now find what rietx's parametric refinement
does in the pages they read first. `switching/topas.md` maps TOPAS's parametric vocabulary
(`prm`, `local`, `#list`, an equation on a `prm`, `!`) to rietx's spellings, lists the
constructs that have no spelling yet, and gives a five-step recipe for porting an input
that does not import. `switching/gsas2.md` shows a GSAS-II sequential refinement as a
rietx chain. `reference/parametric.md` tables the accepted target kinds, with an executed
block. The WP's inventory counts every parametric construct in two real TOPAS inputs
against its rietx spelling, and the milestone's agent row is judged against it.
`guides/equation.md` documents two traps: a coefficient no stage frees, and a plan that
cannot reach a variable. On Yue's rulings of 2026-11-19 a fit now names both with
`VARIABLE_NOT_FREED`, a warning in a joint fit and in a single fit, which a `hold`
silences in a single fit. A refusal of an unknown target names `.parameters()`. PRs
#1573, #1632, #1654 and #1714; a joint fit's `hold` is WP-2103's.

### WP-2150 a tied cell value that contradicts its space group is repaired at read or refused (closed 2026-11-19)

A cell that contradicts its space group's ties no longer builds silently. Before, under a
cubic group b = 5.9 beside a = 5.641 became 5.641 with no word. Now the parameter table
refuses it, naming the entry, both values and the symbol, at a relative bound of 1e-5
(at most 10 ppm in d). A CIF whose two values agree within the digits it prints is read as
the tied cell and says so with `CIF_CELL_TIE_CORRECTED`. A project file from GSAS-II,
GSAS, TOPAS, FullProf or a recipe is refused naming the file, and `Project.create` refuses
before it writes the directory. A history saved by an older release opens with its stored
nodes repaired and `HISTORY_CELL_TIE_CORRECTED`. The cost: a script that edits
`cell.a.value` alone on a cubic or tetragonal phase now raises. Yue approved the three new
reader texts and the table's refusal on 2026-11-19. The indexing acceptance ranking is
unchanged. PR #1698, from issue #1669; the Jana reader's call is WP-1314's.

### WP-2225 a fit says when it held an instrument width beside a specimen width (closed 2026-11-20)

A plan that frees an instrument width beside the specimen width with the same angular shape
gets an answer whose specimen widths depend on the stage order. The data fix only each pair's
sum, and since WP-2002 the stage holds the instrument half at the value an earlier stage left.
On the four comparison standards that run the QPA plan, a staged re-fit moved zincite's V by
1.49 reported esd. On cpd-1a, two Biso starts put fluorite's Lorentzian strain 5.11 esds apart.
Two fixes inside one fit were measured and dropped: freeing the instrument half once its specimen
partner sits on its floor never fired on cpd-1a and froze LaB₆ + cBN's specimen widths, and alternating
the two halves had not converged after 8 rounds on the multi-phase families. On Yue's ruling of
2026-11-20 a fit whose last stage held an instrument width now carries a warning under the
microstructure and calibration purposes. A second ruling, of 2026-11-21, named it
`INSTRUMENT_WIDTH_HELD`. The warning names the held widths and the stage whose values they keep,
and suggests calibrating the instrument on a standard. While it fires, the microstructure summary
prints the size and strain as not quotable. It moves no number, and fires on zincite, fluorite,
corundum and brucite of the eight standards. Changing rietx's own
comparison and acceptance plans to calibrate first is a possible follow-up, not filed. PR #1722.

### WP-2219 a parameter the data cannot place has no esd (closed 2026-11-21)

A parameter on a combination the data do not determine now reports no esd. Before, it
reported its spread along the directions the data did measure. That number was short by a
factor nothing bounds: on synthetic LaB6 with W, `gauss_size` and `gauss_strain` free, two
starts landed 140 esd apart, and the esd jumped by 10⁷ across the inversion's cut. The rule
holds in a single fit, a joint fit and a Pawley fit. `COVARIANCE_DIRECTION_DISCARDED` keeps
firing and says the parameters have no esd. The CIF writes `?` in the su item. This follows
linear-models practice (Searle 1971); GSAS-II and TOPAS quote the truncated esd. Holding W on
the width triple was built and reverted, because the full suite showed it moved answers the
WP did not name. Two calls went to WP-2230 on the maintainer's ruling: an estimable
combination such as a tie's sum loses its esd today, and 535 Pawley intensities on a
discarded direction sit in no overlap group. PR #1718. WP-2230 found the 535 a subtraction
artefact of the probe: every touched intensity sits in an overlap group.

### Every instrument edit in the GUI releases the holds it ends (WP-2229, closed 2026-11-21)

A hold or a free flag in the GUI names a parameter path, and the package keeps it across a
model edit so a checkout can restore it. WP-2218 cleaned these up on one screen, the
Background graph at `/next`. Now the server does it for every instrument edit, whichever
screen sent it. It compares the parameter tables before and after the edit. It releases the
holds on the paths the edit removes or redefines, and it gives each path the edit builds the
free or fixed flag its new model says. A held Chebyshev term no longer holds the P-spline term
of the same name, and an emission line removed takes its hold with it. The answer names the
ended paths, and the Parameters panel drops every pending edit on them, restraints and atom
positions included. The `/api/instrument` request lost its `unhold` and `free` fields. Four
review findings stay open in the WP's record, one of them folded into WP-2212. PR #1741.

### WP-2107 an equation over a reflection (closed 2026-11-22)

A user can write a peak's width, position or intensity as an equation in its hkl and its
angle, refine the coefficients with exact derivatives, and share or parametrise them in a
joint fit. `rx.PeakEquation` sits on `Phase.peak_equations` and `Instrument.peak_equations`
(schema 0.62), with five targets: `lor_fwhm`, `gauss_fwhm`, `gauss_fwhm_squared`, `shift`
and `intensity_factor`. The grammar gains `orbit_mean` and `harmonic` (`GRAMMAR_VERSION`
2), and an equation that differs between the images of one Laue orbit is refused by name,
at trial coefficients as well as the stored ones. Each target matches the built-in term
with the same physics to 1e-12 relative (`lor_strain`, U, sample displacement at both
levels, Biso). Twelve noise seeds recover every coefficient with a mean z-score between
−0.24 and +0.31, and twelve ZrP₂O₇-shaped joint ramps recover all twelve coefficients with
every mean z-score 0.50 or less. Three diagnostics are new: `PEAK_WIDTH_NOT_POSITIVE`,
`QPA_INTENSITY_FACTOR` and `PEAK_EQUATION_SHARED_ACROSS_WAVELENGTHS`, the last two worded
on Yue's rulings of 2026-11-20. PR #1635, merged 2026-11-20. Its open follow-ons are WPs
2151 (the ZrP₂O₇ real-data run), 2152 (a `wavelength` name), 2153 (the LM width rows read
the equation's term) and 2154 (WP-2108's holder offset in a joint fit).

### WP-2151 the ZrP₂O₇ input's peak equations on its data (closed 2026-11-22)

The ZrP₂O₇ input's 2θ calibration curve and each phase's TCHZ terms now refine on the real
data as peak equations, beside the cubic temperature calibration. One joint fit of the 37
patterns shares every coefficient, as the input does, and converges at Rwp 31.79 % on 1167
free parameters (TOPAS 31.56 %). Two things in the input showed up. TCHZ's z/cos²θ term
is z + z·tan²θ, so u, w and z are one exact degeneracy, and z is held for the reported
esds. The stored silicon Gaussian is below zero at every reflection, so its four
coefficients start with no gradient and never move; seeded above zero, the fit reaches
Rwp 31.48 % and χ² falls by 3935. Closing the plan at `CLOSING_WINDOW_TOL` moves no
coefficient by more than 0.48 esd. The calibration's b, c and d stay within 1.5 esd of
WP-1964's fit without the equations. The manual's TOPAS page and the skill's
`PEAK_WIDTH_NOT_POSITIVE` row now name both traps, and WP-2153 inherits the silicon case.
The measurement is arm (e) of `docs/wp/1964-measure/zrp2o7_formula.py`. No code changed. PR #1783.

### WP-2154 a holder offset shared across a joint fit (closed 2026-11-22)

A joint fit over several patterns can share a sample holder's cell and its height offset
while each pattern keeps its own specimen height, with nothing new in the package. Each
holder line's centre is an expression equation of shared variables `a_holder`, `offset`
and `zero` and of a per-pattern `height` (`SharingMap(per_histogram=["vars.height"])`),
and two more equations set the zero shift and the specimen displacement. On five
synthetic patterns at five heights, over 12 noise seeds, every mean z of the truth lies
between −0.32 and +0.26 (both cells, the structure, the offset and each height), and
the offset's esd is 0.42-0.49 of one pattern's. The guide `holder_cell.md` gains the
section, its script asserting every number, and `tests/test_holder_cell.py` the slow
test. PR #1782.

### A joint stage seeds and holds a Stephens block as a single fit does (WP-2239, closed 2026-11-22)

A joint fit now honours `Stage.strain_seed`: a freed all-zero Stephens block starts on the
isotropic ray and is recorded in `StageResult.seeded`, as in a single fit. A shared block over
per-histogram cells takes histogram 0's ray, which lies inside every histogram's cone. The
joint LM step now holds the strain cone and texture P ≥ 0 in every histogram, beside the width
rows WP-2002 added. On the WP's two-pattern fixture the answer is unchanged to the printed

### A peak equation's width is held inside the LM step (WP-2153, closed 2026-11-22)

The default LM driver keeps a peak's total width positive inside each step, and the total
now includes a width peak equation's term. The term enters exactly where it can: as a
constant when the equation's coefficients are held, and as an exact block when the
equation is affine in its free coefficients, as the TCHZ forms are. Without it, a free
TCHZ equation on a synthetic LaB₆ pattern stepped its Gaussian width under the floor at
19 of 19 reflections and stopped at Rwp 0.195 against TRF's 0.0416. With it, LM lands
within 0.0025 esd of TRF. A held positive term had also made the instrument's row too
strict, leaving U, V, W and X 5-115 esd from TRF's; that case now lands within 3e-5 esd.
A term that is not exact stays out of the row, and `PEAK_WIDTH_NOT_POSITIVE` still reports
it after the fit, as it does a term that starts below zero. Only a fit with a width
equation reaches the change, and the standard fit's printed output is unchanged. PR #1784.

### An equation fitted to a series trajectory (2106, closed 2026-11-09)

A GSAS-II user's way of working now has a home. After a series, `rx.fit_trajectory` fits an
equation in the grammar to one parameter's trajectory, weighted by its esds, and returns the
coefficients with esds and χ². The result says it is a fit to a trajectory and which chain
it read, which under `direction="both"` the caller names, the gap between the two being path
dependence nothing resolves. A pattern
the chain quarantined is left out, as it is from the median, and so is a point with no esd;
each is named. Each coefficient carries two esds and rietx picks neither: one scaled by χ²/ν,
as every refined esd is, and one that trusts each pattern's esd as it stands. A `.gpx`'s
stored sequential equations read in through `read_gsas2_gpx`, rewritten in the grammar with a
table of each rewrite (GSAS-II's `sin`, `cos` and `tan` read degrees), and any spelling
outside that table is refused by name on the equation.

Measured: on twenty noise seeds of the guides' seven-pattern LaB₆ ramp, the trajectory's line
and the joint fit's agree within 0.05 of their combined esds. The unscaled esds equal the
joint fit's within 1.1 %, and the scaled ones run 0.35-1.30× them, since χ²/ν has five degrees
of freedom there. The GSAS-II tutorials' sequential peak fit, a project GSAS-II wrote, reads
its stored equation in whole. What is left is on issue #1489: a GSAS-II-written `.gpx` for the
refused arm of the milestone's row, evaluating the fitted equation at a coordinate, a
pseudo-variable as the dependent, and GSAS-II's own table as a trajectory.

### A peak equation reads the wavelength (WP-2152, closed 2026-11-22)

A phase's peak equation can read `wavelength`, the λ in Å of the emission line each peak
is drawn at. A crystallite-size width is then written once, as `y*wavelength/cos(theta)`,
with one `y` shared by patterns at several wavelengths. On two single-line patterns at
0.4139 and 0.7107 Å it reproduces the built-in `lor_size`, which the joint table converts
by λ_h/λ_0, to 1e-12 relative, and it follows a refined λ. The instrument's equation
cannot read it, since its shift is also evaluated at angles no emission line owns.
`PEAK_EQUATION_SHARED_ACROSS_WAVELENGTHS` is silent on an equation that reads
`wavelength`, since the user has written the λ dependence. Settled by Claude under Yue's
"your call" of 2026-11-22. A size term in degrees written in the same expression is
silent too, the known limit. PRs #1785 and #1790. The strain report's compile-time λ
went to WP-1335's Inherited. The built-in size terms still give a Kα2 image the Kα1
width in degrees, where per-line Scherrer would widen it by λ2/λ1 (about 0.25 %, 7.9e-4
of the peak height on brucite); changing that is a default for every user, and nothing
is filed for it.

### A project opened in the same GUI window streams its events from the first (WP-2237, closed 2026-11-22)

Opening another project in a window that stays open no longer renumbers the event stream,
so the Console reads the new project's engine events from its first run. The old numbering
restarted at 0 while the page kept its cursor, which cost the polling path every event up to
the old count. A browser probe showed the open SSE stream had mostly recovered on its own,
because the server's stream loop reads its cursor back from the session. The same probe found

behind in the client found that panels reloading on node ids keep the old project's data when
the two projects have equal node counts, filed as WP-2242. PR #1787.
