# v1.8 — the next release

**Accumulating since 2026-10-08** (version → `1.8.0.dev0`), the day 1.7.0 was
cut. This is the record of release 1.8: the narrative of everything landing on
`main` before the cut, and the measured ship block after it (WP-1540). A

## How v1.8 is getting here

### The kernel tier is a wheel (1940, in flight)

The Rust kernels are their own package, `rietx-kernels`, built in this
repository under `kernels/` and published from a `kernels-v*` tag. Version
1.0.0 reached PyPI on 2026-10-10 with five wheels, each matching numba bit for
bit inside two real fits on its own platform. rietx now depends on it and no
longer on numba, so no number moves. The install is 139 MB smaller, its
first fit compiles nothing, numpy has no ceiling, and an Intel Mac installs
again. An install whose kernels do not load warns once and says why in
`capabilities()`. The indexing traversal and the structure figure lost their
numba twins and run on numpy. The figure's automatic view is 14-40× slower
until the rasteriser joins the wheel, which is its next release.

### The LM driver's step is exact inside its bounds (1937, closed 2026-10-10)

The package's Levenberg-Marquardt driver now solves each step exactly inside
the parameter bounds (bounded-variable least squares). A parameter that ends
on a bound sits on it, and the driver reports which ones did. It also stopped
calling a stage that starts at its minimum "diverged", and its budget is now
counted in residual evaluations, as the default's is. The plan was to make it
the default here. A grid of fourteen acceptance fits, each from five starts
nudged by 1e-14, showed that switch would make things worse in today's
softplus coordinates: 7 fits gave more than one answer, against 3 under the
default. In physical units it gave one answer on 13 of 14 with no stage out
of budget, where the default driver in physical units ran out on three. So the
switch moved to WP-1938 and lands with physical units. Above 128 columns, a
Pawley block's size, the step stays the old approximate one, because the exact
solve took 0.8 s to 177 s per step there.

### The kernel tier's language is Rust (1939, closed 2026-10-10)

A spike put the five model kernels into Rust and into Cython and ran them
inside real fits against numba. Speed did not separate the three: every
candidate landed at 1.01–1.08× numba end to end. Bit agreement did. Rust and
Cython with contraction switched off matched numba on every kernel call on
macOS and both Linux architectures, and Cython under the compiler's default
differed on every scatter and moved a fit 4.8e-2 esd with nothing raised,
because rustc never fuses a multiply and an add and clang does. One abi3 wheel
per platform is 142–245 KB against numba's 143 MB. The maintainer decided the
same day: numba goes, Rust replaces it, for the install rather than the speed,
and bit identity is relaxed for the exponential alone. A review of the spike
found the thread pool never engaged in either benchmark fit, since no call
reached its 512-row threshold, so the first gain available is a Python
constant. The build, the review's findings and the two platforms still owed
an agreement run are WP-1940.

### A width freed at zero starts inside it (1930, in flight)

A stage that freed a softplus width on its floor left it there or not by
rounding, so the same tree reached χ²_red 12.48 on Linux and 9.69 on macOS on
LaB₆ + cBN with every assertion green (issue #832). The package now starts such
a row at 1e-3 of its unit and records it in `StageResult.seeded`, and the
LaB₆ + cBN protocol holds its Gaussian triple. That fit reaches 10.1518 on both
platforms. Fits that free `instrument.profile.y` from its default move; the
staged notes list what. A 0.05° seed was measured and refuted: it broke nine
suites whose true width is zero.

### A width's finite-difference step is sized by its unit (1936, closed 2026-10-09)

The Jacobian's peak-width columns were taken with an absolute step of 1e-6
below 1. On 11-BM that is a tenth of a peak's own variance, and against the
jax Jacobian it put 1.4e-3 of error into the Caglioti `v` column on LaB₆ + cBN.
The step constant then chose the fit's basin. The step now takes a size per
unit from the floor-seed table, for rows that are widths. Twelve acceptance
fits reach one χ² at steps 1e-6, 1e-7 and 1e-8 in both coordinate systems,
wherever they converge. The free-Gaussian LaB₆ + cBN fit lands on its higher
basin, 9.84 against 9.66. The suite's protocol holds those widths and does
not move. Two goldens moved, each closer to jax. One Le Bail trajectory now
splits by platform at its fifth pass, 13.773 % on macOS against 14.031 % on
Linux, so its test asserts the stop rule rather than where it stops.

### A GSAS Gaussian width checked against GSAS-II's own peaks (1543, closed 2026-10-10)

1.7.0 read GSAS's Gaussian `U V W` as a variance. This release checks that
against GSAS-II's drawn pattern rather than its formula. GSAS-II's refined
LaB₆ widths, written as an `.instprm` and read back, draw 24 isolated lines
within 0.21 % of GSAS-II's own FWHM. The reading before #705 drew them 0.42 to
0.53 times as wide. The 8 ln 2 now has one definition, in `caglioti.py`. A
`.prm` offering several profile functions is read by `profile_set=`.

### 1.7.0 cut and published (1546, closed 2026-10-09)

The first weekly cut. It carried 89 pull requests over the five days after
1.6.0 and completed no milestone. Rigid bodies shipped as a provisional first
piece, the maintainer's call. The notes were rewritten from the tag range: the
staged file missed about 28 changes, mostly an outside contributor's, and six
of its claims were false on the tree. The cut re-measured every figure the
validation page, the manual and the skill quote, and about 70 had gone stale
with every check green. It found the Windows pre-upload gate red for four
nights on three tests that need a POSIX sandbox, fixed before the tag. The
measured ship block is the [v1.7 record](v1.7.md)'s appendix. The figures the
cut could not re-run are named in 1546's handover.

### The CIF writer on one registry (1319, closed 2026-10-09)

Issue #756's first three chunks. The six COMCIFS dictionaries are vendored for
tests, and a registry test checks every tag the four CIF writers emit against
them. One number rule writes a value without an esd as its shortest
round-tripping text, and refuses non-finite numbers and whitespace in a label.
Every CIF now opens with one structure block that names its setting three ways,
writes U, and states formula, Z, Mr, density and volume. A checkCIF baseline on
four public files, posted on #756, showed the consistency tests silent for want
of an operation loop. After the change, every structure-block alert is gone and
the computed and reported values agree on all five blocks. A 113-character
`_atom_type_scat_source` was found to stop PLATON without a word. The pattern
block, the multi-block layout and the validation hook went to 1933, the magCIF
parent record to 1911 and the XYZ importer to 1813.

### A planning-doc PR runs only what reads it (1506, closed 2026-10-09)

A PR that changes only planning documents now goes green in about two
minutes, down from about 20. It runs the four test files that read those
documents, found by an audit hook over one fast run rather than by grep.
Branch protection gates on two checks, `lint` and `ci-ok`, so the test matrix
can change shape without touching protection again. Every code PR's fast legs
now upload per-test timings, and each handover quotes what its added tests
cost. The cut to CI time those timings were collected for became WP-1547.
In the week to 2026-10-09 the median fast leg rose from 21.7 to 31.1 min,
mostly from three files. Dropping from four test workers to two on 10-07
changed nothing, because the runner has two physical cores.
