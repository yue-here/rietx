## How v1.11 is getting here

### A result names its radiation (2042, closed 2026-10-24)

A fitted result records the radiation it was fitted with, as `RefinementResult.radiation`: the
source's kind and each emission line's wavelength at the answer. So `result.plot()` labels its
2θ axis as `data.plot()` does, with nothing passed: `Cu Kα, λ = 1.54059 Å` for a tube preset,
and λ alone for a synchrotron, a neutron source or a refined wavelength. A joint fit records
each pattern's own on `HistogramResult.radiation`, which `for_histogram` swaps in. Without it
the per-pattern view would have labelled the second pattern with the first one's λ. A result
saved earlier reads `None`, "not recorded", and draws the figure it always drew, byte for byte.
Schema 0.59 → 0.60. It merged (#1152) after the 1.10.0 tag, so it ships in 1.11; WP-2043 moved
this section here from the v1.10 record.

### 1.10.0 cut and published (2043, closed 2026-10-24)

The fourth weekly cut came ten days after 1.9.0, three days late, because the
Windows gate had been red since 2026-10-20 and the cut found two defects
worth holding for. Chasing the macOS split in the QPA guide's esd led to
GSAS-II's Sabine extinction factor, which every release had copied. Its 3.6 %
step at x = 1 made an esd depend on whether the last finite difference
straddled the step. The maintainer had the continuous function land first
(WP-2044). The VALIDATION re-measure found the hostile round-robin series
spending a very long time in the closing stage every plan now ends with. The
maintainer chose to ship with that stated as a limit, with a measured
workaround, and to fix it in WP-2045. The cut carried WP-2002's closing stage
and removed limits, the purposes WP-2037 prints diagnostics by, and the new
manual, and it completed no milestone. On release day the Windows gate went
red once more, on a test-side path separator in the eval harness, and was
fixed before the tag (#1151). On the release commit the Windows suite passed
every test while its job ran six seconds past its 45-minute limit, and the
maintainer took the suite's result as the gate. The `full` nightly finished on
Linux for the first time since the closing stage landed, with three slow rows
red (WP-2036). 1.10 is the first release to carry its own manual, now
`stable` at `/docs/`. The measured ship block is the
[v1.10 record](v1.10.md)'s appendix.

### A result reproduces its own number (1421, closed 2026-10-25)

A result now describes one state wherever it is read. Since #432 a single fit's curves and
statistics came from a compile at its answer; a joint fit's now do too, so its per-pattern report
no longer reads peak tails cut at stage-start windows as unmatched peaks, and
`FROZEN_COMPILE_STALE` tests each pattern and names the worst. `report()`, the reflection table,
`predict()` and the CIF writer read the answer saved with the result, so a cancelled later fit
cannot mix into it. The finding's claim that the fit is unbiased was withdrawn on two measured
counterexamples. The session re-measured the gap WP-1986 handed over, a plan stopping 9 % above
its re-solved χ², and found it closed for plans by WP-2002's closing stage; a hand-run stage keeps
it, which is WP-2047's subject. Issue #774's zero case was ruled documented, after a practice
survey and a probe showing the alternative doubles a default fit's time for a 4.8e-5 effect;
it is re-checked when WP-2047 lands.

### A stage that ends on stale windows says so (2047, closed 2026-10-25)

A stage computes each peak over a window sized where the stage starts, so a peak that moves or
broadens while it solves spills past it, and the solver can fit the lost intensity instead of the
data. That is how the CPD chain once ran its axial divergence from 0.04 to 558. Every stage now
records the share of the Bragg intensity its windows dropped at its answer, measured without a
compile at 3-5 % of a fit's time, and `STAGE_WINDOWS_STALE` warns when the stage whose answer
reaches the result drops more than its own window tolerance. The four acceptance standards stay
at or under 1.7 % against 2 %; the old runaway reads 73 %. A hand-run stage now reports its own
gap, which WP-1421 handed here, though nothing repairs it. Recompiling between solves was measured
and dropped: a check at a solve's end rebuilt windows at the runaway, and a check every few
iterations worked only at an interval fitted to one case. Windows resized at every evaluation, as
GSAS-II, MAUD, RIETAN-FP and EasyDiffraction do, removed the runaway at 1.24-2.08× the fit time
with no accuracy gain on the four standards. At the maintainer's request WP-2051 tests that design
with a faster resizing and a tapered window edge, and issue #774's zero case moved there with it.

### Windows resized at every evaluation, tested and filed (2051, closed 2026-10-25)

WP-2047's prototype resized each peak's window before every evaluation and cost 1.24-2.08× the
fit time. Most of that cost was one bisection for the window's half-width in FWHM units, solved
afresh per phase and emission line at a fixed ~0.36 ms. A table built once per tolerance replaced
it inside the resizing, which now takes 0.08-0.16 ms, so the ratio fell to 1.05-1.49. What
remained was extra solver evaluations, because the cost steps when a window edge crosses a data
point. A taper that fades each peak to zero over a tenth of its window, emulated in a probe,
recovered most of them, and built into the forward model it is inferred at 0.94-1.10× shipped.
Answers polished at tight windows came out the same as shipped's on the four standards, and the
old runaway stayed removed. The maintainer ruled to file it for now and keep it as a future
possibility, since it buys no accuracy and would rewrite the frozen-per-stage invariant on every
backend. The faster sizing ships, used by the stale-window measurement. The WP file says what
would reopen it and where to start.

### Magnetic superspace groups from the operators (1992, closed 2026-11-01)

`crystallography/superspace/` generates the (3+1)D magnetic superspace group (MSSG) of each irrep
at a real propagation vector. A modulated structure has atoms displaced by a wave that does not
repeat with the cell, and the group needs one extra dimension for the wave's phase. A magnetic
group adds time reversal, written θ on the operator and {1′|000½} for the pure translation
in the extra dimension. The package stays unexported, so no user sees it until the magnetic forward
model lands on it. The group of an irrep comes from a declared line (`little_group_on_line`),
because spgrep's little group is exact at a rational k but snaps a near-rational k below
|Rᵀk − k| ≈ 1e-8 and declines `real=True` on 6 of 9 test lines. spgrep stays a dev-only oracle.
The pins are Stokes & Campbell (2022) Tables 1-3 and Fig. 4, Perez-Mato (2012) Table 1, and the six
MSSGs of SrFeO₃ (Gallego 2016). Types 1-3 match the published counts (775, 775, 3100). Type 4
gives 4651 against the printed 4653, a strict xfail that stays open. It merged from outside as
#1060 (`44de0f62`), and #1227 (`c6c75653`) added a control showing `LINE_ATOL` does not move with
λ near a rational. Yue ruled to close the WP with that xfail standing.

### A peak list refuses a q_esd its two_theta_esd does not give (2071, closed 2026-11-01)

A peak list stores each line's uncertainty twice, as σ(2θ) and as σ(Q), and the indexer weights
lines by σ(Q). The list already refused a Q that its 2θ did not give, but nothing tied the two
uncertainties. So an edit to one line's σ(2θ) loaded clean and never reached the search, and
#1236's weighting experiment ran an arm that changed nothing. The list now checks σ(Q) against
σ(2θ) in the same pass, at a relative 1e-9 with no absolute floor, and a pair where both are
non-finite agrees. The refusal names the peak and both numbers, and says to set both fields
together. Every package constructor derives σ(Q) through the same function, and has since the
peak editor landed, so no saved list from a shipped release is affected. Reported from outside
by @mustachefeeling, fixed in #1281.

### The data-support count reads what drives an atom (2067, closed 2026-11-01)

McCusker's observations-per-parameter ratio divides the reflection count by the number of free
structural parameters. The package counted those by name, as free paths under `atoms.`, so a
mode amplitude, a rigid body's pose and a named variable tied to an atom went uncounted. On the
synthetic rigid-body state the ratio read 12.67 where the true one is 3.45, clearing "preferably
five" when it sat near three. The count now reads what each free column reaches, and a body's
cell input, which only places its atoms, stays out. Reported from outside by @mustachefeeling as
#1250 and fixed in #1276. The close (#1289) found the same name test in the purpose table: a
warning naming a mode amplitude printed as an info line under structure, qpa and magnetic, and
one naming a rigid body under qpa and magnetic. Both families now bear wherever a coordinate
does, and a block declaring a frame input it does not read is refused.
