**Opened 2026-09-12** (version → `1.4.0.dev0`), thirteen days after v1.3
shipped. The slot was first opened for v1.1 and shifted three times
(2026-08-20, -25, -28) with its numbers kept; [`../ROADMAP.md`](../ROADMAP.md)

## Scope

Peaks without a structure — fitted standalone at positions a caller names
(1101), and the `Instrument.extra_components` union seam with broad humps
(1102) and sharp peaks (1103) as its first two members. Each WP file states
its own context and baseline; nothing is restated here.

## Acceptance

**These rows are written at the open**, which is the whole point of protocol
rule 6: the [v1.3 record](v1.3.md) says plainly that rows written at ship are
the weaker evidence, because a row written after the fact cannot fail. Each
names a state a later session can check without asking what was intended.

The 1101 rows are stated in full because that WP is open. The 1102 and 1103
rows are stated at the level `../ROADMAP.md` already commits to, and the
session that opens each WP sharpens its own row here — a bar set by someone
who has not read the WP is a bar set too low.

- **A caller can fit exactly the peaks they name** (1101). `fit_peaks(data,
  instrument, positions)` is a documented top-level call returning a
  `PeakList` whose components in each window are the caller's positions and no
  others, and `capabilities()["features"]["peak_fitting"]` is derived-True —
  derived from the export's existence, not written `True` (WP-1037's rule).
- **A named position that fits nothing is answered, not dropped** (1101). The
  chapter states what `fit_peaks` returns for a position where there is no
  peak, a test pins it, and the answer is neither a silent drop (the version
  this WP tried first, which made the GUI's add verb do nothing) nor an
  unflagged component wearing an ordinary esd.
- **A named position beside an unnamed real one says so** (1101). Fitting the
  caller's model alone where detection saw more biases the named position, and
  the only numeric trace is χ²_red; the affected peaks carry a flag of their
  own. Evidence, not refusal.
- **One window-sizing arithmetic, three callers** (1101). Detection, the GUI
  peak editor and `fit_peaks` size a fresh window through one helper in
  `indexing/`; `gui/` imports it back, and `tests/test_gui_peaks.py` is
  unchanged-green across the lift.
- **Williamson-Hall is a computation the manual executes, not a helper the
  package ships** (1101). The numbers in the chapter come from an executed
  block over a real `PeakList`.
- **The component seam is one serializable union** (1102). An instrument
  carrying extra components round-trips through JSON and back, and a hump is
  the first member rather than a special case beside the seam. *Row to be
  sharpened at 1102's open.*
- **A sharp extra peak is the same seam's second member** (1103), costing no
  new field on the union. *Row to be sharpened at 1103's open.*
