cut. This is the record of release 1.12: the narrative of everything landing

## How v1.12 is getting here

### 1.11.0 cut and published (closed 2026-11-04)

The fifth weekly cut came eleven days after 1.10.0 and carried 183 merged pull requests.
The staged notes were far from complete. Of the pull requests that changed source and did not
touch the notes, 38 had no mention, and the cut wrote a note for each one a user can see.

Merging #1310 exposed a misreading. The cut had called tutorial 05's Rwp of 0.966 a deliberately

The maintainer ruled that a noise check goes into 1.11 (WP-2086, #1406). The first report, a
series failing at 2 %, was one noise draw. Over 100 draws the reach is a rate, so the notes give

The cut stayed on kernel wheel 1.3 by the maintainer's merge. `rietx-kernels` 1.4.0 is still
unpublished. Its only caller, `rietx.solve`, is unexported and has a numpy fallback, so no 1.11
user reaches the difference. WP-2043's ground, that nothing calls the 1.4 kernels, no longer holds
as written, and WP-1997 still owes the floor raise. Measured on a real 1.10.0 install, 1.10.0
refuses every structure, history log, refinement result and series result this release writes,
so a `.rex` project saved here does not open there. Tutorial 01's first pass fires
`STAGE_WINDOWS_STALE` with no prose to explain it, and the maintainer left that for later.

The maintainer's merge of #1400 approved the version, the notes and the tag. The nightly on that commit
passed every job, the tag went on it, and the maintainer approved `pypi`. The counts are in the
[v1.11 record's ship appendix](v1.11.md#appendix--acceptance-at-ship-2026-11-04).

### A metric direction no line constrains stays refused (1915, closed 2026-11-03)

WP-1915 was filed when a triclinic indexing fit to eleven h0l and 0k0 lines came back with NaN
in all six cell esds. It asked for the fit to survive with a, b and c esds equal to the
monoclinic fit's and the two dead angles marked. Since #1232 that fit is refused instead, and
measuring it showed the refusal is right. The lines' Q stay bit-identical along the dead D term
while a, b, c and α all move (b by 2.7 % at D = 0.01), because the inverse metric puts every
cross term into every length. The esds the WP asked for are first-order numbers at the
minimum-norm solution, finite on lengths the data do not bound. The refinement side's own rule
for nonlinear maps (WP-1804's declared reach) marks all six as unmeasured, which is the refusal
by another name. A test now pins the refusal with that reason and a monoclinic positive arm, and
the indexing rulebook says why. No code path changed. PR #1393.

### The structural plan frees extinction only where declared (1944, closed 2026-11-05)

`mccusker_structural` freed the Sabine extinction coefficient on every phase, while its
description said "where declared" (issue #877). Over 69 structural-plan fits in the test suite,
1 freed value in 98 passed 3σ, and that one was a false positive on synthetic data. On the QPA
guide's weak CaF₂ phase, the freed coefficient traded against the scale at ρ = +0.998 and moved
the weight fraction from 1.34 ± 0.11 to 3.58 ± 3.53 wt %. The maintainer chose an opt-in on
2026-11-03. `Phase.extinction` now defaults to `None`, a number declares it, and an old file's
stored value opens as a declaration. No surveyed program refines powder extinction unasked
(`docs/practice.md` § Extinction).

A second ruling asked for opt-in physics to stay findable. The first answer, in #1391, was a
residual score test that warned when a phase's strong lines asked for extinction. It fired on
one synthetic family and borrowed the air-scatter screen's threshold. The maintainer reversed it
on 2026-11-04, before it could ship: findable means documented. #1412 removed the warning. The
extinction help entry, the theory page and one skill row now say when and how to declare it.
WP-2087 is to add the same documentation pointers for Stephens strain, anisotropic ADPs, roughness
and absorption. The numbers that moved are staged in the 1.12.0 notes.

### WP-2102: a joint fit takes a PlanSpec (closed 2026-11-05)

A joint fit raised `AttributeError` when handed a `PlanSpec`, the serializable plan that a
project file, a history header and an agent each hold. It now reads every form of plan that a
single fit reads, and a spec and the plan it was built from give bit-identical joint answers.
The cause was a preset name looked up by hand at the call site. `resolve_plan` is the one
authority for that lookup, so the fix routes each site through it.

The same lookup sat in five more places, and each skipped the mode substitution, under which
`"mccusker_default"` in a Le Bail fit is `profile_only`. Both reports and the public
`build_report` now read a plan as the fit that made the result read it. Read by shape,
`build_report` took a preset name as a plan with no stages and vetoed nothing. A project created with a preset name, and the text
document's plan line, now store the preset expanded through the project's mode, as the GUI's
preset route already did. Before, a Le Bail project created with the default name stored and
ran a scale stage the mode force-fixes.

One reading changes. A Le Bail report given `plan="mccusker_default"` now equals the report
under `profile_only`. A scale suggestion that the hand-read preset had vetoed is active again.
That veto was an accident: the report suggests a scale and a Biso on a Le Bail fit, where both
are force-fixed, whatever plan it is given. The finding went to WP-1998.

### The report names axial asymmetry at zero apertures (2054, closed 2026-11-05)

A lab fit that left both axial apertures at 0 had no asymmetry column in Layer 1, so a one-sided
low-angle residual read as a position error and a stiff background (issue #1106, NIST SRM 660c).
The report now compiles a copy of the model with both apertures at
`NOMINAL_AXIAL_APERTURE` = 0.02 and borrows that copy's ∂Ω/∂(S/L) as a fifth column. The column
is projected off the other four in each region, so the four keep the coefficients they had. On
SRM 660c the three regions below 40° read asymmetry first, at 7-9 esd, and
`refine_axial_asymmetry` fires at confidence 0.50. Its rationale says the apertures are 0 and to
take S/L from a standard's calibration or free it in the plan. Freeing both apertures inside the
plan takes Rwp from 0.129 to 0.087. A fit that declares an aperture gets the report it had.

The code shipped in 1.11.0 (#1363). The reporter's request for a noise-only t on each coefficient
is a public report field the fix did not need. It moved to WP-2004, and #1106 stays open for it.

### A stage that crawls stops and says so (1334, closed 2026-11-05)

Issue #222 measured 3.9 % of stages spending 46.6 % of stage time on a median cost gain of 1.23 %.
Those stages ran to their evaluation budget on a cost that was falling too slowly to matter. The
default LM driver now stops a stage once, at the rate of its last 100 evaluations, another 300
would lower χ² by less than χ²_red, the decrease one esd of joint travel buys. By the maintainer's
ruling of 2026-11-03 such a stage reads `converged`, with `termination="slow_descent"`, and the
info code `STAGE_SLOW_DESCENT` names it. Every `StageResult` also carries `rwp` and `termination`,
so a caller can keep the best stage without parsing the event log.

On the suite fixture with #222's shape, the GSAS-II LaB6 recipe, a fit spends 539 evaluations
against 816, and no parameter moves by more than 0.064 esd. Stages that fall fast enough still run
to their budget. `solve_magnetic` on Cr₂WO₆ at 150 K took 3 to more than 10 continuations across
six 1e-14 nudges of one start value on macOS arm64, and now takes at most 1, so a class no longer
drops out of the ranking by rounding there. A bounded first rung the rule stops below the bound counts as complete,
and its chain answers bit for bit as the unbounded one.

The code shipped in 1.11.0 (#1343, #1366). The last test landed in #1430.

### A Le Bail stage repeats its partition until the intensities settle (1542, closed 2026-11-05)

A Le Bail stage used to stop after a fixed three cycles. It now repeats its partition until one
cycle moves less than 1e-7 of the Bragg counts, under a cap of 25 000 cycles (ruling B11 of
2026-10-19). On #740's pattern the fit ends at Rwp 1.07 % against 1.09 % for the true structure,
where three cycles left 1.61 %. Its cell comes within 4.6 ppm of truth, where three cycles left
34.9 ppm. Six other patterns pay up to 2.1× in wall clock. BT-1 LaMnO3 pays 150×, from 0.45 s to
about a minute. A Le Bail cycle is a Richardson-Lucy step, so plain repetition takes thousands of
cycles where peaks overlap, and SQUAREM S3 (Varadhan & Roland 2008) accelerates it.
`lebail_cycles=3, lebail_tol=0.0` is bit-identical to the old loop, and an old history node
replays its fixed three cycles. A partition cut by its cap warns `LEBAIL_CYCLES_AT_CAP`.

The stop reads how fast the intensities move. It does not read how far they have left to go. On FAP a pair
1e-4 Å apart stops at 1e-7 and then swaps over 3000 further cycles, 1.23 σ at that peak and 0.001
esd in the answer. So the tolerance sits at tier 3 with FAP as its stated failing case. The
extinction screen and the Pawley seed keep three fixed cycles. Claude settled three calls under the
maintainer's delegation of 2026-11-05: the tolerance, each line a reader receives, and a final
compile without a re-partition. WP-2062 takes the re-partition question.

The WP's earlier half asked for a finding when a Le Bail background stays at its seed. No statistic
separates a hump from a benign pedestal, so the maintainer ruled on 2026-11-03 for no finding and left
`auto_background`'s `seed` default at `False`. The skill names `rietx.background.snip` and the
failure instead (#1357, #1394, #1434).

### A runaway fit ends without an expensive closing stage (2045, closed 2026-11-06)

A warm fit in a series could walk a parameter far out of range, such as an axial ratio to
557.8, and end its one stage "converged". The closing stage then recompiled at that answer
with every peak window the width of the whole pattern. One evaluation cost about 1 500
times the declared stage's, and the nightly `full` job hit its time limit from 2026-10-23.
The last declared stage now converges at the solver's tolerance whenever a closing stage
follows it (option 5, ruled 2026-10-24). The hostile series in the sequential acceptance
suite finishes in 92 s on an arm64 Mac, and the 2026-11-04 nightly `full` job completed
green in 1:35:41.

The loose tolerance on the other intermediate stages stays the default, on cost grounds the
maintainer ruled on 2026-11-01 and upheld on 2026-11-02. Re-measured behind the closing
stage, it saves 1.06-1.58× in evaluations on FAP, 11-BM NAC and cpd-1a, and moves no answer
by more than 0.0004 plain esd. The code shipped in 1.11.0 (#1161). The audit rows' evidence
was brought up to date in #1317, #1348, #1352 and #1440.

### A site and its own image are one atom on every route (1991, closed 2026-11-06)

A site whose symmetry images coincide is now merged onto its special position on every
route, where before only a CIF read merged it. A stored, hand-edited or code-built
coordinate a hair off a mirror no longer doubles the composition with nothing said.
`SITE_TWINS_MERGED`, `SITE_TWINS_KEPT` and `SITE_DOFS_RENUMBERED` name each merge and each
renumbered direction (#1014, #1223).

The same work found that a path naming an atom by its number did not follow the atom when
two models numbered their atoms differently (#1264). An edit, a series carry and a re-anchor
now follow each atom, and each phase, by name, so a hold, tie or carried value stays on the
atom it was declared on (#1274). A hold on an anisotropic displacement component now follows
its tensor component when a site merges. A series whose `prepare` hook adds or removes a
phase or an atom reports each trajectory for one atom, keyed by its phase's name and its own
label, as the maintainer ruled on 2026-11-01. Duplicate names are refused (#1360). That PR
changed a stored format, and the maintainer approved it by merging it on 2026-11-03. A
`SeriesResult` from 1.10 opens as written, since it never stored the names a conversion
would need. All four PRs shipped in 1.11.0.

### A parametric equation the user writes (1964, closed 2026-11-06)

A joint fit now takes a parametric equation written as text, nonlinear in its coefficients.
`basis="expression"` carries the formula, and `variables=` declares each coefficient as a
`Parameter`. A variable is one shared column however many equations name it, so nine cell
edges can share one Einstein θ. An equation with no target is an intermediate that later
formulas name, such as a calibrated temperature. A variable matched by a
`SharingMap.per_histogram` glob is a column per pattern instead, which is Stinton and Evans's
temperature offset per pattern. The grammar has its own reference page and a Theory section,
and `debye(x)` is a function with its own derivative.

The readers that assumed a linear basis now read a formula too. Each variable returns with
its esd from the joint covariance. `RefinedParametricEquation.evaluate` gives an equation's value and esd
at any coordinate, through its exact gradient. The form test recovers each formula target's own column
through that gradient. Peak-chain columns that a shared variable ties together are taken by
one finite-difference pass per independent direction. `Parameter.expr`, a field that only
ever held `None`, left the schema. A stored null is dropped at read, and a formula there is
refused, naming the equation that replaces it.

Measured: over 12 seeded synthetic ramps a per-pattern temperature offset and the
coefficients it feeds have mean z-scores within 0.13 of zero. The ZrP₂O₇ tutorial's formulas
reproduce the cells TOPAS stores to its printed digits. On WO₃ the formula text matches the
built-in Einstein basis to 3e-8 of an esd, and 11 patterns under WP-1325's protocol bound θ
from above only. The input's own WO₃ protocol waits on the tie WP-2103 gives a joint fit.

### A line held at its position bound keeps the picker's declared shape (2055, closed 2026-11-06)

On the 16 IUCr round-robin patterns, 24 usable picked lines end on their position bound, so
their reported 2θ is the bound's (issue #1166). The reporter suspected the Kα2 weight the
picker holds. Re-run on this tree, every census and direction count reproduces theirs. Below
90°, 17 of 19 freed lines move to lower 2θ. Freed, 8 move towards the known lattice and 11
away from it, so the bound hides no systematically better positions. Declaring each pattern's Rietveld-fitted
Kα2 weight takes the count only from 24 to 19, and that weight runs from 0 to 0.46 on one tube.
No peak picker surveyed refines the ratio by default (GSAS-II and WinPLOTR leave it to a user's
flag; `docs/practice.md`). So the picker keeps the shape it is handed, settled by Claude on that
practice and measurement.

A third of the 24 turned out to be shoulders on the low-angle tail of a 4–23× stronger line,
and seven of those eight are not lattice lines at all. The flag's help text, which said
detection had misplaced the seed, now says what such a component often is. Whether those
shoulders should leave `usable()` is WP-2120, with the window-edge re-seeds that are the
other leftover class.

### The solve cost at a stated March-Dollase r (2109, closed 2026-11-07)

The cost a direct-space search minimises can now say what χ² would be if the solved phase
were textured at a March-Dollase r and axis the caller states, and how fast χ² changes with
r. It does this without rebuilding the quadratic form. Each reflection's column is rescaled
by the ratio of the new texture factor to the one folded in at extraction. So the free-intensity
floor stays the same at every r, and the cost ratio a search reads stays comparable. The
proposal came from an outside contributor on #562, whose own search reached a textured
structure's basin only once r was a search coordinate.

Against Rietveld-mode `evaluate` on NAC and FAP, the rescaled pattern agrees to 1.1e-15 of
the largest count. Two wrong factors (one not divided by the extraction's own factor, one
read off a single equivalent) fail that row by 0.066 and 0.33. Nothing in the package calls
the new methods, since `rietx.solve` is not public. Whether a search moves r is S9's (#677).
Built from outside as #1420 and closed by the maintainer on 2026-11-07.

### A formula's volume window fits inorganic cells (2030, closed 2026-11-07)

`SearchSpec.from_formula` turned a chemical formula into a volume window for the indexing
search, from Hofmann's (2002) atomic volumes. That window excluded the true cell of 7 of 8
inorganic solids measured, because Hofmann's volumes overestimate an inorganic cell. On
fluorapatite the windowed search abstained where the unwindowed one ranked the truth first.
The window is now a ceiling only, at Hofmann's factor 1.25. `INDEX_Z_NOT_INTEGER` is
withdrawn: it fired on true inorganic cells, whose volume runs 0.38 to 0.87 of the estimate.
A formula whose full stop reads two ways (`CuSO4.5H2O`) is refused, where 1.10.0 read it as
4.5 O and put the volume 39 % low. `IndexingResult` records the formula and temperature it
read, and `rietx index` takes both. Those parts shipped in 1.11.0 (#1123, #1253, #1237, and
#1344 for the GUI peak editor's stale marks).

In 1.12 the GUI's indexing form takes the formula and temperature too, and the project
stores them in `IndexingControls` (#1351). That changed the stored format, which the
maintainer approved on 2026-11-06. All five PRs came from an outside contributor. The
maintainer closed the WP on 2026-11-07, and issue #1121 closed the same day.

### An assigned parameter keeps its field's range (2088, closed 2026-11-07)

A field such as `Phase.lor_size` declares a range and a unit, and a `Parameter` handed to the
constructor without them has inherited both since issue #204. An assignment did not:
`phase.lor_size = Parameter(value=0.01, vary=True)` left the width unbounded below and
unitless, and 70 of the 72 fields that declare a range behaved the same way. A free width or
occupancy could then walk out of its physical range with nothing said. The assignment now
inherits through the same rule as the constructor. The code review found an older defect on
that path. Any assignment replaced the model's other declared parameters with copies, so a
change made through an object a script held reached nothing. That is fixed too. No fit
prints or returns anything new (#1458).

### One formula language for every constraint (2118, closed 2026-11-07)

A single refinement can set a parameter by a formula, `tie(path, expression="...")`, in the
grammar a joint fit's equations use. The maintainer ruled on 2026-11-07 that a formula reads
only variables declared with `add_variable` and numbers, so a model parameter enters by tying
it to a variable first. The spelling is a keyword on `tie`, so `untie`, the history and a
checkout serve both kinds of tie. A linear tie stays on the constant matrix and a formula
always runs as a formula, so no stored tie and no golden moved. The practice review behind
the rulings is in `docs/practice.md` § The same language across a program.

A formula tie is stored as `TieSpec.expression` (schema 0.61, additive). A series declares
one in its `constrain` hook, with each pattern's temperature written into the text. The
manual warns that GSAS-II's expression `sin`, `cos` and `tan` take degrees, and the TOPAS
writer refuses a formula tie rather than writing it as the constant 0. A stored tie carrying
both a formula and a linear part is refused. A joint fit has no `tie` verb yet, so its
`expression=` is WP-2103's.

Measured: a Debye-model Biso on synthetic LaB6 recovers θ_D within 2 esd on three noise
seeds (1.69, 0.14 and 0.75 esd from the truth). A linear formula and the matrix tie agree to
4e-16 relative, and the new cross-backend row agrees on fd, jax and torch.

### A moment's size carries its likelihood interval where its esd cannot be read (2060, closed 2026-11-07)

Issue #1075, from an outside contributor, measured how often rietx's uncertainties cover a known
truth on simulated data. Two magnetic cases failed. A moment refined to zero reported an esd of
10 000-200 000 μ_B with no warning, and asking for its likelihood interval returned a zero-width
answer. And a weak moment whose angles the stationary-angle test left out of the covariance had an
esd that covered the truth 82 % of the time at a nominal 95 %.

The first case shipped in #1322. `MOMENT_UNSUPPORTED` warns where the data do not support a moment,
and `profile_interval` steps back in where its first probe overshoots, so the interval at m = 0 runs
from 0 to about 0.06 μ_B. A profile also keeps the fit's own held parameters held. Phase scale and
occupancy get no default interval: on the reporter's measurement every rule already covers there.

For the second case Mike ruled on #1075 (2026-11-04, amended 2026-11-05) that the fit computes the
moment size's profile interval unasked on every site the stationary test flags (#1459). The
interval covered 0.93-0.98 in his runs, and costs 2.5-11.8 s a moment. The esd stays on the row
beside it. Where the profile finds a fit better than the answer by a whole Δχ² cut, the interval is
withheld, and `MOMENT_ANGLE_STATIONARY` gives that point and asks for a refit. The maintainer ruled
the stored-format parts on 2026-11-07: magCIF keeps value(su) unchanged, the existing
`RefinedParameter.interval` field carries the interval, and no schema version moves.

### The design record says how a design is chosen (2119, closed 2026-11-07)

`docs/DESIGN.md` gained Rule 5, from heuristics the maintainer stated on 2026-11-05 while
answering two WP-1964 decisions. A change takes the shape rietx already uses for the same
job, and a departure names the likely mistake or wrong number the convention would cause.
A design builds towards the stated direction and is not fitted to one case. Existing
practice from any field is adopted where it meets accuracy and the reused design's
constraints. When these disagree, the API's shape follows rietx convention, a name follows
the literature and the IUCr dictionaries, and a number follows accuracy. Checked against
WP-1964 (a) and (c), WP-1303 and the 2026-11-04 ruling on TOPAS aliases, the WP's draft
needed two sharpenings for all four to come out as decided. The maintainer approved the
revised text as drafted.

### The GUI's indexing step reaches a cell on real lab data (2124, closed 2026-11-09)

The GUI overhaul's indexing rounds found the old GUI's indexing a dead end on fluorapatite,
the shipped real lab pattern. The extinction screen was refused on a project with no phase,
though a pattern-only project is where indexing starts and the screen fits its own Le Bail
models. Adopt took only the one candidate `best_or_none()` picks, and on that pattern nothing
reaches `high`, so the right cell could not be adopted. The maintainer ruled on 2026-11-08 that

machine, is the judge. That reverses WP-1027's gated Adopt. A candidate the gate did not pick
now writes its grade and caveats into the history node's label. The pick route also takes the
2θ range and the contamination marks beside shoulders, and edits keep the options the list was
picked with; before, every edit re-marked the Kβ and tungsten lines a pick had declined.
Measured on the way: 8 of fluorapatite's 12 candidates carry a supercell check under the
default search, not the 2 the design rounds recorded. Naming the remaining relations ("same
cell", "c doubled") needs a new field, so it waits for the piece that redraws the table.

### The pattern at values nobody has applied (2125, closed 2026-11-09)

`POST /api/preview` returns the calculated pattern, the background, each phase and the ticks at
parameter values sent in the body, and writes nothing. It serves the gui-overhaul milestone's
sliders, whose client half is the next piece. It evaluates on the cached compile while every
window and node count still covers the new values, resizes the windows when one grows, and
compiles afresh when a reflection moves by the list's 0.5° margin. A resized answer equals a
fresh compile to 1e-13 σ. Through the real server on loopback, with the compiled tier, the
fluorapatite example answers in 10.3-15.7 ms and the NAC example in 2.1-2.5 ms, inside one
animation frame. That settled it against shipping the design prototype's JavaScript peak model,
which sat 0.08 esd rms from rietx and would have been a second copy of every correction. An
axial term moved off zero on NAC takes about 140 ms, the FCJ images' own cost.

### The model moved by hand (2128, closed 2026-11-09)

`rietx gui` has an Interactive tab beside Parameters. It gives a slider to each value a person
adjusts by hand before a fit: the scales, cell lengths, zero shift, displacement, axial
apertures and peak-width terms. A drag redraws the Pattern graph through `POST /api/preview`
and commits nothing until the action bar's Apply. The title line then says `Preview, not

also sends the three residuals the curves route sends. In chromium, a real pointer drag on the
synthetic layout pattern redrew in 32-38 ms from the value change to the painted frame. Twelve
presentation calls without a ruling are listed in the WP for the maintainer's review.

### A restraint follows its atoms through an edit (2121, closed 2026-11-09)

A soft restraint named its atoms by their place in the atom list, and nothing renumbered it
when an edit reordered that list. On fluorapatite, swapping two atoms moved a bond restraint
onto a pair reported 3.92 Å apart and pulled it toward 1.54 Å with nothing said. Removing a restrained
atom passed the edit and crashed the next fit. Now an edit and a series `prepare` hook carry
every restraint onto the same atoms, for all seven kinds. A restraint on a removed atom is
dropped and named in a warning. An edit that both renumbers atoms and changes a restraint is
refused, because its numbers could mean either list. Distortion-mode rows follow a pure reorder
(#1463, merged 2026-11-08). The maintainer then ruled on 2026-11-09 that atoms are named by
unique label everywhere ("labels for everything, and make sure they're unique"). That remedy,
with the record of a renumbering and the construction-time checks, is WP-2140.

### A width on its floor reads as no broadening under either solver (1914, closed 2026-11-09)

Filed from notebook 04 when the solver still refined widths through a softplus map: a
Gaussian width the data put at zero came back as a tiny positive number and read as a
domain size of 10⁸ Å. Since WP-1938 the default LM solver lands such a width exactly on its
floor, so the default path was already right. Under `solver="trf"`, which keeps its iterates
strictly inside the bounds, the same CeO₂ fit stopped at 3.4×10⁻²⁴ deg² and the table read
a 4.3×10¹³ Å domain, with a size ratio of 1.4×10¹¹. The table now reads a width carrying
`FLOOR_HIT` as `at_zero`, so the warning, the parameter row's `at_bound` and the reading are
three projections of one bound test. Default fits read the same to every printed digit.

### The GUI's layout shell (2123, closed 2026-11-09)

The first piece of the gui-overhaul milestone gave `rietx gui` the redesign's shape. The graphs
sit on the left under their own tab strip, with a title line saying what the graph shows. The
nine panels sit on the right, with one action bar under them that applies edits and refines:
one cycle on the ticked parameters, or the staged plan, on ⌘⏎. Each side collapses from a button

### A parametric equation keeps its target inside its bounds (1325, closed 2026-11-12)

A joint fit refines a parameter as a declared function of each pattern's coordinates, such
as a cell edge along a temperature ramp, and returns the function's coefficients with esds
from the joint covariance. The scalable solver, the form test and the coefficients' covariance
landed before this release. Two pieces closed the WP. The default solver now holds each target
of an equation inside the target's own bounds within the step. Before, a line through Biso(T)
that wanted a negative Biso at one end converged and then raised when the answer was written
back, so no result came out. Now the target sits on its floor in that pattern and
`FLOOR_HIT` names it. Where the default solver cannot hold the row, under `solver="trf"` or
for a formula equation, the joint fit finishes, the model holds the crossed bound, and
`PARAMETRIC_OUT_OF_RANGE` quotes the equation's own value (−0.14 Å² on a five-pattern ramp).
Per-pattern starting structures must now agree in every field that shapes a shared parameter's
column, so two texture axes can no longer hide under one shared March-Dollase r. Merged on
2026-11-10 (#1497). The next-term test and the replicate reading (#1218, row S2) stay
parked in the WP, as the parametric milestone's scope says.

### A Pawley joint fit shares a parametric cell (2104, closed 2026-11-13)

A cell series can now share a parametric equation before anyone has a structure. A joint

### Unapplied edits survive a close or a crash (2209, closed 2026-11-13)
