# rietx 1.10.0

This release carries everything that reached `main` in the ten days after 1.9.0, 128 merged pull requests.
Five changes are the largest.
Every plan now ends in a closing stage, which solves once more on peak windows that keep 99.9 % of each peak, so the answer of every default fit moves.
Sabine's extinction factor is now continuous, where 1.9.0's stepped by 3.6 %.
A fit that stopped on that step could report an esd that depended on the platform: in the QPA guide it was ten times smaller on macOS than on Linux.
`solve_magnetic` now charges each ΔBIC for the observations a powder pattern holds, so its evidence for a magnetic group is about ten times smaller.
A fit's diagnostics print by what they mean for the result you want from it, and every diagnostic's message is rewritten.
And the manual is rebuilt at rietx.org/docs/ in six tabs, and every tutorial notebook runs in a browser at rietx.org/lite/ with nothing installed.

On the 11-BM NAC example, README's figures move with the closing stage: Rwp goes from 0.0933 to 0.0930, and the history holds 15 nodes where it held 13.
Nearly every fit row of `docs/VALIDATION.md` moved, most by under 1 %, and [Numbers that move](#numbers-that-move) lists the larger moves.
A fit whose declared stages run away can spend a very long time in its closing stage, and `closing_window_tol=None` avoids it (see [Code to check](#code-to-check)).
Everything that changes what 1.9.0 code gets back is in [Upgrading](#upgrading).

## Install

```sh
pip install --upgrade rietx
```

## Upgrading

Code written against 1.9.0 runs unaltered, with the exceptions in this list.

### Code to check

- Code that reads the text `print(result)` or `summary()` prints for its diagnostics (WP-2037).
  The "N unresolved" header is gone, and with no deliverable only an error prints in full: every other row is one line naming the code, its parameters and the purposes it is a warning under.
  `summary(deliverable=…)` prints that purpose's warnings in full, and `result.diagnostics` holds every row as before, which is what code should read.

- `SearchSpec.n_unindexed` and `SearchSpecSpec.n_unindexed` default to `None`, where they were 2, and also take `"inliers"`.
  `None` keeps the count of two and adds the retry below; an int still declares that absolute count with no retry, so code that set one is unchanged and code that read the default as an int now reads `None`.

- `ParametricTie` is now `ParametricEquation`, with no alias.
  Code from 1.9.0 that builds `parametric=[rx.ParametricTie(...)]` must change the name.
  The standard term is a parametric equation, as in GSAS-II and in Stinton and Evans (2007).
  A 1.9.0 result's `ParametricCoefficient` rows carry the key `tie`, and they open here with that key read as `equation`.
  Reading `.tie` on a `ParametricCoefficient` raises, because the attribute is now `.equation`.
- `capabilities().schema_version` is `0.59`, where 1.9.0's was `0.55`.
  0.56 adds `RefinementResult.parametric_form`.
  0.57 adds `Phase.texture` and `RefinementResult.texture`.
  0.58 adds `RigidBody.riding`.
  0.59 adds `RefinedParameter.equations`, `.interval` and `.stderr_uncorrected`, and `RefinementResult.parametric_equations` and `.parametric_form_joint`.
  It also adds `StageResult.cell_reset`, `.collapsed`, `.width_twins_held`, `.window_area_tol` and `.n_lapack_fallbacks`.
  It adds `NodeAction.phase_support_sigma`, `.correlation_guard` and `.window_area_tol`, and `PlanSpec.phase_support_sigma` and `.closing_window_tol`.
  For indexing it adds `CellCandidate.n_search_unindexed` and `.unindexed_two_theta`, `ObservedPeak.two_theta_esd_fit`, `ExtinctionCandidate.excluded_groups` and `.laue_classes`, and `ExtinctionScreen.prior`.
  For QPA it adds `QuantitativePhaseAnalysis.unmeasured_phases` and `.unmeasured_held` and `NodeMetrics.held_scale_phases`, and lets `PhaseQuantity.weight_fraction` be `None`.
  What this means for stored files is in [Files that change](#files-that-change).
  A 1.9.0 result opens here with `equations` set to `None` on every row, meaning not recorded.
- `capabilities().indexing_thresholds_version` is `1.11`, where 1.9.0's was `1.9`.
  Every indexing change below that can alter a search's answer rides it: the picker's false-discovery bar and its resolvability rule, the undriven `weak_line` lines, the inlier retry, the search window sized by the list's widths, the intensity-weighted indexed fraction, and the extinction prior.
  `capabilities().report_thresholds_version` is `1.13`, where it was `1.12`, because the noise `MAGNETIC_WIDTH_UNMODELLED` divides by has moved ([Magnetic structures](#magnetic-structures)).
- Every plan now ends in a stage it does not declare, named `closing`, so `RefinementResult.stages` holds one entry more than the plan's `stages` (WP-2002).
  Code that reads `result.stages[-1]` as the last declared stage, or counts stages against `plan.stages`, should read `plan.run_stages()` instead.
  `compile_model`, `Refinement.predict` and `Refinement.run_stage` now compute at the closing stage's windows by default, so a pattern they draw carries tails a 1.9.0 one lacked.
  Pass `window_area_tol=rietx.model.forward.WINDOW_AREA_TOL` to `compile_model` or `run_stage` for 1.9.0's windows.
  What the closing stage changes in an answer is under [Numbers that move](#numbers-that-move).
- `build_report` takes `instrument=` beside `structure=`, and refuses a Rietveld or Le Bail `model=` passed without both (WP-2002).
  The report now reads its misfit at the closing stage's precision and its peak shapes at the declared stages', so it compiles whichever of the two models it was not handed.
  A Pawley model is read as it is, as before.
- `Harmonic.order` has no default, where it was 2, and `rietx.schemas.instrument.DEFAULT_HARMONIC_ORDER` is gone (WP-2002).
  Which orders a monochromator passes depends on its crystal: Si(111) and Ge(311) pass no λ/2.
  `Instrument.constant_wavelength_neutron(harmonics=True)` is refused with a message naming the crystals, so pass the orders, such as `harmonics=[2]`.
  A stored instrument carries its order and opens as before.
- `Refinement.tie` and `tie_equal` refuse a tie whose source is itself tied onto a locked or derived row (WP-1804).
  1.9.0 accepted it and left the target frozen without a word.
  No shipped plan or verb builds that chain, so no fit moves.
- `magnetic_supercell` refuses a magnetic candidate or group given without `magnetic_species` ([#1079](https://github.com/yue-here/rietx/pull/1079) by @mustachefeeling).
  1.9.0 returned a child phase with a magnetic group and no moment on any site, which fitted with no magnetic term and no diagnostic.
  A displacive candidate carries no moment and is not refused.
- Every diagnostic's `message` and `suggestion` is rewritten (WP-1985).
  The message states what this case found, with its numbers, and the suggestion is one action.
  What a code means moved out of both, to `Diagnostic.explanation` and `rietx.help.explain(code)`.
  `str(d)` prints `warning[CODE]: message`, then an `at:` line with the paths and a `help:` line with the suggestion.
  The rewrite renames no code, so code that matched on message text should match on `code` and `where` instead.
  The parameter help, the plan descriptions in `PLAN_INFO` and the API summaries are rewritten in the same voice.
- `rietx.help.PEAK_DIAGNOSTIC_HELP` is now `rietx.help.DIAGNOSTIC_HELP`, and it explains every diagnostic code rietx raises (WP-1985).
  `rietx.help.help_registry()` names that arm `"diagnostics"`, where it was `"peak_diagnostics"`.
- A GSAS-II project's spherical-harmonics entry is now `Gsas2Hap.texture`, and its `Gsas2Hap.preferred_orientation` is `None` (WP-1960).
  In 1.9.0 that field held the entry's unused March-Dollase slots under the model name `"SH"`.
- Three limit constants are gone, with the limits they set (WP-2002): `rietx.params.vector.SIZE_CAP_MIN_SIZE_A`, `rietx.schemas.structure.MARCH_R_MAX` and `rietx.schemas.instrument.HARMONIC_WEIGHT_MAX`.
  `rietx.params.vector.size_cap` takes the fitted range alone, `size_cap(tt_min, tt_max)`, where it also took a wavelength.
  `rietx.schemas.structure.MARCH_R_MIN` is now 1e-6, where it was 0.15.
- `auto_background` returns a `BackgroundChoice`, the background with the scores it was chosen on beside it (WP-2002, B12).
  Assign its `background` to `Instrument.background`: `ins.background = rx.auto_background(data).background`.
  In 1.9.0 it returned the background alone, and code assigning that now raises a validation error naming `BackgroundChoice`.
  The background itself is the one 1.9.0 built.
- `solve_magnetic` no longer takes `tie_r`, and `rietx.strategy.magnetic.SOLVE_TIE_R_MAGNETIC` is gone (WP-2002, B12; the ranking change is under Magnetic structures).
- `QPA_FRACTION_UNDETERMINED` is now `QPA_FRACTION_RANGE`, an `info` record on every width profile whose fit has an esd, and `rietx.schemas.fraction.FRACTION_PROFILE_EXCESS` is gone (WP-2002, B12).
  In 1.9.0 the code was a warning, raised only when an admissible fraction lay more than twice the esd's 95 % half-width from the fit's, a factor chosen rather than measured.
  The record's `value` is that distance, `FractionProfile.excess`, so a filter on the old code becomes a test of `value`.
- `rietx.viz.indexing` no longer has the colour constants `OBS`, `CALC`, `BKG`, `DIFF`, `ABSENT` and `UNMATCHED` (WP-1972).
  Their values are the `index_obs`, `index_calc`, `index_bkg`, `index_diff`, `absent` and `unmatched` entries of `rietx.viz.plots.PALETTES["light"]`.
  `CANDIDATE_COLORS` stays.
- `CandidateSet.classes` is now the partition split by the consistency rule ([#936](https://github.com/yue-here/rietx/pull/936) by @mustachefeeling, issue #565 part 5), so a set whose union-find class held a proved separation reports more classes than 1.9.0 did, one per irrep group the proofs tell apart.
  `CandidateSet.merged_classes` holds the old union-find partition beside it.
  `solve_magnetic` therefore tries one more representative on such a set, never fewer.

- `PatternData` refuses an inverted or empty excluded region, such as `(31, 30)` or `(30, 30)`, with the sentence a project's document already used (WP-1986).
  In 1.9.0 it accepted one and excluded nothing.
  A fit given an inverted `two_theta_limits` now says so, where it reported that fewer than 10 points remained.

- `pick_peaks` decides a group's component count by resolvability as well as by ΔBIC ([#948](https://github.com/yue-here/rietx/pull/948) by @mustachefeeling, issue #934).
  Two components of comparable area closer than Sparrow's limit for the fitted shape (no dip between two equal lines there) are reported as one line: the stronger one, its σ(2θ) widened to reach the other, which stays in the list flagged `unresolved_split`.
  `ObservedPeak.two_theta_esd_fit` keeps the fit's own σ(2θ) from before the widening.
  A group whose fitted width runs into its bound, five times the pattern's own width law, is flagged `width_capped`.
  `fit_peaks` and the peak editor name their own positions and make neither judgement.
  Both flags leave `usable()`, and the info diagnostics `PEAK_UNRESOLVED_SPLIT` and `PEAK_WIDTH_CAPPED` name them.
  On #728's synthetic silicon with flat-topped lines, 34 usable components on 11 lines become 18; with its steep background, 26 off-lattice usable components become 6.
  Over the 16 IUCr round-robin lab patterns 789 usable components become 782 (cpd-4 76 to 75); `width_capped` fires on six of them, each at I/σ_I ≤ 3.9.

- A fit whose declared stages run away can spend a very long time in its closing stage (WP-2045 owns the fix).
  The closing stage rebuilds the model at the answer it is handed, so a runaway width or axial ratio gives it peak windows as wide as the pattern.
  On the IUCr round-robin series that `tests/test_acceptance_sequential.py` carries whole from mixture to mixture, scales included, as `SequentialRefinement` does by default, the warm fit of cpd-1b walks `axial_sl` to 557.8 and ends at Rwp 0.760.
  1.9.0 bounded `axial_sl` at 0.2 ([Numbers that move](#numbers-that-move)).
  The closing stage then costs about 1 500 times what one evaluation of the stage before it cost, and it ran for over 50 CPU-minutes without finishing.
  Code from before the closing stage fitted the same two patterns in 3 seconds.
  Set `RefinementPlan.closing_window_tol` to `None` to skip the closing stage: on that series all eight patterns then finish in 9.2 s, each accepted on its first attempt.
  Without the closing stage a fit's answer moves by up to 0.97 esd, and cpd-1a's weight fractions by up to 0.12 wt % ([Numbers that move](#numbers-that-move)).

### Numbers that move

- Every plan ends in a closing stage, so the answer of every default fit moves (WP-2002).
  After the declared stages, rietx compiles the model again at the answer, with peak windows that drop 0.1 % of each peak's area where the declared stages drop 2 %.
  It then solves once more with every parameter the plan freed.
  At 2 % the missing tails had moved lab answers by up to 0.97 esd, such as zincite's scale on cpd-1a and the fluorapatite's Lorentzian size, and the background coefficients by 2 to 5 esd.
  The closing answer lies within 0.02 esd of the answer with complete tails on the fluorapatite, cpd-1a and 11-BM NAC.
  It also removes the dependence on the start that the frozen windows caused: on the fluorapatite, Biso started at 0.5 and at 1.5 Å² gave answers 0.119 esd apart, and now 0.000.
  Switching the closing stage off moves cpd-1a's weight fractions by up to 0.12 wt %, the fluorapatite's Lorentzian size by 2.5 % and its strain by 3 %, LaB6's widths by 1-2 %, and NAC's values by under 0.4 %.
  A fit takes 1.2 to 2.3 times as long, from 1.2× on NAC to 2.20-2.33× on the fluorapatite.
  Set `RefinementPlan.closing_window_tol` to `None` to run the declared stages alone, as 1.9.0 did.
  `RefinementPlan.run_stages`, `.closing_stage` and `.stage_window_tols` list what a plan runs, and `StageResult.window_area_tol` and `NodeAction.window_area_tol` record the fraction each stage ran at.
  BGMN ends its refinements the same way, with every parameter free and restarted from the previous answer.

- A phase with no reflection in the fitted range has its scale held at the value handed in, under every solver, and no weight fraction ([#1103](https://github.com/yue-here/rietx/pull/1103) by @mustachefeeling, WP-1958, issue #954).
  Its `PhaseQuantity.weight_fraction` and esd are `None`, `QuantitativePhaseAnalysis.unmeasured_phases` names it, and the other fractions are normalised over the phases seen in range, which `PHASE_UNCONSTRAINED`, the QPA table's caveats and the text summary say.
  In 1.9.0 the scale stayed free: on WP-1534's four-phase fixture over 25–33° Cu Kα, `solver="trf"` walked bcc Fe's scale from 1e-4 to 164.7 and read iron at 99.99 wt%, and the default LM left it at its start and read 0.61 wt%, the start value; both withheld every other fraction's esd.
  Now neither moves the scale, iron has no fraction, and corundum, zincite and fluorite read 72.4, 3.7 and 23.9 wt% with esds.
  A joint fit holds each histogram's own scale where that histogram has no line of the phase.
  The Brindley correction is skipped while a phase is unmeasured, and `microabsorption_skipped` names it, since the mixture's mean µ needs every phase's fraction.
  Code that formats every `weight_fraction` as a number checks for `None` first.

- `Refinement.report().microstructure[i].separable` is `None` where the report fitted no width trend (WP-1545).
  In 1.9.0 it read `True`, and `size_strain_collinearity` read 0.0, on any fit whose width trend had too few regions to fit, such as a synthetic fit at GoF 1.00.

- A cell that runs away during a stage goes back to the value the stage started from (WP-2002, B8).
  When a free cell parameter leaves ±15 % of its stage-start length (±6° for an angle), its phase's free cell is put back at the start and held while the stage solves once more, and `StageResult.cell_reset` names it.
  In 1.9.0 the parameter was pulled to the edge of that window, a value no fit produced, with esds from the runaway point.
  A cell held this way in the last stage leaves `RefinementResult.parameters`, and `CELL_RUNAWAY` says what was put back.
  It fired in none of the 104 fits of WP-1523's sweep, so ordinary fits do not change.
  `rietx.refine.clamp_cell_runaway` is now `reset_cell_runaway`, and its record `CellClamp` is `CellReset`.

- A crystallite size is no longer held at 2 nm or more (WP-2002, B8).
  The only default limit on `lor_size` and `gauss_size` is now a line no wider than the fitted 2θ range, which on a Cu Kα 10–80° scan sits near 0.15 nm.
  A fit whose size term stopped at the 2 nm floor in 1.9.0, reported by `BOUND_HIT`, now refines past it.
  `SIZE_UNUSUALLY_SMALL` still fires below 5 nm, and its message now says that below about 2 nm a crystallite is a few unit cells and broadened Bragg peaks may not describe its pattern; the Debye scattering equation does.
  For comparison, TOPAS's `CS_L` limits size to 0.3-10 000 nm, GSAS-II clamps it to 0.001-10 µm, and FullProf sets no limit.
- Limits chosen on quantities that stay physical are gone (WP-2002, B9).
  A fit that stopped at one of them in 1.9.0, reported by `BOUND_HIT`, now goes past it.
  `Atom.occ` keeps its floor of 0 and loses its ceiling of 1.5, and `OCCUPANCY_ABOVE_ONE` (below) reports a refined value above 1.
  March-Dollase `r` keeps only a floor of 1e-6 against the pole at zero, where it was held to 0.15-6, so a pressed clay or mica plate can refine below 0.15.
  `Harmonic.weight` loses its ceiling of 0.5, and `HARMONIC_FRACTION` still warns past 15 %.
  `EmissionLine.weight` loses its ceiling of 2, and the presets' Kα2 weight its ceiling of 1.
  `axial_sl` and `axial_hl` lose their ceiling of 0.2 and keep their floor of 0.
  The peak-position corrections lose their default bounds too: `Instrument.zero_shift` its ±0.5°, `Geometry.sample_displacement` and the two capillary offsets their ±1 mm, and `Geometry.sample_transparency` its ceiling of 0.05 (it keeps its floor of 0).
  Where a scan cannot separate one of them from the cell, the fit reports `FLAT_DIRECTION` and the cell's esd shows the spread.
  On 11-BM NAC with zero and both capillary offsets freed, the cell now lands 5111 ppm from its reference with an esd of 2544 ppm, where the bound had stopped it at 1097 ppm with an esd of 2610 ppm.
  The GSAS, GSAS-II, FullProf, `.prm`, `.instprm` and recipe readers no longer write the old ceilings either, so an `.instprm` or recipe stating SH/L above 0.4 now reads.
  A project, history or JSON file written before 1.10 stores its bounds and keeps them, since a stored bound is the caller's claim: nothing is migrated, and such a file refits as it did.

- A search that finds no lattice two engines agree on is **searched again by inlier count**, and says so with `INDEX_INLIER_RETRY` ([#951](https://github.com/yue-here/rietx/pull/951) by @mustachefeeling, issue #933).
  On a list with measured intensities, the retry accepts a cell that indexes at least 60 % of the N driven lines (and n_dof + 4), the five strongest among them, where the first pass needs all but two; a list whose lines carry one intensity keeps the count of two.
  Off-lattice lines past two no longer leave a search with no cell, or with single-engine cells that explain them by having a line everywhere: on a synthetic Si pattern with twelve planted lines (53 usable), a cubic search found no cell within 1 % of the truth at a count of 2 or 3, and now ranks the truth first, found by all three engines.
  A run whose first pass found a lattice two engines agree on is unchanged, because the inlier rule changes the pool the panel ranks: on SRM 660c LaB6 it alone takes the certified cell from rank 1 to 3.
  `CellCandidate.n_search_unindexed` reports the driven lines a cell left, and `.unindexed_two_theta` the usable lines it left, in 2θ (schema 0.59), under every rule.
- With no shift declared or measured, a picked list's search window is sized by its own widths, the lower-quartile fitted FWHM, where it was a constant 0.05° 2θ ([#951](https://github.com/yue-here/rietx/pull/951) by @mustachefeeling, issue #916).
  The 0.05° stays as a ceiling, so a lab pattern with lines 0.05° or wider is unchanged, and a position-only list keeps it.
  On a synthetic Si twin at λ 0.8257 Å (FWHM 0.021°) the allowance falls to 0.021°, the unshifted truth's cell moves from −228 ppm to −7 ppm, the √2·a₀ cubic I cell no longer reaches `medium`, and a 100 µm displacement the pair screen cannot name is still found.
  `INDEX_SHIFT_ALLOWANCE` still fires, since the shift itself is unmeasured, and its message names where the window came from.
- A picked line flagged `weak_line` no longer drives an indexing search ([#1048](https://github.com/yue-here/rietx/pull/1048) by @mustachefeeling, issue #934).
  It stays in `usable()` and is scored as before, so a cell may still explain it, but `search_line_order` leaves it out of the lines an accepted cell must index; below six unflagged lines the strongest flagged ones are driven again.
  On the synthetic Si pattern of issue #916 the driven set falls from 17 lines (18 under a tuned profile) to the 11 silicon lines: a cubic search with a declared `n_unindexed=2` returned no cell and ranks the truth first, and an all-systems search moves the truth from sixth to fourth (absent to fifth).
  No indexing-acceptance list drives a `weak_line` line, so none of their answers moves.
- The `indexed_fraction_low` caveat reads the share of the usable lines' **intensity** a cell indexes, where it read their count ([#1042](https://github.com/yue-here/rietx/pull/1042) by @mustachefeeling, WP-1969, issue #933).
  Weak foreign lines no longer refute the cell that explains the rest of the pattern, and a cell missing a strong line is refuted however many weak ones it indexes.
  On SRM 660c with three or six weak impurity lines the certified cell indexes 25 of 28 or 31 lines (0.89, 0.81) but 0.93-0.97 of the intensity, and its intensity share passes; the same six lines at the stronger half's intensities leave it at 0.73-0.74 and `low`.
  A line count under the same 0.9 bar caps the grade at `medium` through the new caveat `indexed_lines_low`, which does not refute: from the line list alone a sub-cell missing a superstructure and a cell beside an impurity look the same.
  The certified cell with three or six weak impurity lines therefore goes from `low` to `medium`, not `high`, and the six strong lines leave it `low`.
  A caller matching the `IndexCaveat` vocabulary exhaustively gains one member.
  On a position-only list every line weighs one, so nothing moves there.

- A joint fit with per-histogram phase paths now holds a pattern's own copy of a phase's cell where that pattern cannot see the phase (WP-1325).
  In 1.9.0 the cell stayed free in that pattern whenever another pattern still showed the phase, so it could wander with nothing to fit.
  A fit moves only where a phase is absent from some of its patterns and its cell is per-histogram, as under `SharingMap(per_histogram=["phases.*"])`.

- Indexing no longer keeps one lattice as two candidates when its two descriptions reduce either side of a Niggli boundary ([#949](https://github.com/yue-here/rietx/pull/949) by @mustachefeeling, issue #834).
  Two candidates the χ² test calls distinct are now compared again across the reduction's boundaries, in Selling's form, and joined when a description of one passes the same χ² against the other.
  `same_lattice` and dedup's grouping answer this way; a pair the old test joined is answered exactly as before.
  Replaying every dedup call logged on the bethanechol benchmark, 574 of 178 875 groups go, and on the LaB6 acceptance searches the rank-6 tetragonal duplicate joins the rank-3 one.
  Dedup takes up to about twice its former time; on the benchmark that is a few per cent of a run.

- A reflection whose drawn peak lies inside the fitted range is now modelled however far the geometry's shift moves it (WP-1908).
  The reflection list reached a fixed 0.5° past the range, so a large sample displacement at a range edge left such a peak out of the model, its ticks and the report.
  The list now widens by the shift and stops at 180°, and a geometry with no shift keeps its 1.9.0 list to the bit.
  A tick now also sits at the refined wavelength: refining λ by 0.1 % had left a tick at 150° about 0.43° from its peak, by 2·tanθ·Δλ/λ.

- `RefinementResult.absorption` and the surface-roughness regime check read each reflection at its Bragg angle, where the forward model applies both corrections (WP-1976).
  In 1.9.0 they read the angle the peak is drawn at, which a refined displacement moves by up to 0.26°.
  On rutile with a 0.5 mm displacement the reported `equivalent_delta_biso` moves by at most 0.0025 Å², and the roughness check can change its verdict near its edge.

- `RefinementResult.geometry.bonds` lists bonds longer than 3.5 Å (WP-2002).
  The neighbour search stopped at the 3.5 Å contact radius, although the covalent radii call longer pairs bonds, so CsCl's eight 3.571 Å Cs–Cl bonds were missing.
  The search now reaches the longest pair the radii could bond, and the contact radius bounds only the contacts listed.

- A restraint now binds the nearest image of its atom pair in any cell (WP-2002).
  In monoclinic cells stored at β 135-150°, the one shell of lattice shifts searched missed the nearest image of 72 of 2518 pairs within 4 Å, so a restraint could bind the wrong pair.
  A second pass now covers every nearer image, and a reduced cell's restraints are unchanged.

- The Laue half of Sabine's extinction factor is now one continuous function, e^(−x)·[I₀(x) + I₁(x)] (WP-2044).
  It is the exact integral that the papers' series and asymptote truncate. In 1.9.0 rietx used GSAS-II's pair, which steps by 3.6 % at x = 1, and no program surveyed evaluates it without a step.
  A fit moves where extinction is on and some reflection's x passes about 0.5, the size of the strongest reflections of a well-crystallised phase: the factor differs from 1.9.0's by 5.6e-6 at x = 0.5, 0.08 % just below x = 1, 3.6 % just above it and 0.1 % at x = 5. Below x = 0.25 it differs by under 1e-7.
  On the QPA guide's first fit, CaF₂'s reflections reach x = 6.5 and the fit had stopped with one on the step. Its esd then depended on the platform: 3.08 ± 0.21 wt% on GitHub's macOS runner and ± 2.24 on Linux. Now the fit gives 3.58 ± 3.53 wt% with extinction 1919 ± 4066 µm², and `HIGH_CORRELATION` reads scale ~ extinction at ρ = +0.998. Holding CaF₂'s extinction and Biso, as the guide does, still gives 1.37 ± 0.07 wt%.
  The TOPAS writer has no Bessel function to spell, so it writes Abramowitz & Stegun's polynomials, within 3.6e-8 of rietx's factor, and the file's head says so.

- [VALIDATION.md](https://github.com/yue-here/rietx/blob/main/docs/VALIDATION.md) is re-measured on this release, and each row that moved gives its 1.9.0 value beside the new one.
  Nearly every fit row moved, most by under 1 %, through the closing stage and the hold on an instrument width beside its free specimen twin (both WP-2002).
  WP-2044's extinction factor moved none of them.
  These moves are larger than 1 % or change what a row claims.
  On round-robin sample 1 with dispersion, the worst weight-fraction error is 1.37 wt % and the RMS error 0.69 wt %, where 1.9.0 gave 1.20 and 0.62.
  Without dispersion the worst error is 5.10 wt %, where it was 4.92.
  On sample 2's brucite the worst error is 3.01 wt % under March-Dollase and 2.91 wt % with spherical harmonics of order 6, where 1.9.0 gave 2.80 and 2.71.

- A joint fit now tests each parametric declaration's form against its own data (WP-1325, schema 0.56).
  `RefinementResult.parametric_form` holds one `ParametricFormTest` per declaration: how much the fit would improve with the target free in each pattern, over the noise level, against the 95 % point for its degrees of freedom.
  It is a score test at the answer and needs no refit; on a 33-pattern real ramp it cost 0.7-0.8 s and gave a full refit's verdict on all five equations tried.
  `str(result)` prints the verdict after each declaration's coefficients, and `PARAMETRIC_FORM_REJECTED` (warning) names the coefficients of a rejected equation, whose esds assume the form.
  The test sees an equation only where a pattern measures its target, so an equation carried through patterns that cannot see a phase is not checked there.
  The verdict line counts the patterns tested against the subset (`ParametricFormTest.n_subset`) and gives the p-value (`ParametricFormReading.p_value`).
  With several equations, each is read twice: with the other equations tied (`ParametricFormTest.tied`) and with their targets freed (`ParametricFormTest.others_freed`).
  The freed reading is the verdict, because it does not assume the other equations' forms.
  The statistic is the χ² the alternative would remove over the answer's χ²_red.
  On equations that must hold any smooth truth, over three real ramps, it rejected 12 of 242 (5.0 %).
  Two equations whose targets change the pattern alike can each pass with the other freed while both are wrong, so `RefinementResult.parametric_form_joint` also reads every equation at once.
  When it rejects and no single equation does, `PARAMETRIC_FORM_REJECTED` names every tested equation's coefficients and says the data cannot tell which form is wrong.
  A verdict beside a rejected equation is marked provisional (`ParametricFormTest.provisional_on`), because the rejected equation has moved the answer every reading steps from.
- A joint fit's parameter rows now say which parametric equation set them (WP-1325, schema 0.59).
  `RefinedParameter.equations` names the declaration on each pattern's target row, on what follows the target there, and on each coefficient's `vars.` row, and is empty on every other row.
  A target row's value and esd are the equation's at that pattern's coordinates, so they can be far tighter than the pattern measures alone.
  `PARAMETRIC_TARGET_UNSEEN` (warning) names the patterns where an equation sets a target whose phase the pattern cannot see.
- A parametric equation can be evaluated at any coordinate, with its esd (WP-1325, schema 0.59).
  `RefinementResult.parametric_equations` holds each declaration as resolved, a `RefinedParametricEquation` with its coefficients' covariance in the caller's units, and `result.parametric_value("a", {"T": 293.0})` returns a `ParametricValue`.
  At a pattern's own coordinates it reproduces that pattern's row; beyond the subset's range it names the coordinates it extrapolates in, and it carries the form test's verdict.
  It also says whether that verdict is provisional and whether the joint reading rejects the set, because the esd assumes the form either way.

## Magnetic structures

- `solve_magnetic` charges each ΔBIC N/f² observations, where it charged the N fitted channels (WP-2002, B12; issue #270).
  f is the Bérar-Lelann factor of the restricted fit: the nuclear reference for a trial, the winner for the descent audit.
  Neighbouring channels of one peak share the sign of their misfit, so the raw count let any χ² gain outvote the parameter penalty.
  This is the count `compare_freed` already charged.
  Every ΔBIC shrinks, by about f², and the caveat that said the count was raw now gives N, the count charged and f.
  On the three real patterns in the tests the verdict is unchanged.
  On Cr₂WO₆ at 4 K (f 3.38) the winner 58.395 leads by 143 where it led by 1682, and 58.398 falls from +61 to −3, so it no longer counts as evidence.
  On LaMnO₃ at 50 K (f 3.22) Pn′ma′ leads by 164 where it led by 1704.
  Cr₂WO₆ at 150 K still has nothing to solve.
- Every ΔBIC tie in `solve_magnetic` abstains (WP-2002, B12 and the ruling of 2026-10-20).
  In 1.9.0 a magnetic-only R lower by more than 2 % chose the winner first; that margin was chosen and never measured.
  A tied class with fewer moment parameters also won, which counted a cost the ΔBIC already charges.
  The tied classes now come first in `trials`, fewest moment parameters first, and the reason gives each one's count and R_mag, neither of which ranks them.

- A moment angle the fit leaves out of its covariance, at a direction the site symmetry fixes, now carries its profile interval (WP-2002, B2, schema 0.59).
  In 1.9.0 such an angle had no esd and nothing in its place, so its value read as exact.
  After the last stage, a single-pattern fit runs `profile_interval` for each such angle and stores the answer on `RefinedParameter.interval`.
  The refits run on a copy of the models, so the history gains no node.
  `MOMENT_ANGLE_STATIONARY` now gives each angle's distance from the direction and says whether the interval includes it.
  Only a fit whose test passed pays: 20-32 refits an angle, 2.6-16.7 s on the two-site test fits of 0.2-1.2 s.
  A joint fit computes no interval, and nor do the trial fits `solve_magnetic` runs.
  Any profile interval of a moment angle (explicit or automatic) now stops a side half a turn from the value, with the new stop `"period"` and no end, since an angle repeats every 2π: a moment the data no longer saw had walked to ±1e12 rad over 120 refits an angle.

- `analyse` splits a class of magnetic candidates that holds a proved separation ([#936](https://github.com/yue-here/rietx/pull/936) by @mustachefeeling, issue #565 part 5, the last of five).
  A class union-find joined can hold a pair one family is proved unable to reproduce: the join rests on a false sampled edge, or on a partial containment.
  Every pair the loop skipped as already joined, whose join the proofs have since undone, is now drawn; every sampled direction a proof contradicts is drawn once more; and what is still joined is split at the two irreps holding the proof, each dropped edge naming the proof that refuted it (`refuted_by`).
  `classes` is that split partition and the new `merged_classes` the union-find one; the table prints the dropped edges with their draw counts and which merged class each split class came from.
  On the `F m -3 m` Γ set at the general site the union-find answer was four classes with S8 and S9 inside S7 ∪ S10, and is now six, S8 and S9 apart on proofs.

- `determine_extinction_symbol(restrict=rx.ExtinctionPrior(sohncke=True))` declares facts about the specimen: chirality, centrosymmetry, polarity ([#940](https://github.com/yue-here/rietx/pull/940) by @mustachefeeling, issue #935).
  A powder pattern cannot separate the members of an extinction class, so the choice inside one is chemistry, and this is where it is declared.
  The prior filters each class's members and nothing else: every class is fitted and ranked on the data as before, `ExtinctionCandidate.excluded_groups` names what it removed, and `EXTINCTION_PRIOR_APPLIED` reports it.
  `ExtinctionScreen.prior` records the declaration.
  `best_or_none()` answers among the classes the prior leaves a member in, so a synthetic P 2₁ specimen declared enantiopure answers `P 1 21 1` with `P 2₁` alone.
  It abstains when the data prefer an emptied class decisively, so a P 2₁/c specimen declared enantiopure gets no chiral answer.
- `ExtinctionCandidate.laue_classes` groups a class's members by Laue class, and `LAUE_CLASS_NOT_SEPARABLE` says when the leading class spans more than one ([#940](https://github.com/yue-here/rietx/pull/940) by @mustachefeeling, issue #935).
  Such members differ only in which reflections are equivalent, never in a position or an absence, so a structure solution runs once per Laue class.

- `solve_magnetic` ends its winner in the closing stage its plan would run, when the package chose the plan (WP-2002).
  The winner's Rwp, GoF, R_mag, moments and status come from that fit, and its ΔBIC from the ranking, whose trials keep the declared windows; a caveat says which numbers are which.
  On a synthetic two-site Pnma set the moduli esds fall from 0.00242 and 0.00179 to 0.00151 and 0.00111 μ_B, since the declared windows' missing tails had inflated them by about 1.6.
  A caller's own plan is untouched.

- `FitReport.satellites` now offers the zone-boundary points of a centred lattice ([#1071](https://github.com/yue-here/rietx/pull/1071) by @mustachefeeling, issue #795).
  Its candidates were the literal (0 or ½, 0 or ½, 0 or ½) in conventional axes, which on a centred lattice is not the set of points with k ≡ −k.
  On F m m m that left out the X point (1, 0, 0), where the (Pr,Sr)MnO₃ structure of GSAS-II's Magnetic-IV tutorial orders, so every candidate scored at chance.
  The X point now ranks first on that pattern.
  A primitive or rhombohedral-axes lattice keeps its candidates to the bit.
- The satellite note now names unexplained peaks at positions the lattice's centring forbids, such as (1 0 0) on F ([#1102](https://github.com/yue-here/rietx/pull/1102) by @mustachefeeling, issue #795).
  It gives how many there are, the strongest by Δ/σ with its (h k l), and the causes the arm cannot tell apart: a lattice less centred than declared, λ/2, an impurity line, and on neutron data a magnetic structure with that integer k.
  It offers λ/2 only where the space group allows the (2h 2k 2l) reflection.
  No count, ranking or diagnostic code changes.

- `magnetic_supercell` restates the parent's scale divided by |det P|², where it carried the scale unchanged ([#1077](https://github.com/yue-here/rietx/pull/1077) by @mustachefeeling).
  The child cell holds the parent's atoms |det P| times, so each parent reflection's F is |det P| times larger there.
  A supercell built from a converged nuclear fit therefore computed a pattern |det P|² times too strong, four times at index 2.
  The child with its moments at zero now computes the parent's pattern to 1e-9, and the weight fraction is unchanged.

- `MAGNETIC_WIDTH_UNMODELLED` measures its noise on the nuclear-only reflections ([#1087](https://github.com/yue-here/rietx/pull/1087) by @mustachefeeling, WP-1343).
  It had taken the scatter over the magnetic reflections too, which the misfit under test inflates.
  On a synthetic CrSBr fit with the magnetic width held, that scatter was 2.57 against 0.99, so z sat at 2.99 under its bar of 3 while the moment was 25 % low.
  Where the magnetic misfit is not width-shaped the two scatters agree to a few per cent, so z moves little; where the width is the misfit, z grows by their ratio.
  No fitted value changes.

- A distorted child structure decomposes into displacive modes in Å, one amplitude per irrep of its parent ([#950](https://github.com/yue-here/rietx/pull/950), [#996](https://github.com/yue-here/rietx/pull/996) and [#1022](https://github.com/yue-here/rietx/pull/1022) by @mustachefeeling, WP-1419).
  `distortion_basis(parent, child, transform)` in `rietx.crystallography.representation.distortion` builds every symmetry-adapted mode the child admits, in the AMPLIMODES normalisation and the parent's unstrained metric.
  `mode_amplitudes` gives the child's amplitude per (k, irrep, direction), and the tests check it against Perez-Mato et al. (2010) on LaMnO₃.
  `IrrepModes.primary` and `ModeAmplitude.primary` mark an irrep whose isotropy group is the child's own group, and read `None` where spglib could not name that group.
  `rietx.crystallography.magnetic.isotropy.distortion_candidates(parent, k)` lists every child a displacement at k can give, each with its modes.

- The peak-width coefficients `u`, `v` and `y` lose their chosen floors (WP-2002, ruled 2026-10-23).
  Each now stops at the mirror image of its ceiling, −180² deg² or −180°, which no width reaches.
  The X-ray presets held `u` ≥ −0.05 and `v` ≥ −0.5, the neutron preset `u` ≥ −0.5 and `v` ≥ −4, and both held `y` ≥ 0.
  The five coefficients' ceilings sit at the width of the 2θ axis, 180² deg² for `u`, `v` and `w` and 180° for `x` and `y`.
  In 1.9.0 the X-ray presets capped each at 1 and `v` at 0.5, and the neutron preset each at 8 and `v` at 4.
  What must stay non-negative is the width.
  The default solver holds the Gaussian width as before, and now holds the Lorentzian width X/cosθ + Y·tanθ at or above zero at every reflection a stage lists, in a joint fit too.
  Under `solver="trf"`, `RESOLUTION_NOT_POSITIVE` now also reports a Lorentzian instrument width below zero.
  `w` and `x` keep their floors.
  A stage that frees an instrument width with the specimen width of the same angular shape now holds the instrument width at its stage-start value, and `StageResult.width_twins_held` names the pair.
  The pairs are `u` with `gauss_strain` or `gauss_size`, `x` with `lor_size`, and `y` with `lor_strain` or a Stephens block.
  With both free the data see only their sum, and without the floors the pair would walk off together.
  No shipped plan frees such a pair; `solve_magnetic`'s last stage did, and now frees the instrument widths alone.
  A plan of your own that fits the instrument widths on the specimen before freeing its widths keeps the split that earlier stage found.
  Calibrating on a standard first, with `lab_calibrate` and `load_instrument_profile`, avoids it.
  None of the seven programs surveyed floors an instrument coefficient, and those that separate instrument from specimen fix the instrument from a standard or from its geometry.
  Every preset builds one box, so `TCHZ_BOUNDS_COARSE` is gone, and `ProfileTCHZ.coarse` stays as the way to build the five widths from values.
  The `.prm`, `.instprm` and recipe readers now read a negative Y, and refuse one only where it takes the Lorentzian width below zero: over the fitted range for a recipe, below 180° 2θ for a calibration.
  A project, history or JSON file written before 1.10 stores its bounds and keeps them.
- `read_gsas_tof_iparm` fills `TOFSource.l1_m` on every bank from the file's `FPATH1` record, where 1.9.0 left it `None` and reported the record dropped ([#1122](https://github.com/yue-here/rietx/pull/1122) by @mustachefeeling, WP-2032, with the three notes below).
  The GSAS manual does not list `FPATH1`; SNS files write it, so it is read as one number and a record holding anything else is refused naming the file.
- A GSAS file whose `TIME_MAP` record follows a bank's rows reads, where 1.9.0 refused it as a malformed data record of that bank (WP-2032).
  The manual lets the record sets come in any order.
- `load_instrument_profile`'s refusal of a profile holding a time-of-flight bank starts with the file's path (WP-2032).
- `Project.open` on a project that records no GSAS `bank` writes the bank it read into `data_ref.options`, so the next save records it (WP-2032).
- `read_gsas_tof_iparm` reads a time-of-flight bank whose `ICONS` record writes `POLA`, `IPOLA` and `KRATIO` as zeros, where 1.9.0 refused any text in columns 53-77 ([#1126](https://github.com/yue-here/rietx/pull/1126) by @mustachefeeling).
  The manual says the three are absent for neutron data, and a blank FORTRAN numeric field reads as zero (ANSI X3.9-1978 §13.5.9), so a written zero and a blank are one record.
  A non-zero or non-numeric field is still refused, now naming its own columns.
  GSAS-I `.prm` files from SNS's NOMAD and POWGEN write the zeros.
- A GSAS `STD` bank that writes its counter numbers now reads ([#1072](https://github.com/yue-here/rietx/pull/1072) by @mustachefeeling, issue #1061).
  The reader split each record on whitespace, so such a bank came back with the counter numbers among the counts and the first half of the counts spread over the whole axis, with no diagnostic.
  It now reads each `(I2,F6.0)` field by position, as the GSAS manual gives the record, and refuses a field out of layout by its columns.
  The GSAS-II tutorial Magnetic-IV pattern writes counter numbers 1 to 20.
  Where a counter number exceeds 1, σ is withheld and `PATTERN_INTENSITY_SCALED` says so, because the manual does not say whether the count is then a total or a mean.
- A FullProf file opening with an `XYDATA` heading carries its `TEMP` as `PatternData.metadata["temperature_k"]` ([#1080](https://github.com/yue-here/rietx/pull/1080) by @mustachefeeling).
  1.9.0 skipped the heading's lines as rows it could not parse.
  An `INTER` line whose x or y factor is not 1, or whose interpolation switch is 1, is refused naming the file and the value, since 1.9.0 read such a file without applying them.
- A CIF site that lies on a special position within the file's printed precision is stored on the position without a diagnostic (WP-2037).
  A coordinate printed to d decimals stands for any value within half its last digit.
  So Ca1 of the bundled fluorapatite, at 0.3333333333, no longer reports `SITE_SNAPPED_TO_SPECIAL_POSITION`, and a site printed 0.33334 still does.
- A fit no longer stops with an error when LAPACK's divide-and-conquer driver fails to converge on a decomposition (WP-2002).
  rietx repeats that decomposition with the QR-iteration driver, which computes the same answer by another route, and `StageResult.n_lapack_fallbacks` counts the repeats.
  macOS's system LAPACK failed this way on a TRF fit of the round-robin brucite pattern, which now completes at Rwp 0.1787.
- A guard finding a later stage raises again on the same paths is reported once, the later one (WP-2002).
  `ADP_NOT_POSITIVE_DEFINITE`, `STEPHENS_STRAIN_NOT_POSITIVE`, `TEXTURE_NOT_POSITIVE` and `HUMP_TOO_NARROW` are taken again on the answer, so a finding the closing stage clears leaves the result.
- The fits rietx runs on a fit's behalf now take that fit's `phase_support_sigma` and `correlation_guard`, where they ran at 3σ and 0.98 whatever the fit used (WP-2002).
