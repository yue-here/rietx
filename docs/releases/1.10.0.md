> **Staging file, not yet a release.** Opened 2026-10-14, the day 1.9.0 was
> cut, so that a break or a user-facing addition is recorded the day it lands
> (ROADMAP protocol rule 6). There is no `1.10.0` on PyPI and no `v1.10.0` tag
> until `RELEASING.md` is walked. The cut writes the framing, and checks this
> file against the tag range `v1.9.0..main`. Stage each note under the

## Upgrading

Code written against 1.9.0 runs unaltered, except code that names `ParametricTie`, imports one of the six indexing colour constants named below, imports one of the five removed constants named below, uses what `auto_background` returns as a background, passes `tie_r` to `solve_magnetic`, or looks for the code `QPA_FRACTION_UNDETERMINED`.

### Code to check

- `SearchSpec.n_unindexed` and `SearchSpecSpec.n_unindexed` default to `None`, where they were 2, and also take `"inliers"`.
  `None` keeps the count of two and adds the retry below; an int still declares that absolute count with no retry, so code that set one is unchanged and code that read the default as an int now reads `None`.

- `ParametricTie` is now `ParametricEquation`, with no alias.
  Code from 1.9.0 that builds `parametric=[rx.ParametricTie(...)]` must change the name.
  The standard term is a parametric equation, as in GSAS-II and in Stinton and Evans (2007).
  A 1.9.0 result's `ParametricCoefficient` rows carry the key `tie`, and they open here with that key read as `equation`.
  Reading `.tie` on a `ParametricCoefficient` raises, because the attribute is now `.equation`.
- `capabilities().schema_version` is `0.59`, where 1.9.0's was `0.55`.
  0.56 adds `RefinementResult.parametric_form`.
  0.57 adds `Phase.texture` and `RefinementResult.texture`.
  0.58 adds `RigidBody.riding`.
  0.59 adds `RefinedParameter.equations`, `RefinementResult.parametric_equations`, `RefinementResult.parametric_form_joint`, `CellCandidate.n_search_unindexed`, `CellCandidate.unindexed_two_theta`, `StageResult.cell_reset`, `StageResult.collapsed`, `RefinedParameter.interval`, `PlanSpec.phase_support_sigma`, `RefinedParameter.stderr_uncorrected` and `Phase.parent_cell`.
  A model or result carrying any of them does not open in 1.9.0.
  A 1.9.0 result opens here with `equations` set to `None` on every row, meaning not recorded.
- A GSAS-II project's spherical-harmonics entry is now `Gsas2Hap.texture`, and its `Gsas2Hap.preferred_orientation` is `None` (WP-1960).
  In 1.9.0 that field held the entry's unused March-Dollase slots under the model name `"SH"`.
- Three limit constants are gone, with the limits they set (WP-2002): `rietx.params.vector.SIZE_CAP_MIN_SIZE_A`, `rietx.schemas.structure.MARCH_R_MAX` and `rietx.schemas.instrument.HARMONIC_WEIGHT_MAX`.
  `rietx.params.vector.size_cap` takes the fitted range alone, `size_cap(tt_min, tt_max)`, where it also took a wavelength.
  `rietx.schemas.structure.MARCH_R_MIN` is now 1e-6, where it was 0.15.
- `auto_background` returns a `BackgroundChoice`, the background with the scores it was chosen on beside it (WP-2002, B12).
  Assign its `background` to `Instrument.background`: `ins.background = rx.auto_background(data).background`.
  In 1.9.0 it returned the background alone, and code assigning that now raises a validation error naming `BackgroundChoice`.
  The background itself is the one 1.9.0 built.
- `solve_magnetic` no longer takes `tie_r`, and `rietx.strategy.magnetic.SOLVE_TIE_R_MAGNETIC` is gone (WP-2002, B12; the ranking change is under Magnetic structures).
- `QPA_FRACTION_UNDETERMINED` is now `QPA_FRACTION_RANGE`, an `info` record on every width profile whose fit has an esd, and `rietx.schemas.fraction.FRACTION_PROFILE_EXCESS` is gone (WP-2002, B12).
  In 1.9.0 the code was a warning, raised only when an admissible fraction lay more than twice the esd's 95 % half-width from the fit's, a factor chosen rather than measured.
  The record's `value` is that distance, `FractionProfile.excess`, so a filter on the old code becomes a test of `value`.
- `rietx.viz.indexing` no longer has the colour constants `OBS`, `CALC`, `BKG`, `DIFF`, `ABSENT` and `UNMATCHED` (WP-1972).
  Their values are the `index_obs`, `index_calc`, `index_bkg`, `index_diff`, `absent` and `unmatched` entries of `rietx.viz.plots.PALETTES["light"]`. `CANDIDATE_COLORS` stays.
- `CandidateSet.classes` is now the partition split by the consistency rule (issue #565 part 5), so a set whose union-find class held a proved separation reports more classes than 1.9.0 did, one per irrep group the proofs tell apart.
  `CandidateSet.merged_classes` holds the old union-find partition beside it.
  `solve_magnetic` therefore tries one more representative on such a set, never fewer.

- `PatternData` refuses an inverted or empty excluded region, such as `(31, 30)` or `(30, 30)`, with the sentence a project's document already used (WP-1986).
  In 1.9.0 it accepted one and excluded nothing.
  A fit given an inverted `two_theta_limits` now says so, where it reported that fewer than 10 points remained.

- `pick_peaks` decides a group's component count by resolvability as well as by ΔBIC (#934).
  Two components of comparable area closer than Sparrow's limit for the fitted shape (no dip between two equal lines there) are reported as one line: the stronger one, its σ(2θ) widened to reach the other, which stays in the list flagged `unresolved_split`.
  A group whose fitted width runs into its bound, five times the pattern's own width law, is flagged `width_capped`.
  `fit_peaks` and the peak editor name their own positions and make neither judgement.
  Both flags leave `usable()`, and the info diagnostics `PEAK_UNRESOLVED_SPLIT` and `PEAK_WIDTH_CAPPED` name them.
  On #728's synthetic silicon with flat-topped lines, 34 usable components on 11 lines become 18; with its steep background, 26 off-lattice usable components become 6.
  Over the 16 IUCr round-robin lab patterns 789 usable components become 782 (cpd-4 76 to 75); `width_capped` fires on six of them, each at I/σ_I ≤ 3.9.
  `INDEXING_THRESHOLDS_VERSION` moves to 1.11.

### Numbers that move

- `Refinement.report().microstructure[i].separable` is `None` where the report fitted no width trend (WP-1545).
  In 1.9.0 it read `True`, and `size_strain_collinearity` read 0.0, on any fit whose width trend had too few regions to fit, such as a synthetic fit at GoF 1.00.

- A cell that runs away during a stage goes back to the value the stage started from (WP-2002, B8).
  When a free cell parameter leaves ±15 % of its stage-start length (±6° for an angle), its phase's free cell is put back at the start and held while the stage solves once more, and `StageResult.cell_reset` names it.
  In 1.9.0 the parameter was pulled to the edge of that window, a value no fit produced, with esds from the runaway point.
  A cell held this way in the last stage leaves `RefinementResult.parameters`, and `CELL_RUNAWAY` says what was put back.
  It fired in none of the 104 fits of WP-1523's sweep, so ordinary fits do not change.

- A crystallite size is no longer held at 2 nm or more (WP-2002, B8).
  The only default limit on `lor_size` and `gauss_size` is now a line no wider than the fitted 2θ range, which on a Cu Kα 10–80° scan sits near 0.15 nm.
  A fit whose size term stopped at the 2 nm floor in 1.9.0, reported by `BOUND_HIT`, now refines past it.
  `SIZE_UNUSUALLY_SMALL` still fires below 5 nm, and its message now says that below about 2 nm a crystallite is a few unit cells and broadened Bragg peaks may not describe its pattern; the Debye scattering equation does.
  For comparison, TOPAS's `CS_L` limits size to 0.3-10 000 nm, GSAS-II clamps it to 0.001-10 µm, and FullProf sets no limit.
- Limits chosen on quantities that stay physical are gone (WP-2002, B9).
  A fit that stopped at one of them in 1.9.0, reported by `BOUND_HIT`, now goes past it.
  `Atom.occ` keeps its floor of 0 and loses its ceiling of 1.5, and `OCCUPANCY_ABOVE_ONE` (below) reports a refined value above 1.
  March-Dollase `r` keeps only a floor of 1e-6 against the pole at zero, where it was held to 0.15-6, so a pressed clay or mica plate can refine below 0.15.
  `Harmonic.weight` loses its ceiling of 0.5, and `HARMONIC_FRACTION` still warns past 15 %.
  `EmissionLine.weight` loses its ceiling of 2, and the presets' Kα2 weight its ceiling of 1.
  `axial_sl` and `axial_hl` lose their ceiling of 0.2 and keep their floor of 0. The peak-position corrections lose their default bounds too: `Instrument.zero_shift` its ±0.5°, `Geometry.sample_displacement` and the two capillary offsets their ±1 mm, and `Geometry.sample_transparency` its ceiling of 0.05 (it keeps its floor of 0). Where a scan cannot separate one of them from the cell, the fit reports `FLAT_DIRECTION` and the cell's esd shows the spread. On 11-BM NAC with zero and both capillary offsets freed, the cell now lands 5109 ppm from its reference with an esd of 2579 ppm, where the bound had stopped it at 1097 ppm with an esd of 2612 ppm. A project file that stored the old bounds keeps them.
  The GSAS, GSAS-II, FullProf, `.prm`, `.instprm` and recipe readers no longer write the old ceilings either, so an `.instprm` or recipe stating SH/L above 0.4 now reads.
  A project, history or JSON file written before 1.10 stores its bounds and keeps them, since a stored bound is the caller's claim: nothing is migrated, and such a file refits as it did.

- A search that finds no lattice two engines agree on is **searched again by inlier count** (indexing C4), and says so with `INDEX_INLIER_RETRY`.
  On a list with measured intensities, the retry accepts a cell that indexes at least 60 % of the N driven lines (and n_dof + 4), the five strongest among them, where the first pass needs all but two; a list whose lines carry one intensity keeps the count of two.
  Off-lattice lines past two no longer leave a search with no cell, or with single-engine cells that explain them by having a line everywhere: on a synthetic Si pattern with twelve planted lines (53 usable), a cubic search found no cell within 1 % of the truth at a count of 2 or 3, and now ranks the truth first, found by all three engines.
  A run whose first pass found a lattice two engines agree on is unchanged, because the inlier rule changes the pool the panel ranks: on SRM 660c LaB6 it alone takes the certified cell from rank 1 to 3.
  `CellCandidate.n_search_unindexed` reports the driven lines a cell left, and `.unindexed_two_theta` the usable lines it left, in 2θ (schema 0.59), under every rule.
- With no shift declared or measured, a picked list's search window is sized by its own widths, the lower-quartile fitted FWHM, where it was a constant 0.05° 2θ (indexing C6).
  The 0.05° stays as a ceiling, so a lab pattern with lines 0.05° or wider is unchanged, and a position-only list keeps it.
  On a synthetic Si twin at λ 0.8257 Å (FWHM 0.021°) the allowance falls to 0.021°, the unshifted truth's cell moves from −228 ppm to −7 ppm, the √2·a₀ cubic I cell no longer reaches `medium`, and a 100 µm displacement the pair screen cannot name is still found.
  `INDEX_SHIFT_ALLOWANCE` still fires, since the shift itself is unmeasured, and its message names where the window came from.
  Both changes can alter a search's answer, so `INDEXING_THRESHOLDS_VERSION` is `1.11` for them.
- A picked line flagged `weak_line` no longer drives an indexing search (#934).
  It stays in `usable()` and is scored as before, so a cell may still explain it, but `search_line_order` leaves it out of the lines an accepted cell must index; below six unflagged lines the strongest flagged ones are driven again.
  On the synthetic Si pattern of issue #916 the driven set falls from 17 lines (18 under a tuned profile) to the 11 silicon lines: a cubic search with a declared `n_unindexed=2` returned no cell and ranks the truth first, and an all-systems search moves the truth from sixth to fourth (absent to fifth).
  No indexing-acceptance list drives a `weak_line` line, so none of their answers moves; this rides the 1.11 `INDEXING_THRESHOLDS_VERSION`.

- A joint fit with per-histogram phase paths now holds a pattern's own copy of a phase's cell where that pattern cannot see the phase (WP-1325).
  In 1.9.0 the cell stayed free in that pattern whenever another pattern still showed the phase, so it could wander with nothing to fit.
  A fit moves only where a phase is absent from some of its patterns and its cell is per-histogram, as under `SharingMap(per_histogram=["phases.*"])`.

- Indexing no longer keeps one lattice as two candidates when its two descriptions reduce either side of a Niggli boundary (WP-1932).
  Two candidates the χ² test calls distinct are now compared again across the reduction's boundaries, in Selling's form, and joined when a description of one passes the same χ² against the other.
  `same_lattice` and dedup's grouping answer this way; a pair the old test joined is answered exactly as before.
  Replaying every dedup call logged on the bethanechol benchmark, 574 of 178 875 groups go, and on the LaB6 acceptance searches the rank-6 tetragonal duplicate joins the rank-3 one.
  Dedup takes up to about twice its former time; on the benchmark that is a few per cent of a run.

### Files that change

- A CIF written for a phase that has a rigid body now carries two more atom-site columns, `_atom_site_refinement_flags_posn` and `_atom_site_calc_flag` (WP-1810).
  `G` marks an atom the body places, `R` a riding hydrogen, `.` a free atom; the calc flag is `calc` for a riding H and `d` otherwise.
  A phase without a body writes neither column, so its file is unchanged.
- A `.rex` project's stored plan now carries `phase_support_sigma` (WP-2002, B1), so a project saved here does not open in 1.9.0.
  `Capabilities.project_format_version` is 1.5.

### Requirements that rise

## New

- `BackgroundChoice` carries what `auto_background` chose and the scores it chose on (WP-2002, B12).
  For a P-spline: `amorphous_hump_score` against `hump_trigger`, which set the knot spacing `knot_step_deg`, and `air_scatter_gain` against `air_scatter_trigger`, which set `air_scatter`.
  For a Chebyshev: `selection`, the order scan with every order's BIC and Durbin-Watson d.
  `seed_level` is the start every coefficient took under `seed=True`.

- The absent-phase hold's threshold is a plan setting, `RefinementPlan.phase_support_sigma`, mirrored by `PlanSpec.phase_support_sigma` (WP-2002, B1).
  A stage holds the cell, positions, widths and displacements of a phase whose scale sits fewer than that many esds from zero, as it did at 3σ since WP-1523, and the default is still 3.
  `None` switches the hold off: no stage holds, releases or restores a phase, and no cell takes the window an unseen phase's cell gets.
  `PHASE_UNCONSTRAINED` reads the same number, and with the hold off it still reports a phase under 3σ and names what refined without signal.
  `Refinement.run_stage` takes it as a keyword, a project's stage verb passes its stored plan's, and the `.rxt` document writes it as a `support` line when it is not 3.
  A fit at the default is unchanged.

- `StageResult.collapsed` names the parameters a stage put back at their starting values and held after its first solve found them flat (WP-2002, B14).
  That happens to a phase whose scale the solve drove under `phase_support_sigma`, and to a moment direction that stopped moving the pattern.
  They were in `StageResult.held` in 1.9.0 too, beside the parameters held at stage start, with nothing to tell the two apart.
  `StageResult.seeded` now also lists the Stephens DOFs a `Stage.strain_seed` started, each at the value the seed wrote.
  Both are records only, and no fit's numbers change.

- `OCCUPANCY_ABOVE_ONE` (info) reports a refined occupancy above 1 with its distance in esds, now that `Atom.occ` has no ceiling (WP-2002, B9). It is an info record because counting noise alone puts a freely refined full site above 1 about half the time.
  It names the site, gives the value and its distance above 1 in esds, and changes nothing in the fit.
  The value is expected where a mixed site declared as its lighter species refines site scattering, such as Mg declared on an Fe-Mg site, which reads about 2.2 at full Fe.
  It judges only an occupancy the fit moved, so a held value does not fire it, and a full site refined freely can land just above 1 by counting noise.

- Each parameter row now carries its esd without the Bérar-Lelann factor, `RefinedParameter.stderr_uncorrected` (WP-2002, B4, schema 0.59).
  `stderr` is unchanged and still carries the factor, which corrects for neighbouring residuals that share a sign.
  `stderr_uncorrected` is the esd GSAS-II and FullProf print, so compare theirs with it.
  FullProf prints the factor as SCOR and leaves its own esds without it.
  The factor is 2.15 on the fluorapatite tutorial pattern and 8.07 on the 11-BM NAC example, so there `stderr` is two and eight times `stderr_uncorrected`.
  Single-pattern and joint fits write it, and a series carries its fits' rows.
  The estimation chapter now explains the factor and what GSAS-II, FullProf and TOPAS report, and the pages on switching from each program say which rietx number to compare.

- `rietx.examples.fetch(name)` downloads a data file the wheel does not carry, checks its sha256, and keeps it under `~/.rietx/data` (WP-1986).
  It knows two files, listed in `rietx.examples.REMOTE_FILES`: APS 11-BM's scan of NIST SRM 640c silicon in a Kapton capillary, and the same capillary scanned empty.
  The manual's guides on a measured blank and on a hump run on them.
  Without a network it raises `OSError` naming the path to save the file at by hand.

- A joint fit now tests each parametric declaration's form against its own data (WP-1325, schema 0.56).
  `RefinementResult.parametric_form` holds one `ParametricFormTest` per declaration: how much the fit would improve with the target free in each pattern, over the noise level, against the 95 % point for its degrees of freedom.
  It is a score test at the answer and needs no refit; on a 33-pattern real ramp it cost 0.7-0.8 s and gave a full refit's verdict on all five equations tried.
  `str(result)` prints the verdict after each declaration's coefficients, and `PARAMETRIC_FORM_REJECTED` (warning) names the coefficients of a rejected equation, whose esds assume the form.
  The test sees an equation only where a pattern measures its target, so an equation carried through patterns that cannot see a phase is not checked there.
  The verdict line counts the patterns tested against the subset (`ParametricFormTest.n_subset`) and gives the p-value (`ParametricFormReading.p_value`).
  With several equations, each is read twice: with the other equations tied (`ParametricFormTest.tied`) and with their targets freed (`ParametricFormTest.others_freed`).
  The freed reading is the verdict, because it does not assume the other equations' forms.
  The statistic is the χ² the alternative would remove over the answer's χ²_red.
  On equations that must hold any smooth truth, over three real ramps, it rejected 12 of 242 (5.0 %).
  Two equations whose targets change the pattern alike can each pass with the other freed while both are wrong, so `RefinementResult.parametric_form_joint` also reads every equation at once.
  When it rejects and no single equation does, `PARAMETRIC_FORM_REJECTED` names every tested equation's coefficients and says the data cannot tell which form is wrong.
  A verdict beside a rejected equation is marked provisional (`ParametricFormTest.provisional_on`), because the rejected equation has moved the answer every reading steps from.
- A joint fit's parameter rows now say which parametric equation set them (WP-1325, schema 0.59).
  `RefinedParameter.equations` names the declaration on each pattern's target row, on what follows the target there, and on each coefficient's `vars.` row, and is empty on every other row.
  A target row's value and esd are the equation's at that pattern's coordinates, so they can be far tighter than the pattern measures alone.
  `PARAMETRIC_TARGET_UNSEEN` (warning) names the patterns where an equation sets a target whose phase the pattern cannot see.
- A parametric equation can be evaluated at any coordinate, with its esd (WP-1325, schema 0.59).
  `RefinementResult.parametric_equations` holds each declaration as resolved, with its coefficients' covariance in the caller's units, and `result.parametric_value("a", {"T": 293.0})` returns a `ParametricValue`.
  At a pattern's own coordinates it reproduces that pattern's row; beyond the subset's range it names the coordinates it extrapolates in, and it carries the form test's verdict.
  It also says whether that verdict is provisional and whether the joint reading rejects the set, because the esd assumes the form either way.
- A notebook shows the pattern, fit, series and structure figures in the frontend's light or dark theme, and follows a theme switch without a rerun (WP-1970).
  A figure drawn light carries a dark copy as HTML beside its PNG, and what you add to the returned figure appears in both.
  JupyterLab, Notebook 7 and JupyterLite switch it; a frontend that strips the switch, such as GitHub's viewer, shows the light figure.
  A saved notebook stores about three times the image bytes per figure. `SeriesResult.plot` now takes `style="dark"` too.
- The indexing figures take `style="dark"` and follow a notebook's theme, as the pattern figures do (WP-1972).
  `plot_peak_list`, `plot_candidates`, `plot_validation` and `plot_indexing` each take it, and the light figures keep their colours.
- A phase can carry a spherical-harmonics texture, the preferred-orientation correction for a texture with no single axis (WP-1960, schema 0.57).
  `Phase.texture` declares an even order, and its coefficients refine from zero with exact analytic columns.
  The default driver keeps the pole density non-negative at every reflection, and `TEXTURE_NOT_POSITIVE` reports where it goes negative between them.
  `RefinementResult.texture` gives each textured phase's texture index J and the two minima of P.
  The `mccusker_structural` plan frees the coefficients beside March-Dollase's, and a phase declares one of the two.
  On the IUCr round-robin sample 2, the platy brucite's worst weighed-fraction error was 2.71 wt % at order 6, against 2.80 under March-Dollase.
- `to_structure` carries a GSAS-II project's spherical-harmonics texture, converted to this package's convention (WP-1960).
  Under `bragg_brentano` the carried texture gives GSAS-II's own multipliers to its single precision.
  `GSAS2_GPX_TEXTURE_NOT_CARRIED` says when it cannot: a Debye-Scherrer histogram, histograms that disagree, or terms GSAS-II 5.8.4 itself evaluates wrongly.
- A rigid body can declare riding hydrogens (WP-1810, schema 0.58).
  `RigidBody.riding` lists them, and `crystallography.riding.set_riding_lengths` puts each at its bond class's length from its parent, along the direction the template already has.
  The length depends on the radiation: SHELXL's riding defaults for X-ray data, and the neutron means of the *International Tables* Vol. C Table 9.5.1.1 for neutron data (X₂N–H 1.009 Å among them); a joint fit takes the neutron lengths.
  A result carrying a body with `riding` does not open in 1.9.0. A CIF read does not rebuild a body, so the flags are written but not read back into a body.

- `pick_peaks` now states a per-pattern false-discovery rate for its list (#934).
  Each fitted component's I/σ_I is tested by Benjamini–Hochberg at q = 0.01 over the pattern's resolution elements, and a component under that bar is flagged `weak_line`.
  The new info diagnostic `PEAK_EXPECTED_FALSE_LINES` gives the bar and, as its `value`, the expected number of noise lines among those kept.
  The flag is reported, not refused, so `usable()` does not change.
  On #728's synthetic silicon with a steep background it marks 24 of the 26 off-lattice usable components and no silicon line; over the 16 IUCr round-robin lab patterns it marks 13 of 789 usable components, several of them weak lines the true cell indexes.
  `INDEXING_THRESHOLDS_VERSION` moves to 1.10.

## Magnetic structures

- `solve_magnetic` charges each ΔBIC N/f² observations, where it charged the N fitted channels (WP-2002, B12; issue #270).
  f is the Bérar-Lelann factor of the restricted fit: the nuclear reference for a trial, the winner for the descent audit.
  Neighbouring channels of one peak share the sign of their misfit, so the raw count let any χ² gain outvote the parameter penalty.
  This is the count `compare_freed` already charged.
  Every ΔBIC shrinks, by about f², and the caveat that said the count was raw now gives N, the count charged and f.
  On the three real patterns in the tests the verdict is unchanged.
  On Cr₂WO₆ at 4 K (f 3.38) the winner 58.395 leads by 143 where it led by 1682, and 58.398 falls from +61 to −3, so it no longer counts as evidence.
  On LaMnO₃ at 50 K (f 3.22) Pn′ma′ leads by 164 where it led by 1704.
  Cr₂WO₆ at 150 K still has nothing to solve.
- Every ΔBIC tie in `solve_magnetic` abstains (WP-2002, B12 and the ruling of 2026-10-20).
  In 1.9.0 a magnetic-only R lower by more than 2 % chose the winner first; that margin was chosen and never measured.
  A tied class with fewer moment parameters also won, which counted a cost the ΔBIC already charges.
  The tied classes now come first in `trials`, fewest moment parameters first, and the reason gives each one's count and R_mag, neither of which ranks them.

- A moment angle the fit leaves out of its covariance, at a direction the site symmetry fixes, now carries its profile interval (WP-2002, B2, schema 0.59).
  In 1.9.0 such an angle had no esd and nothing in its place, so its value read as exact.
  After the last stage, a single-pattern fit runs `profile_interval` for each such angle and stores the answer on `RefinedParameter.interval`.
  The refits run on a copy of the models, so the history gains no node.
  `MOMENT_ANGLE_STATIONARY` now gives each angle's distance from the direction and says whether the interval includes it.
  Only a fit whose test passed pays: 20-32 refits an angle, 2.6-16.7 s on the two-site test fits of 0.2-1.2 s.
  A joint fit computes no interval, and nor do the trial fits `solve_magnetic` runs.
  Any profile interval of a moment angle (explicit or automatic) now stops a side half a turn from the value, with the new stop `"period"` and no end, since an angle repeats every 2π: a moment the data no longer saw had walked to ±1e12 rad over 120 refits an angle.

- `magnetic_supercell` now builds the children it refused because their group names no tabulated type in the child's axes, such as a C-centred type in a primitive doubled cell (WP-1419, schema 0.59).
  Such a child states its cell through its parent's: `Phase.parent_cell` holds the parent's group, the transform, the parent's cell and one strain per Γ lattice strain the child's group allows, and the child's six cell parameters are derived from them and locked.
  `phases.*.cell.*` then frees the parent's edges; a strain is freed only by name.
  `parent_cell=True` states every child this way, and `parent_cell=False` keeps the refusal; a child that built before builds exactly as before.
  On the shipped LaMnO₃, 5 of the 36 displacive children of Pnma now build.
  A phase carrying `parent_cell` does not open in 1.9.0.

- `analyse` splits a class of magnetic candidates that holds a proved separation (issue #565 part 5, the last of five).
  A class union-find joined can hold a pair one family is proved unable to reproduce: the join rests on a false sampled edge, or on a partial containment.
  Every pair the loop skipped as already joined, whose join the proofs have since undone, is now drawn; every sampled direction a proof contradicts is drawn once more; and what is still joined is split at the two irreps holding the proof, each dropped edge naming the proof that refuted it (`refuted_by`).
  `classes` is that split partition and the new `merged_classes` the union-find one; the table prints the dropped edges with their draw counts and which merged class each split class came from.
  On the `F m -3 m` Γ set at the general site the union-find answer was four classes with S8 and S9 inside S7 ∪ S10, and is now six, S8 and S9 apart on proofs.

- `determine_extinction_symbol(restrict=rx.ExtinctionPrior(sohncke=True))` declares facts about the specimen: chirality, centrosymmetry, polarity (#935).
  A powder pattern cannot separate the members of an extinction class, so the choice inside one is chemistry, and this is where it is declared.
  The prior filters each class's members and nothing else: every class is fitted and ranked on the data as before, `ExtinctionCandidate.excluded_groups` names what it removed, and `EXTINCTION_PRIOR_APPLIED` reports it.
  `best_or_none()` answers among the classes the prior leaves a member in, so a synthetic P 2₁ specimen declared enantiopure answers `P 1 21 1` with `P 2₁` alone.
  It abstains when the data prefer an emptied class decisively, so a P 2₁/c specimen declared enantiopure gets no chiral answer.
- `ExtinctionCandidate.laue_classes` groups a class's members by Laue class, and `LAUE_CLASS_NOT_SEPARABLE` says when the leading class spans more than one (#935).
  Such members differ only in which reflections are equivalent, never in a position or an absence, so a structure solution runs once per Laue class.
  These fields ride the 1.11 `INDEXING_THRESHOLDS_VERSION` already staged for 1.10.0.

## Changed

- The peak-width coefficients `u`, `v` and `y` lose their chosen floors (WP-2002, ruled 2026-10-23).
  Each now stops at the mirror image of its ceiling, −180² deg² or −180°, which no width reaches.
  The X-ray presets held `u` ≥ −0.05 and `v` ≥ −0.5, the neutron preset `u` ≥ −0.5 and `v` ≥ −4, and both held `y` ≥ 0.
  What must stay non-negative is the width.
  The default solver holds the Gaussian width as before, and now holds the Lorentzian width X/cosθ + Y·tanθ at or above zero at every reflection on the data.
  Under `solver="trf"`, `RESOLUTION_NOT_POSITIVE` now also reports a Lorentzian instrument width below zero.
  `w` and `x` keep their floors.
  Every preset builds one box, so `TCHZ_BOUNDS_COARSE` is gone, and `ProfileTCHZ.coarse` stays as the way to build the five widths from values.
  The `.prm`, `.instprm` and recipe readers now read a negative Y, and refuse one only where it takes the Lorentzian width below zero: over the fitted range for a recipe, below 180° 2θ for a calibration.
  A project, history or JSON file written before 1.10 stores its bounds and keeps them.
- `read_gsas_tof_iparm` fills `TOFSource.l1_m` on every bank from the file's `FPATH1` record, where 1.9.0 left it `None` and reported the record dropped (WP-2032).
  The GSAS manual does not list `FPATH1`; SNS files write it, so it is read as one number and a record holding anything else is refused naming the file.
- A GSAS file whose `TIME_MAP` record follows a bank's rows reads, where 1.9.0 refused it as a malformed data record of that bank (WP-2032).
  The manual lets the record sets come in any order.
- `load_instrument_profile`'s refusal of a profile holding a time-of-flight bank starts with the file's path (WP-2032).
- `Project.open` on a project that records no GSAS `bank` writes the bank it read into `data_ref.options`, so the next save records it (WP-2032).
- `IrrepModes.primary` is `False` for a component whose isotropy group is a supergroup of the child's, where 1.9.0 compared only operation counts and could read it as primary (#1002).
  `mode_amplitudes` rows carry the same flag, so they change the same way: a supergroup component's `ModeAmplitude.primary` now reads `False` where 1.9.0 read `True`.
- A figure a plot returns keeps its notebook size after a `set_xlim` or `set_ylim` of your own (WP-1971).
  In 1.9.0 the gutter labels and the statistics line were placed in data coordinates, and a zoom to a tenth of the x range made the notebook image 7.7 times wider.
  They now stay beside the axes, and a label your zoom leaves outside the axes is hidden.
- A figure a plot returns pickles, which raised `AttributeError` in 1.9.0 (WP-1971).
- The tutorial notebooks show one step of rietx a cell and link the manual for the reasons (WP-1545).
  Notebook 02's tie, hold and verdict moved to a new notebook, `02b_steering_a_refinement`.
  The checklists for supervising an agent left the notebooks.
- A refined parameter, a bond distance, a series trajectory and a phase's microstructure block each print as rows (WP-1545).
  The first two take one line, so a list of them reads as a table.
- `suggest`'s `summary` prints the predicted Δχ² to three significant figures and ΔBIC to one decimal, where 1.9.0 printed four significant figures of each (WP-2002).
  Where the fit stops moves both in the fourth figure.
  On the fluorapatite guide, starts 1e-14 apart put ΔBIC between −1.29940 and −1.29971, which printed as −1.299 or −1.3 depending on the start.
