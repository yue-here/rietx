# rietx 1.8.0

> **Staging file, not yet a release.** Opened 2026-10-08, the day 1.7.0 was
> cut, so that a break or a user-facing addition is recorded the day it lands
> (ROADMAP protocol rule 6). There is no `1.8.0` on PyPI and no `v1.8.0` tag
> until `RELEASING.md` is walked. The cut writes the framing, and checks this
> file against the tag range `v1.7.0..main`.

## Upgrading

Code written against 1.7.0 runs unaltered, but some fits land elsewhere.

### Numbers that move

- A stage that frees a peak width sitting at zero now starts it at a small value first: 1e-3° for a width in degrees, its square for a variance in deg², 1e-3 µm² for extinction.
  At zero the width had no slope, so the last bits of rounding chose where the fit ended, and two machines could disagree.
  Every fit that frees `instrument.profile.y` from its default can move, which is every preset's `profile` stage.
  On the 11-BM LaB₆ + cBN Le Bail pattern every pass came down about 3 points of Rwp.
- The finite-difference step for the Caglioti `u` and `v` is now sized by their unit, 1e-6 deg², instead of by 1 (WP-1936).
  On a sharp instrument the old step was a large part of the peak's own variance, and on 11-BM SRM 660c it put 8.8e-4 of error into `u`'s Jacobian column.
  Every fit that frees `u` or `v` can move.
  So can a fit that declares a width an identity parameter with a lower bound of 0, or ties a named variable to one.
  The 11-BM LaB₆ + cBN Le Bail run from cells 0.4 % long now depends on the platform at its fifth pass.
  It ends at Rwp 13.773 % on macOS arm64 and at 14.031 % on Linux x86-64, where both ended at 14.031 % before.
- `StageResult.seeded` lists what each stage lifted and the value it started from.
  `StageResult.floor_unseeded` lists a freed row left at zero because its unit has no seed size, and the fit reports `SOFTPLUS_FREED_AT_FLOOR`.
- A fit run with `solver="lm"` moves (WP-1937). Each step is now solved exactly inside the parameter bounds, so a parameter that ends on a bound sits on it.
  Its budget is now `max_iter × 4` residual evaluations, as the default driver's is, where it was `max_iter` outer iterations.
  A stage that starts at its minimum reports `converged`. It said `diverged`, and a series set such a pattern aside.
  The default driver is unchanged.
- `capabilities().schema_version` is `0.44`.
- The LaB₆ + cBN validation row holds the instrument's Gaussian widths, so its published QPA is 17.791 ± 0.319 wt %, no longer 17.874 ± 0.314.

### Files that change

A CIF written by `Structure.to_cif` or `Refinement.write_cif` states more, and
two of its items change name (WP-1319). Old CIFs, ours included, still read.

- Displacements are U (`_atom_site_U_iso_or_equiv`, `Uiso`/`Uani`), no longer B.
  The GSAS-II phase CIF keeps B, which is what GSAS-II's importer reads.
- The space group is `_space_group_name_H-M_alt` (the resolved setting) with
  the Hall symbol, IT number, crystal system and the full operation loop. The
  deprecated `_symmetry_space_group_name_H-M` is no longer written, except in
  the GSAS-II phase CIF.
- New: the CIF 1.1 magic line, `_audit_*` and `_audit_conform`, an
  `_atom_type` loop, site multiplicities, the formula, Z, Mr, the calculated
  density and the cell volume.
- A number without an esd is written as the shortest text that reads back as
  the same double, where it was four or six decimals. A β of 90.00004 and an
  occupancy of 0.33333 now survive a round trip.

A script that reads those two old tags out of a file this build wrote needs
the new ones.

The refinement CIF's pattern block is rewritten (WP-1933). `read_pdcif` reads
both the old and the new form.

- The profile loop holds every measured point, where it held the fitted ones.
  `_pd_proc_ls_weight` is 0 on each point the fit did not use, and
  `_pd_proc_info_excluded_regions` names the stretches.
- The grid is `_pd_meas_2theta_scan`, no longer `_pd_proc_2theta_corrected`,
  since nothing corrects it. The intensities are `_pd_meas_counts_total`, or
  `_pd_meas_intensity_total` with the file's σ in parentheses, no longer
  `_pd_proc_intensity_total`. The undefined `_pd_proc_intensity_total_su`
  column is gone; the fit's σ is in the weights.
- New: `_pd_proc_d_spacing`, the measured and fitted ranges and point counts,
  a wavelength loop with every emission line's weight, the probe, the method,
  the instrument geometry, the restraint count, `_refine_ls_shift/su_max`, the
  absorption correction, extinction on the phase's block, f′ and f″ in the
  `_atom_type` loop, a `_refln` loop, `_cell_volume` with its esd, and
  publication flags and `_geom_special_details` on the geometry loops.
- The profile and background functions are text with an esd on every value,
  in lines of at most 80 characters. The profile text names the shape the fit
  computed. Before, it said TCHZ for a Voigt fit.
- A geometry row whose symmetry code cannot be written is left out and
  counted, where it was written with `?`.

A script that reads the old pattern tags out of a file this build wrote needs
the new ones.

### Requirements that rise

- rietx needs spglib 2.8 or later, where it accepted 2.4.
  spglib 2.8.0 corrects three magnetic space groups (UNI 282-284) that 2.7.0 could not identify from their own operators.
  Every one of the 1651 groups now round-trips.
  Some magnetic candidates that came back unnamed now carry a BNS number.
- `operators.UNI_NOT_IDENTIFIABLE` is gone, since no entry fails to match itself any more.

### The compiled kernels are a wheel

- rietx depends on `rietx-kernels`, its compiled model kernels in Rust, and no longer on numba.
  A fresh install's packages take 182 MB, where 1.7.0's took 321 MB, and its first fit compiles nothing.
  numba held numpy below 2.6, and that ceiling is gone.
- An Intel Mac can install rietx again.
  numba has shipped no macOS x86_64 wheel since 0.63, which was rietx's floor.
- `rietx-kernels` has wheels for Linux x86_64 and aarch64, macOS arm64 and x86_64, and Windows x64, on Python 3.11 or later.
  It has no source distribution, so pip refuses to install rietx anywhere else, such as on musllinux or a free-threaded 3.13t or 3.14t.
  numba had wheels for the free-threaded builds.
- Nothing writes `~/.rietx/numba-cache` any more, and it can be deleted.
- The dichotomy indexing engine and the structure figure run on numpy alone.
  An indexing search on a real pattern takes 3-9 % longer.
  A structure figure renders 5-26× slower, and the larger the image the larger the factor.
  `view="auto"` is 14-40× slower.
  On the NAC cell at 400 px, `view="auto"` takes 1.3 s, where it took 92 ms.
  The rasteriser's port into `rietx-kernels` is that package's next release (WP-1940).

### Refusals that are new

The CIF writers refuse, by name and before any file is written, a non-finite
number and whitespace in a label, a species or a disorder group. Each wrote a
file no CIF reader could parse. Two phases whose names collapse to one block
name (`ph 1`, `ph-1`) used to raise gemmi's bare `RuntimeError`, and now get
distinct blocks.

## New

- `read_gsas_prm(..., profile_set=N)` reads one of several profile functions a bank offers side by side, as `PRCF1`, `PRCF2` and so on.
  Without it set 1 is read, as GSAS-II reads it, and a file offering more than one reports `GSAS_PRM_PROFILE_SET_DEFAULTED`.
  A refused set 1 names any type-3 set the file states. GSAS-II's `BT1_Cu311.inst` offers types 1, 2 and 3, and its refusal now names set 3.

- `RefinementResult.cell_volumes`: each phase's cell volume with its esd
  through the cell covariance, in every mode (WP-1933).
- `write_refinement_cif(pattern=)` writes every measured point;
  `Refinement.write_cif` passes the pattern the fit was given.
- `ReflectionRow.phase_index`, a phase link that holds where two phases share a
  name.
- `read_pdcif` reads an su written in parentheses on the intensities.
- `capabilities().compiled_kernels_unavailable` says why the compiled kernels did not load here, and is `None` when they did.

## CIF files checked against checkCIF

A structure-only CIF from `Structure.to_cif` now reports the same volume,
symmetry, formula, Mr, density and Z that IUCr checkCIF computes. Before, it
reported none of them, and checkCIF skipped its consistency tests for want of
the operation loop. Its remaining alerts ask for single-crystal and instrument
items a powder structure does not have (WP-1319, issue #756).

On a refinement CIF from `Refinement.write_cif`, the alerts for the
shift/su, for lines over 80 characters and for a volume without its esd are
gone, and f′ and f″ are stated (WP-1933). Its A alerts on the FAP and NAC test
files are the same single-crystal and instrument items.

## Changed

- An install whose compiled kernels do not load warns once, says why, and runs the numpy path.
  Before, it ran the numpy path in silence.
  `RIETX_COMPILED=0` chooses the numpy path and silences the warning.
- A result's stage summary says `(10 evals, …)` where it said `(10 it, …)`.
  `StageResult.n_iterations` has always counted residual evaluations, and the manual now says so.
- The matplotlib floor drops from 3.10.5 to 3.10 on Python 3.11 to 3.13.
  Python 3.14 keeps 3.10.5, the first release with wheels for it.
  Google Colab preinstalls matplotlib 3.10.0 and imports it at startup.
  Under the old floor, `%pip install rietx` upgraded it and Colab asked for a
  runtime restart before the tutorial's next cell.
