- **A choice outside its set is refused at the call, and some refusals changed
  type or wording.** A misspelt `mode` (`refine`, `Refinement.fit`, `run_stage`,
  `parameters`, `suggest`, `SequentialRefinement.fit`, `Project.create`) raises
  `ValueError` before any work, naming the choices: `unknown mode 'lebial';
  mode takes 'rietveld', 'lebail' or 'pawley'; did you mean 'lebail'?`.
  Before, it ran most of a fit and raised a pydantic error about an internal
  schema, and `Refinement.parameters(mode=...)` answered without a word. An
  unknown `backend` raises `ValueError`, where it raised `NotImplementedError`.
  `RefinementTree.best(metric=...)` refuses a name that is not a numeric
  `Statistics` field; it used to say that no node carried statistics.
  `auto_background(kind=...)`, `index_pattern(preset=..., engines=...)`,
  `merge(prefer=...)` and `solve_magnetic(nuclear_group=...)` refuse before any
  work. Code matching the old message text (`refit must be one of`,
  `unknown search preset`, `unknown background kind`) needs the new form
  (WP-2302).
- **`two_theta_range` is `two_theta_limits` wherever it requests a window**:
  `pick_peaks`, `fit_peaks`, `rx.viz.plot_result`, `rx.viz.plot_pattern`, and
  the `plot` methods that forward to them. The old keyword raises `TypeError`.
  A field that describes a span keeps the name `two_theta_range`
  (`DataRef.two_theta_range`, `ExtinctionScreen.two_theta_range`,
  `SuggestedAction.two_theta_range`) (WP-2302).
