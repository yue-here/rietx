- **A `SeriesResult` refuses two patterns under one name** (#1395's review). A series diagnostic names its pattern in `where` by the pattern's label, or its index where the label is empty, and the GUI's trace finds the pattern by that name, so two patterns sharing one could put a mark on the wrong point.
  Building or loading a series whose entries and failures give two patterns one name now raises `ValueError`, naming both.
  A run never writes one: `rietx.sequential.unique_labels` now keeps a suffix it makes off a name already given (`["a", "a", "a_1"]` is `["a", "a_1", "a_1_2"]`, where 1.12 made two `a_1`), and an empty label passed to `labels=` is named as an unlabelled pattern is (`p000`), where 1.12 kept it empty and its diagnostics fell back to the index.
