# rietx 1.12.0

This release carries everything that reached `main` in the fourteen days after 1.11.0, 150 merged pull requests.
Six changes are the largest.
Extinction is declared per phase, so `mccusker_structural` frees it only where a phase asks for it.
A Le Bail stage repeats its partition until the intensities settle, where 1.11.0 stopped after three cycles, so every Le Bail fit's numbers can move.
A point whose file esd is zero or negative takes no weight, where 1.11.0 gave it about a million times its neighbours' weight.
A formula can now set a parameter: `tie(path, expression=...)` in one fit, and a parametric equation with an `"expression"` basis in a joint fit.
A joint fit runs in Pawley mode, so a cell series needs no structure.
And the GUI has a new layout, a start screen, a File menu, and a recovery copy that keeps unapplied edits through a close or a crash.

Everything that changes what 1.11.0 code gets back is in [Upgrading](#upgrading).
1.11.0 refuses a structure, a refinement result or a project that this release writes ([Files that change](#files-that-change)).

## Install

```sh
pip install --upgrade rietx
```

## Upgrading

Code written against 1.11.0 runs unaltered, with the exceptions in this list.

### Code to check

- `capabilities().schema_version` is `0.61`, where 1.11.0's was `0.60`.
  0.61 makes `Phase.extinction` optional (WP-1944) and adds `Phase.parent_cell` (WP-1419).
  It adds `IndexingControls.formula` and `IndexingControls.temperature` (WP-2030), and `ExtinctionCandidate.tested_hkl` and `ExtinctionCandidate.tested_two_theta` (WP-2076).
  It adds the `"expression"` basis and `expression` field to `ParametricEquation`, makes its `target` optional, and removes `Parameter.expr` (WP-1964).
  It adds `TieSpec.expression` (WP-2118), `StageSpec.turn_off` and `StageResult.fixed` (WP-2208), and `StageSpec.lebail_tol`, `StageResult.lebail_cycles_run` and `StageResult.lebail_settled` (WP-1542).
  It adds `RefinementResult.sigma_rule`, `HistogramResult.sigma_rule` and `PatternData.nonpositive_sigma` (WP-1952).
  [Files that change](#files-that-change) says which documents open where.

- **`Parameter.expr` is gone** (WP-1964). It only ever held `None`, and any other value raised.
  `Parameter(..., expr=None)` still constructs, and a stored `"expr": null` still reads.
  Code that reads `param.expr` raises `AttributeError`.
  A formula is now a joint fit's `ParametricEquation(basis="expression")`, or a tie's `expression=`.

- **Extinction is opt-in per phase** (WP-1944, #1391, issue #877). `Phase.extinction`
  now defaults to `None`, so code that reads `phase.extinction.value` on a phase
  that never declared it raises. On such a phase, `set_vary` and `set_values`
  naming `phases.N.extinction` raise `ValueError` for an unknown path. A custom
  plan's `phases.*.extinction` glob frees nothing there, and no code says so.
  `phase.extinction = 0.0` declares it, and `mccusker_structural` then frees it
  after the displacement parameters. The CIF, TOPAS and FullProf writers write
  no extinction for a phase that declares none.

- **`Refinement.edit(structure=…)` can refuse a change to the restraints made beside an atom reorder** (WP-2121).
  A restraint the structure held at the same place in its list is carried onto its atoms.
  One appended after them is read in the new numbering.
  A restraint changed in the same edit that renumbers its atoms could mean either atom list, so the edit raises `ValueError`.
  Deleting a restraint in that edit counts as changing every one after it.
  Code that renumbered restraints by hand to work around 1.11's defect meets this refusal.
  Make the atom change alone, then change the restraints.

- **A stage that frees two of a rigid body's three turn directions raises** (WP-1805, #1388).
  `RIGID_BODY_PARTIAL_TURN` is refused at the stage's start, so a stage that ran in 1.11.0 with a hold, a tie or a `set_vary` glob leaving exactly two directions free now raises.
  Free none, one, or all three directions of a body's turn. No preset and no importer frees part of a turn.
  The profile interval of one rotation parameter of a three-direction body returned an interval in 1.11.0 and now has no ends (issue #1390 item 4).

- **A joint fit's per-pattern starting structures must be one model** (WP-1325, #1497).
  Starts that differ in a field that is not a parameter now raise, where that field shapes a shared parameter.
  The fields are a texture axis, a declared extinction or Stephens block, restraints and a rigid body.
  Under a per-histogram texture, different axes are accepted.
  A phase's `name` and `particle_radius_um` may always differ.

### Numbers that move

- **`mccusker_structural` frees no extinction unless a phase declares it**
  (#1391). Over 69 structural-plan fits in the test suite, 1 freed value in 98
  passed 3σ, and that one was a false positive on synthetic data. Where the
  coefficient had sat at 0, nothing moves and a `FLOOR_HIT` warning about it
  disappears. Where it had left 0, the phase scale moves by up to 2.8 esd and
  Biso by up to 1.7 esd. The QPA guide's weak CaF₂ phase reads 1.34 ± 0.11 wt %
  where it read 3.58 ± 3.53 wt %.

- **A Le Bail stage repeats its partition until the intensities settle** (WP-1542, #1434).
  It stops when one cycle moves less than 1e-7 of the Bragg counts, under a cap of 25 000 cycles.
  1.11.0 ran three cycles, so every Le Bail fit's numbers can move.
  FAP's Rwp goes from 10.237 % to 10.108 %, and its largest move in a parameter other than the background is 0.783 esd.
  11-BM NAC keeps its Rwp of 14.358 %, and moves by 0.004 esd.
  Corundum's Rwp rises by 0.019 points.
  A pattern with heavy overlap is slower.
  BT-1 LaMnO₃ took 63-83 s on a loaded machine, where it took 0.44 s, and its cell `b` moves by 12.8 esd.
  `Stage(..., lebail_cycles=3, lebail_tol=0.0)` reproduces 1.11.0 bit for bit, and an old history node replays its three cycles.

- **A point whose file esd is zero or negative takes no weight** (WP-1952, #1541, issue #1448).
  1.11.0 floored such an esd at a thousandth of the column's median.
  That gave the point about a million times its neighbours' weight, and nothing said so.
  A fit moves wherever a file carries such a point.
  On a synthetic LaB6 pattern with one σ = 0 at the strongest channel, 1.11.0 stopped at its iteration limit with the cell 1.75e-3 Å from the truth.
  1.12 converges to within 2e-4 Å.
  [Changed](#changed) says what the readers do with such a point.

- **Assigning a `Parameter` to a schema field gives it the field's declared range and unit** (WP-2088, #1458).
  Passing one to the constructor already did so (issue #204).
  In 1.11.0, `phase.lor_size = Parameter(value=0.01, vary=True)` left the width unbounded below and without a unit, so a free width could walk out of its physical range.
  The same assignment also replaced the model's other `Parameter` objects.
  So an object held beforehand, such as `g = phase.gauss_size`, was no longer the model's, and `g.vary = True` freed nothing.
  A fit whose model was built by assignment can give a different answer.
  A stored document that holds an unbounded range keeps it.

- **`result.microstructure` reads a width on its floor as no broadening under either solver** (WP-1914, #1506).
  Under `solver="trf"` a width driven to zero stores a tiny positive value, and 1.11.0 read it as a real domain size.
  On notebook 04's CeO₂ pattern, which has no Gaussian broadening, `gauss_size` stored 3.4e-24 deg² and read as 4.3e13 Å.
  It now reads `at_zero`.
  The default LM solver already stored 0.0, and its readings do not change.

- **A joint fit's parametric form test runs at the answer** (WP-2104, #1547).
  The test (the lack-of-fit check on an equation's form) used the parameter vector the last stage started from.
  The equation guide's two quoted statistics move from 9.3 to 9.4 and from 501.5 to 504.2, and both verdicts stand.

- `check_rigid_bodies` keeps a body's riding hydrogens riding in its released refit (WP-1989 part 1, #1008), so on a body with riding H `chi2_released`, `n_added`, `p_value`, `delta_bic`, `deviations` and `fires` can move.
  Each riding H is tied to its parent and no bond or angle with one in it is restrained, so the refit adds 3 parameters per other atom less the body's own.
  `n_added` is 36 on acridine form IX's 14 heavy atoms and 9 H, where 1.11.0 freed the H too and added 63.
  On the deposited pattern (COD 2242872) with C2–C3 stretched 0.3 Å, as #1008 measured it, ΔBIC is +20.8 at N/f², where it was −137 with the H freed, and Hamilton's p is 4.8e-37.
  The deposited body gives −233.
  A body with no riding H refits as before.

- **The extinction screen compares Pawley fits, where 1.11.0 compared Le Bail fits** (WP-2076, #1460, #1461).
  It scores each class on the forbidden lines that class can test.
  On 318 of 1082 synthetic rows at a correct cell, the old comparison named a class that excluded the true group, and nothing fired.
  Corundum over 20-90° returns `R - c -` at ΔBIC −45.9, where it was −3435.
  FAP now abstains, with `P 63 - -` leading on one testable line at 68.0°.
  NAC still returns `I - - -`.
  PbSO₄ returns `P c - a`, where the specimen is `P c - n`.

### Files that change

Measured both ways on a fluorapatite fit, with 1.11.0 installed from PyPI.

- **1.11.0 refuses a structure, a refinement result or a project that 1.12 writes.**
  A structure carries `parent_cell` and, on a phase that declares no extinction, `extinction: null`.
  A result carries `sigma_rule`, and each stage's `fixed`, `lebail_cycles_run` and `lebail_settled`.
  A project's `project.json` carries the indexing controls' `formula` and `temperature`, as null when unset.
  `capabilities().project_format_version` is `1.6`, where 1.11.0's was `1.5` (WP-2030).
  An instrument written by 1.12 opens in 1.11.0.
- **1.12 opens what 1.11.0 wrote.** A stored extinction value opens unchanged, as a declaration.
  So `mccusker_structural` still frees extinction on a 1.11.0 project's phases, as it did there.
  A 1.11.0 project opens with no formula.
- A parameter 1.12 saves carries no `expr` key (WP-1964).

- rietx needs `rietx-kernels` 1.5 or later, where it accepted 1.3, and pip upgrades it with rietx (WP-1997, WP-1548, #1554, #1557).

## New

- **A formula sets a parameter** (WP-2118, #1456).
  `Refinement.tie(path, expression="...")` sets one parameter by a formula over named variables (`vars.<name>`, from `add_variable`) and constants.
  The grammar is the manual's `reference/expressions.md`, version `capabilities().expression_grammar_version`.
  Trigonometric functions take radians.
  The Jacobian takes the formula's exact derivative.
  A formula tie checks out, replays, shows in the `.rxt` tie row and reaches a series through `constrain=`.
  The TOPAS writer refuses one by name.

- **A joint fit takes a formula as a parametric equation** (WP-1964): `ParametricEquation(basis="expression", expression="zero_a + grad/(exp(theta/T) - 1)")`, over `refine_multi(variables={...})` and the coordinate columns.
  An equation with `target=None` is an intermediate a later formula names, such as a temperature calibration.
  A variable named in `SharingMap.per_histogram` is one free number per pattern, such as a temperature offset.
  `MultiHistogramRefinement.preview_equations()` evaluates every equation at the start, before a fit.

- **A joint fit runs in Pawley mode** (WP-2104, #1547): `refine_multi(..., mode="pawley")` and `MultiHistogramRefinement.fit(mode="pawley")`.
  Each pattern keeps its own per-reflection intensities.
  The cell, zero, profile and a parametric equation's coefficients are fitted once across all patterns, so a cell series needs no structure.
  The mode refuses a fit that shares nothing, and a parametric equation on a force-fixed target such as `biso`.
  A Pawley joint fit gives no phase fractions.

- **A plan stage can fix parameters as well as free them** (WP-2208, #1520).
  `Stage(..., turn_off=[...])` in python, `stage NAME free ... fix ...` in the `.rxt` document, and a Fixes row on the GUI's Plan tab.
  A stage frees its `turn_on`, then fixes its `turn_off`, and the closing stage keeps them fixed.
  `StageResult.fixed` names the free paths a fix took.
  A series whose plan fixes is refit stage by stage, so its warm fits cost more iterations.

- **A Le Bail stage reports how its partition settled** (WP-1542, #1434).
  `Stage.lebail_cycles` defaults to 25 000 and `Stage.lebail_tol` to 1e-7.
  `StageResult.lebail_cycles_run` lists the cycles each partition ran, and `StageResult.lebail_settled` says whether every partition met the tolerance.
  A partition cut at its cap in the last stage warns `LEBAIL_CYCLES_AT_CAP`.

- **Every result says which σ it weighted by** (WP-1952, #1541).
  `RefinementResult.sigma_rule` and `HistogramResult.sigma_rule` are a `SigmaRule` of three counts: the fitted points weighted by the file's σ, those weighted by the Poisson σ, and those left out.
  `read_pattern(..., nonpositive_sigma="poisson")` keeps a point with σ ≤ 0 in the fit at σ = √max(y, 1).

- **`render_structure` takes three optional cues** (WP-1548, #1554).
  `depth_cue=True` fades each surface toward the background with depth.
  `planar_rings=True` (or a colour) fills each five- or six-membered ring of drawn bonds whose atoms lie within 0.1 Å of their mean plane.
  `faces=[mask, (mask, "#rrggbb")]` fills the atoms a `cut` mask selects.
  The GUI's structure drawer has the first two as the "depth cue" and "fill planar rings" boxes.

- **The GUI window has a new layout** (WP-2123, WP-2126, WP-2127, #1476, #1483, #1484).
  Graphs sit on the left in tabs and the panels on the right, and either side collapses.
  One action bar holds the refine choice (`One cycle` or `Staged plan`), the count of pending edits, Revert, Apply and `Refine`.
  The header's Run button, the Parameters footer and the `Split | Full` switch are gone.
  Below 760 px the window is one column.
  The Parameters tab groups each phase into a band, folds symmetry-held cell rows into one line, and holds a parameter by its padlock.
  The Plan tab reads as a recipe, with stages you drag to reorder and plan edits that wait in the action bar.
  The manual's GUI chapters show the new window.

- **The GUI has new tabs and dialogs** (WP-2125, WP-2128, WP-2129, WP-2131, WP-2133, #1479, #1487, #1488, #1498, #1502).
  The Interactive tab previews the pattern at values nobody has applied, and so do the Pattern and Single peaks previews.
  The Background tab draws the background with its covariance band and holds each term.
  With no project open, `rietx gui` shows a start screen and a New project dialog, and a bare launch reopens the last project.
  A File menu on the project name copies, renames, moves and closes the project.
  The header's `Open…` button is gone.

- **A rebuilt GUI opens beside today's, unfinished** (WP-2215, WP-2216, WP-2218, #1534 to #1538, #1673).
  `rietx gui --new` opens the browser at `/next`.
  Every `rietx gui` session serves both pages, and `/` does not change.
  The two pages share one session, so a project open in one is open in the other.
  Today `/next` has the start screen, New project, the File menu, Settings, a command palette and keyboard shortcuts.
  Its Pattern graph draws the fit with a hover readout.
  The Parameters tab edits values, with menus on a phase (rename, change space group, add an atom) and on an atom.
  The Interactive tab moves the model by hand, and the Pattern graph draws the preview beside the last fit.
  The action bar applies the edits and refines, and unapplied edits come back through the recovery copy.
  The Peaks, Background and Structure graphs and the Plan and Text tabs read "Not built yet", and the History tab is empty.
  The manual does not document `/next` yet, and its pages describe the window at `/`.

- **The GUI keeps unapplied edits in a recovery copy** (WP-2209, WP-2213, #1523, #1633).
  The copy sits in the GUI's state directory, written half a second after each change and before the project closes.
  It covers the action bar's edits, the Text document as typed and the Model panel's forms.
  Closing the project, opening another, closing the tab or stopping the server keeps them, and reopening offers them.
  Opening another project no longer carries pending values into it.
  In 1.11.0 the next Apply sent them to the new project.

- The GUI's indexing form takes the specimen's formula and the pattern's temperature beside the volume limits, and the project stores them as `IndexingControls.formula` and `IndexingControls.temperature` (WP-2030, #1121).
  A run with a formula adds a `Z` column to the candidate table, each candidate's `formula_units`.
  A project file or the form refuses a bad formula or temperature in the words `rietx index` uses, from one function, `rietx.crystallography.atomic_volume.check_formula_input`.

- `Refinement.released_arm(body)` builds the released refit `check_rigid_bodies` compares a body with, as a `ReleasedArm` (WP-1989 part 1, #1008).
  It holds the structure with the body removed and the restraints added, the free globs, and each riding H's tie to its parent.
  The check fits this arm, so a refit built from it by hand gives the check's χ².
  `freed=` frees other members, and `freed=body.atoms` gives the arm 1.11.0 fitted.

- **A diagnostic names the panel that shows it** (WP-1133, #1676).
  `Diagnostic.view` returns a panel of `rietx.viz.plot_for_vlm`, such as `"plot_for_vlm.residual"`, or `None`.
  Three codes name one: `MODEL_FAR_FROM_DATA` the overview, and `LOW_ANGLE_UNMODELLED` and `AIR_SCATTER_UNDECLARED` the Δ/σ panel.
  In a notebook a `see:` line under the diagnostic names the panel, and `str(diagnostic)` does not change.

## Magnetic structures

- `magnetic_supercell` now builds the children it refused because their group names no tabulated type in the child's axes, such as a C-centred type in a primitive doubled cell (WP-1419, schema 0.61).
  Such a child states its cell through its parent's.
  `Phase.parent_cell` holds the parent's group, the transform, the parent's cell and one strain per Γ lattice strain the child's group allows.
  The child's six cell parameters are derived from them and locked.
  `phases.*.cell.*` then frees the parent's edges, and a strain is freed only by name.
  A stage that frees the edges while a strain stays held reports the info diagnostic `PARENT_STRAIN_HELD`.
  A bound stated on the parent's cell carries over to the child, and the cell safeguards (`CELL_RUNAWAY`, the minimum length, the support window) read the parent's edges.
  A freed strain is bounded where the child's metric stays positive definite.
  `parent_cell=True` states every child this way, and `parent_cell=False` keeps the refusal.
  A child that built before builds exactly as before.
  On the shipped LaMnO₃, 5 of the 36 displacive children of Pnma now build.
  The TOPAS, GSAS, GSAS-II and FullProf writers refuse such a phase by name, since none of those formats states a cell through a parent.
  `phase.model_copy(update={'parent_cell': None})` writes the derived cell as it stands.

- **A site flagged `MOMENT_ANGLE_STATIONARY` carries a 95 % profile interval on its moment's size** (WP-2060, #1459).
  `RefinedParameter.interval` is filled for the modulus row as well as the angles, and the row keeps its `stderr`.
  A modulus whose refits find a χ² a whole cut or more below the fit has no interval.
  Its diagnostic then gives the lowest point and says to refit from it.
  The magnetic guide's example reads 3.47 to 3.65 μ_B, beside 3.56 ± 0.04.

## Changed

- **A restraint follows its atoms through `Refinement.edit(structure=…)`** (WP-2121).
  A restraint names atoms by position, so an edit that swapped two atoms left a bond restraint on two other atoms.
  The next fit pulled those atoms toward the old target, and nothing said so.
  Each restraint the new structure carried over now names the same atoms, as holds and ties already did.
  One whose atom was removed is dropped, and a warning names it.
  A series `prepare` hook that removes or reorders atoms gets the same.
  An edit is refused when a restraint, a rigid body or a distortion-mode record names an atom the new structure lacks.
  Such an edit was accepted before, and the next fit raised.
  A distortion-mode record's rows follow their atoms when the atoms are only reordered.

- **A tied parameter's own limits hold inside the LM step** (WP-1325, #1497).
  A parametric equation or a tie could want its target past the target's limits.
  1.11.0 then converged and raised `ValueError` at write-back, so no result came out.
  The target now sits on its limit and the fit converges.
  `CONSTRAINT_ACTIVE` names the equation, and `FLOOR_HIT` or `BOUND_HIT` names the pattern's path.
  Under `solver="trf"`, and for an `"expression"` equation, the fit finishes with the new `PARAMETRIC_OUT_OF_RANGE`.

- **A joint fit takes a `PlanSpec`** (WP-2102, #1413).
  `refine_multi` and `MultiHistogramRefinement.fit` raised `AttributeError` on one in 1.11.0.
  A Le Bail report built with a preset name now reads the plan the fit ran.
  So `report(plan="mccusker_default")` on a Le Bail fit no longer marks `refine_scale` as already refined.

- **The readers' handling of σ ≤ 0** (WP-1952, #1541).
  A point whose file σ is zero or negative stays in the pattern, leaves the fit, and the reader warns with the new `PATTERN_SIGMA_NONPOSITIVE`.
  A column with no positive esd is not read, and the Poisson σ applies.
  The `gsas` reader dropped σ ≤ 0 channels without a word, and `xy` and `chi` declined such a column without a word.
  All three now warn.

- **The `xy` reader says what it skips and refuses what it would misread** (WP-1952, #1504).
  A line between data rows that is not a row of numbers raises `PATTERN_ROWS_DROPPED`, where 1.11.0 dropped it silently.
  A comma inside a number (`10,02` or `1,234`) is refused by name.
  1.11.0 read a decimal-comma file at a 1° step as 2θ = 10, 11, 12 with intensity 0.
  A trailing `#` or `!` comment keeps its row, and `;` separates columns.

- A GSAS-I TOF `.iparm` whose `PRCF` profile set is written without its set number opens (#1503).
  1.11.0 refused the whole file and lost the bank's DIFC, DIFA and ZERO.
  The bank keeps its calibration and gets an all-zero `ProfileTOF`, with the warning `GSAS_IPARM_PROFILE_DECLINED`.

- A `.rasx` or `.brml` that Python's `zipfile` cannot read is refused with a `ValueError` naming the file (#1593).
  An archive whose version-needed field is past 6.3 raised `NotImplementedError` from `identify_format` and `read_pattern`.
  A member compressed with Deflate64, an encrypted member and a corrupt deflate or LZMA stream raised `NotImplementedError`, `RuntimeError`, `zlib.error` or `lzma.LZMAError` from `read_pattern`.

- **New warnings about restraints and rigid bodies** (WP-1814, WP-2144, #1510, #1562).
  `RESTRAINT_ON_FIXED_BODY_GEOMETRY` fires on a restraint whose atoms all sit in one copy of one rigid body, where no torsion the body declares changes it.
  No parameter can move such a row, and the row stays in the fit.
  `RESTRAINT_BODY_CONTACTS_UNCHECKED` fires when a fit turns a torsion inside a rigid body that carries anti-bump rows.
  The anti-bump rows skip pairs inside one copy of a body, and a torsion can fold two of them together.
  The warning names the body and each torsion's start and end angle.

- `EXTRA_PEAK_NO_INTENSITY` fires when the peak's area sits on its `FLOOR_HIT` finding, under either solver and in a joint fit (WP-2141, #1566).
  A stage stopped early under `solver="trf"` can leave a floored area near 2e-5, and 1.11.0 missed it.
  An area held on a positive lower bound no longer reads as having no intensity.

- An unknown parameter path that belongs to an opt-in correction the model has not declared names the line that declares it (WP-2087, #1515).
  The corrections are extinction, March-Dollase, spherical-harmonics texture, Stephens strain, anisotropic ADPs and Suortti and Pitschke roughness.
  1.11.0 offered the nearest real path, which named a different parameter.
  `STAGE_PATH_UNKNOWN` carries the line, and so does the `ValueError` from `set_vary` or `set_values`.

- The `means:` text of `BISO_NEGATIVE` and `BISO_UNUSUALLY_LARGE` names the usual causes: roughness, absorption and extinction (WP-2087, #1505).
  The manual's extinction page had the bias backwards, and now says an undeclared extinction lowers Biso.

- An attribute asked for under the other spelling of an esd names the field (WP-1913, #728 item 5).
  `RefinedParameter(...).esd` now raises "did you mean 'stderr'?", and `ParameterRow`'s `.stderr` names `esd`.
  Neither is an alias, and the attribute still raises.
- The refusal of a free coordinate on a fully fixed special position names every such site, where it named the first (WP-1913, #728 item 4).
  With one site the sentence does not change.
- `Refinement.fix_special_positions()` clears a rigid body's origin on a fully fixed special position too.
  It walked atoms only, returned `[]` and left the table refusing.

- **Indexing searches again when no two engines agree** (WP-2078, #1567).
  `index_pattern` then searches once more on the lines at or above 5 % of the strongest, the list of the 2004 indexing round robin.
  Its candidates replace the first list's only if it finds agreement.
  The info diagnostic `INDEX_WEAK_LINE_RETRY` says the retry ran, how many lines it set aside, and whose candidates the result holds.
  A declared `n_unindexed` forbids the retry.
  On a synthetic Mo pattern with a trace of MoO₃, the true cell moved from absent to rank 1.

- Two indexing messages were wrong on a short peak list (WP-2149, #1637).
  `INDEX_PANEL_REDUCED` states which systems have enough lines to determine a cell, where it listed all five.
  `INDEX_SYSTEMS_NOT_COVERED` separates the systems the list supports from those it does not, and gives the line count a cell needs.

- The extinction screen's class whose own fit raises stays unscored, and `best_or_none` abstains (WP-2076, #1461).
  1.11.0 counted the class as refuted.
  The diagnostic names the first error.
  `EXTINCTION_SYMBOL_AMBIGUOUS` names the tested positions where the two leading classes differ.

- The extinction screen counts atoms per cell from the formula's decimals as written (#1271 follow-up).
  1.11.0 took the count from floating point: `(Mg0.7Fe0.3)2SiO4` gave Fe 0.6000000000000001 per formula unit, so at Z = 10 an ordered screen found 6.000000000000001 per cell and called it not whole.
  The count is now exact and holds Fe 6, in the screen and in the "not counted" diagnostic line.

- The GUI's indexing routes reach a cell on real lab data (WP-2124, WP-2130, #1478, #1490).
  `POST /api/index/extinction` screens a candidate on a project with no phase, where it was refused with `NO_PHASES`.
  `POST /api/index/adopt` takes any candidate, where it refused all but the one `best_or_none()` picks with `ADOPT_GATED`.
  The Peaks panel offers Adopt on every row, and the gate's pick keeps its badge.
