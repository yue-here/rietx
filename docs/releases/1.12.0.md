## Upgrading

Code written against 1.11.0 runs unaltered, except where § Code to check says otherwise.

### Code to check

- `capabilities().schema_version` is `0.61`, where 1.11.0's was `0.60`.
  0.61 makes `Phase.extinction` optional (WP-1944) and adds `IndexingControls.formula` and `IndexingControls.temperature` (WP-2030).
  It also adds the `"expression"` basis to `ParametricEquation`, and removes `Parameter.expr` (WP-1964).
  [Files that change](#files-that-change) says which documents open where.

- **`Parameter.expr` is gone** (WP-1964). It only ever held `None`, and any other value raised.
  `Parameter(..., expr=None)` still constructs, and a stored `"expr": null` still reads.
  Code that reads `param.expr` raises `AttributeError`.
  A formula is now a joint fit's `ParametricEquation(basis="expression")`.

- **Extinction is opt-in per phase** (#1391, issue #877). `Phase.extinction`
  now defaults to `None`, so code that reads `phase.extinction.value` on a phase
  that never declared it raises. On such a phase, `set_vary` and `set_values`
  naming `phases.N.extinction` raise `ValueError` for an unknown path. A custom
  plan's `phases.*.extinction` glob frees nothing there, and no code says so.
  `phase.extinction = 0.0` declares it, and `mccusker_structural` then frees it
  after the displacement parameters.

### Numbers that move

- **`mccusker_structural` frees no extinction unless a phase declares it**
  (#1391). Over 69 structural-plan fits in the test suite, 1 freed value in 98
  passed 3σ, and that one was a false positive on synthetic data. Where the
  coefficient had sat at 0, nothing moves and a `FLOOR_HIT` warning about it
  disappears. Where it had left 0, the phase scale moves by up to 2.8 esd and
  Biso by up to 1.7 esd. The QPA guide's weak CaF₂ phase reads 1.34 ± 0.11 wt %
  where it read 3.58 ± 3.53 wt %.

### Files that change

- `capabilities().project_format_version` is `1.6`, where 1.11.0's was `1.5` (WP-2030).
  A project this release saves stores `formula` and `temperature` in its indexing controls, as null when unset, so 1.11.0 refuses any project 1.12.0 has saved.
  A 1.11.0 project opens here with no formula.

`Phase.extinction` is optional (schema 0.61, WP-1944), and a phase that declares none is saved with `extinction: null`.

- **1.11.0 opens less of what 1.12 writes.** It refuses that `null`, so a structure or a `.rex` project written by 1.12 does not open in 1.11.0.
  A project stops at "malformed history record".
  A Rietveld result and an instrument written by 1.12 do open there, measured on the NIST LaB6 fit.
- **1.12 opens what 1.11.0 wrote, and keeps the old plan behaviour.** A stored extinction value opens unchanged, as a declaration.
  So `mccusker_structural` still frees extinction on a 1.11.0 project's phases, as it did there.

A parameter 1.12 saves carries no `expr` key, which 1.11.0 reads as `None` (WP-1964).
A result whose joint fit declared a formula stores `basis: "expression"`, which 1.11.0 refuses.

### Requirements that rise

- rietx needs `rietx-kernels` 1.4 or later, where it accepted 1.3, and pip upgrades it with rietx (WP-1997).

## New

- The GUI's indexing form takes the specimen's formula and the pattern's temperature beside the volume limits, and the project stores them as `IndexingControls.formula` and `IndexingControls.temperature` (WP-2030, #1121).
  A run with a formula adds a `Z` column to the candidate table, each candidate's `formula_units`.
  A project file or the form refuses a bad formula or temperature in the words `rietx index` uses, from one function, `rietx.crystallography.atomic_volume.check_formula_input`.

- A joint fit takes a formula as a parametric equation (WP-1964): `ParametricEquation(basis="expression", expression="zero_a + grad/(exp(theta/T) - 1)")`, over `refine_multi(variables={...})` and the coordinate columns.
  An equation with `target=None` is an intermediate a later formula names, such as a temperature calibration.
  A variable named in `SharingMap.per_histogram` is one free number per pattern, such as a temperature offset.
  `MultiHistogramRefinement.preview_equations()` evaluates every equation at the start, before a fit.
  The grammar is the manual's `reference/expressions.md`, version `capabilities().expression_grammar_version`.

## Changed

- A FullProf `.pcr`'s `Nre` hard limits are applied as bounds where FullProf's manual maps them (WP-2058, the follow-up of #1199).
  1.11.0 read these limits and applied none (it reported `FULLPROF_LIMITS_NOT_APPLIED`), so the same file now builds a `Structure` with bounds it did not have, and a refit can land elsewhere.
  FullProf clamps a limited parameter in least squares, not only in simulated annealing (fp2k 8.20 on its own `ce1.pcr`, `docs/practice.md` § Limits a control file declares), so a file read without its limits fits a different model from the one its author ran.
  `to_structure` sets each limit as the `min` and `max` of the first value from the top of the file carrying its parameter number at multiplier +1, where that value is a cell entry rietx refines, a `Biso` or March `r` (FullProf manual p. 126).
  Every other limit is reported with its reason, one diagnostic per limit: `FULLPROF_LIMITS_NOT_APPLIED` (info), or the new `FULLPROF_BINDING_LIMIT_NOT_APPLIED` (warning) where the file's value sits on the limit or past it.
  A scale or an occupancy never maps, a coordinate or a moment refines through DOFs a bound cannot reach, and a limit reaching March `r`, Caglioti `W`, a cell length at 0 or a cell angle at 0° or 180° is not applied, and the message names why.
  `rietx.io.projects.fullprof.limit_readings(model)` says where each limit lands.
