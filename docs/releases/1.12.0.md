> cut, so that a break or a user-facing addition is recorded the day it lands
> (ROADMAP protocol rule 6). There is no `1.12.0` on PyPI and no `v1.12.0` tag

## Upgrading

Code written against 1.11.0 runs unaltered, except where § Code to check says otherwise.

### Code to check

- `capabilities().schema_version` is `0.61`, where 1.11.0's was `0.60`.
  0.61 makes `Phase.extinction` optional (WP-1944) and adds `IndexingControls.formula` and `IndexingControls.temperature` (WP-2030).
  It also adds the `"expression"` basis to `ParametricEquation`, and removes `Parameter.expr` (WP-1964).
  [Files that change](#files-that-change) says which documents open where.

- **`Parameter.expr` is gone** (WP-1964). It only ever held `None`, and any other value raised.
  `Parameter(..., expr=None)` still constructs, and a stored `"expr": null` still reads.
  Code that reads `param.expr` raises `AttributeError`.
  A formula is now a joint fit's `ParametricEquation(basis="expression")`.

- **Extinction is opt-in per phase** (#1391, issue #877). `Phase.extinction`
  now defaults to `None`, so code that reads `phase.extinction.value` on a phase
  that never declared it raises. On such a phase, `set_vary` and `set_values`
  naming `phases.N.extinction` raise `ValueError` for an unknown path. A custom
  plan's `phases.*.extinction` glob frees nothing there, and no code says so.
  `phase.extinction = 0.0` declares it, and `mccusker_structural` then frees it
  after the displacement parameters.

- **`Refinement.edit(structure=…)` can refuse a change to the restraints made beside an atom reorder** (WP-2121).
  A restraint the structure held at the same place in its list is carried onto its atoms.
  One appended after them is read in the new numbering.
  A restraint changed in the same edit that renumbers its atoms could mean either atom list, so the edit raises `ValueError`.
  Deleting a restraint in that edit counts as changing every one after it.
  Code that renumbered restraints by hand to work around 1.11's defect meets this refusal.
  Make the atom change alone, then change the restraints.

### Numbers that move

- **A fit that frees an FCJ axial ratio sitting on zero now returns a different
  answer.** A stage that newly frees S/L or H/L at exactly zero starts S/L at
  0.02 and H/L at 0.01 (a start that would equal the other ratio's value takes
  the other number), and records the rows in `StageResult.seeded`. Before, the
  column at zero was nearly zero and a Gauss-Newton fit could end `converged`
  on zero with an esd of order 1 (#1075; WP-1955). On #1075's repro under
  `lab_bragg_brentano`, S/L went from 0.00008 ± 1.29 (Rwp 0.0831) to
  0.04531 ± 0.00018 (Rwp 0.0630). The aperture columns themselves are exact
  now at one zero aperture, so an esd moves where it was read off them (55×
  narrower on the nonzero aperture of `test_e8`). Fits that start both ratios
  positive are unchanged to under 0.02 esd on LaB6, FAP and cpd-1a. In a joint
  fit the two histograms of one instrument may end on opposite orders of the
  pair, which the pair's symmetry allows.

- **`mccusker_structural` frees no extinction unless a phase declares it**
  (#1391). Over 69 structural-plan fits in the test suite, 1 freed value in 98
  passed 3σ, and that one was a false positive on synthetic data. Where the
  coefficient had sat at 0, nothing moves and a `FLOOR_HIT` warning about it
  disappears. Where it had left 0, the phase scale moves by up to 2.8 esd and
  Biso by up to 1.7 esd. The QPA guide's weak CaF₂ phase reads 1.34 ± 0.11 wt %
  where it read 3.58 ± 3.53 wt %.

### Files that change

- `capabilities().project_format_version` is `1.6`, where 1.11.0's was `1.5` (WP-2030).
  A project this release saves stores `formula` and `temperature` in its indexing controls, as null when unset, so 1.11.0 refuses any project 1.12.0 has saved.
  A 1.11.0 project opens here with no formula.

`Phase.extinction` is optional (schema 0.61, WP-1944), and a phase that declares none is saved with `extinction: null`.

- **1.11.0 opens less of what 1.12 writes.** It refuses that `null`, so a structure or a `.rex` project written by 1.12 does not open in 1.11.0.
  A project stops at "malformed history record".
  A Rietveld result and an instrument written by 1.12 do open there, measured on the NIST LaB6 fit.
- **1.12 opens what 1.11.0 wrote, and keeps the old plan behaviour.** A stored extinction value opens unchanged, as a declaration.
  So `mccusker_structural` still frees extinction on a 1.11.0 project's phases, as it did there.

A parameter 1.12 saves carries no `expr` key, which 1.11.0 reads as `None` (WP-1964).
A result whose joint fit declared a formula stores `basis: "expression"`, which 1.11.0 refuses.

A phase carrying `Phase.parent_cell` (schema 0.61, WP-1419) does not open in 1.11.0, even where it declares extinction.

### Requirements that rise

- rietx needs `rietx-kernels` 1.4 or later, where it accepted 1.3, and pip upgrades it with rietx (WP-1997).

## New

- The GUI's indexing form takes the specimen's formula and the pattern's temperature beside the volume limits, and the project stores them as `IndexingControls.formula` and `IndexingControls.temperature` (WP-2030, #1121).
  A run with a formula adds a `Z` column to the candidate table, each candidate's `formula_units`.
  A project file or the form refuses a bad formula or temperature in the words `rietx index` uses, from one function, `rietx.crystallography.atomic_volume.check_formula_input`.

- A joint fit takes a formula as a parametric equation (WP-1964): `ParametricEquation(basis="expression", expression="zero_a + grad/(exp(theta/T) - 1)")`, over `refine_multi(variables={...})` and the coordinate columns.
  An equation with `target=None` is an intermediate a later formula names, such as a temperature calibration.
  A variable named in `SharingMap.per_histogram` is one free number per pattern, such as a temperature offset.
  `MultiHistogramRefinement.preview_equations()` evaluates every equation at the start, before a fit.
  The grammar is the manual's `reference/expressions.md`, version `capabilities().expression_grammar_version`.

## Magnetic structures

- `magnetic_supercell` now builds the children it refused because their group names no tabulated type in the child's axes, such as a C-centred type in a primitive doubled cell (WP-1419, schema 0.61).
  Such a child states its cell through its parent's: `Phase.parent_cell` holds the parent's group, the transform, the parent's cell and one strain per Γ lattice strain the child's group allows, and the child's six cell parameters are derived from them and locked.
  `phases.*.cell.*` then frees the parent's edges; a strain is freed only by name, and a stage that frees the edges while a strain stays held reports the info diagnostic `PARENT_STRAIN_HELD`.
  A bound stated on the parent's cell carries over to the child, the cell safeguards (`CELL_RUNAWAY`, the minimum length, the support window) read the parent's edges, and a freed strain is bounded where the child's metric stays positive definite.
  `parent_cell=True` states every child this way, and `parent_cell=False` keeps the refusal; a child that built before builds exactly as before.
  On the shipped LaMnO₃, 5 of the 36 displacive children of Pnma now build.

## Changed

- **A restraint follows its atoms through `Refinement.edit(structure=…)`** (WP-2121).
  A restraint names atoms by position, so an edit that swapped two atoms left a bond restraint on two other atoms.
  The next fit pulled those atoms toward the old target, and nothing said so.
  Each restraint the new structure carried over now names the same atoms, as holds and ties already did.
  One whose atom was removed is dropped, and a warning names it.
  A series `prepare` hook that removes or reorders atoms gets the same.
  An edit is refused when a restraint, a rigid body or a distortion-mode record names an atom the new structure lacks.
  Such an edit was accepted before, and the next fit raised.
  A distortion-mode record's rows follow their atoms when the atoms are only reordered.
- The GUI's text document gives the right reason when a user tie's `=` annotation is edited: `ref.untie()` and `ref.tie()` change it.
  It said every tie came from the crystal system or the site symmetry.
- The GUI's indexing routes reach a cell on real lab data (WP-2124).
  `POST /api/index/extinction` screens a candidate on a project with no phase, where it was refused with `NO_PHASES`.
  `POST /api/index/adopt` takes any candidate, where it refused all but the one `best_or_none()` picks with `ADOPT_GATED`.
  An adopted candidate the gate did not pick writes its grade and caveats into the history node's label, and the `adopt` arm of `GET /api/index/result` gains `picked`.
  The Peaks panel still enables Adopt on the gate's pick until the redesigned panel lands.
  `POST /api/peaks` takes `two_theta_range` and `flag_contamination` beside `shoulders`, and edits to the list keep the options it was picked with.
