## Upgrading

Code written against 1.11.0 runs unaltered, except where § Code to check says otherwise.

### Code to check

- **Extinction is opt-in per phase** (#1391, issue #877). `Phase.extinction`
  now defaults to `None`, so code that reads `phase.extinction.value` on a phase
  that never declared it raises. On such a phase, `set_vary` and `set_values`
  naming `phases.N.extinction` raise `ValueError` for an unknown path. A custom
  plan's `phases.*.extinction` glob frees nothing there, and no code says so.
  `phase.extinction = 0.0` declares it, and `mccusker_structural` then frees it
  after the displacement parameters.
- `capabilities().schema_version` `0.61` also adds the `PeakFlag` member `residue_misfit` (WP-1969).
  A build older than this one refuses a peak list carrying it.

### Numbers that move

- **`mccusker_structural` frees no extinction unless a phase declares it**
  (#1391). Over 69 structural-plan fits in the test suite, 1 freed value in 98
  passed 3σ, and that one was a false positive on synthetic data. Where the
  coefficient had sat at 0, nothing moves and a `FLOOR_HIT` warning about it
  disappears. Where it had left 0, the phase scale moves by up to 2.8 esd and
  Biso by up to 1.7 esd. The QPA guide's weak CaF₂ phase reads 1.34 ± 0.11 wt %
  where it read 3.58 ± 3.53 wt %.

### Files that change

`capabilities().schema_version` is `0.61`, where 1.11.0's was `0.60` (WP-1944).
`Phase.extinction` is optional, and a phase that declares none is saved with `extinction: null`.

- **1.11.0 opens less of what 1.12 writes.** It refuses that `null`, so a structure or a `.rex` project written by 1.12 does not open in 1.11.0.
  A project stops at "malformed history record".
  A Rietveld result and an instrument written by 1.12 do open there, measured on the NIST LaB6 fit.
- **1.12 opens what 1.11.0 wrote, and keeps the old plan behaviour.** A stored extinction value opens unchanged, as a declaration.
  So `mccusker_structural` still frees extinction on a 1.11.0 project's phases, as it did there.

### Requirements that rise

- rietx needs `rietx-kernels` 1.4 or later, where it accepted 1.3, and pip upgrades it with rietx (WP-1997).

## New

- `rietx.indexing.index_residue` indexes what one cell leaves of a pattern, as a second `IndexingResult` (WP-1969, #933).
  It fits the first result's top cell (or `candidate=`) with the validation protocol's own fit, in `VALIDATION_MODE` (Pawley, following #1191), subtracts its peaks, picks the remainder at that fit's widths, flags a pick standing on more of the subtracted profile than its own height (`RESIDUE_MISFIT_RATIO`) as `residue_misfit`, and indexes the list; `INDEX_RESIDUE_PASS` names the cell and the flagged picks.
  A flagged pick stays a usable line, so the second result is graded with it counted as unindexed, and it never drives the search.
  A cell whose fit needs widths outside three times the list's own leaves no residue: nothing is picked, and the message says why (on #933's reproducer, whose first cell on `main` is a wrong cubic I one, it refuses rather than pick at that fit's 2° widths).
  A list handed in as positions carries an assumed width, so the width test is skipped for it and the fit is not seeded from it.
  On synthetic Si with MgO at 0.05, 0.1 or 0.3 of its scale, or NaCl at 0.1, the second result holds the second phase's cell first, at `medium`, and flags none of its lines. Synthetic Si alone leaves no pick and SRM 660c only flagged ones, so both abstain. On real mixtures, with the largest phase subtracted, it holds LaB6 first under 11-BM's cBN and finds no second phase in the eight IUCr CPD lab mixtures. It is opt-in: `index_pattern` is unchanged, and the first result is never modified.
