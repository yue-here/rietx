# rietx 1.11.0

This release carries everything that reached `main` in the eleven days after 1.10.0, 183 merged pull requests.
Six changes are the largest.
The indexer validates each candidate by a Pawley fit, where 1.10.0 ran one Le Bail pass, and a line screen counts the predicted lines the pattern lacks, so a wrong cell can no longer buy a count of zero by refitting its background.
`RefinementResult.parameters` lists only what the fit could move, so a cubic `b` and `c` no longer sit beside a held `a`.
`lab_calibrate` and `lab_bragg_brentano` refine the axial ratio S/L and hold H/L, because the two are interchangeable and a fit could report either as a measurement.
A stage whose χ² still falls, too slowly to move its parameters by an esd, now stops and says so.
A series no longer calls any step a jump or refits a pattern for a high Rwp: it records steps, direction gaps and code counts with no threshold, and it follows each phase and atom by name.
And a structure can hold more: a rigid body on a special position, planarity and torsion restraints, and a distorted child refined on its mode amplitudes.

Everything that changes what 1.10.0 code gets back is in [Upgrading](#upgrading).
1.10.0 refuses a structure, a history log, a refinement result or a series result that this release writes ([Files that change](#files-that-change)).

## Install

```sh
pip install --upgrade rietx
```

## Upgrading

Code written against 1.10.0 runs unaltered, with the exceptions in this list.

### Code to check

- `capabilities().schema_version` is `0.60`, where 1.10.0's was `0.59`.
  0.60 adds `RefinementResult.radiation` and `HistogramResult.radiation` (WP-2042), `Phase.distortion_modes` and `RefinementResult.distortion_totals` (WP-1419), `IndexingResult.formula`, `IndexingResult.temperature`, `PeakList.instrument_undeclared` and `CellCandidate.formula_units` (WP-2030), `PlanarityRestraint` (WP-1809), `GeometryTable.torsions` and `TorsionRestraint` (WP-1815), `StageResult.rwp`, `StageResult.termination` and `StageResult.window_loss` (WP-1334, WP-2047), and `SeriesResult.code_counts`, `SeriesResult.direction_gaps` and `SeriesEntry.rwp_over_median` (WP-2003).
  `RestraintRow.kind` gains `"planarity"` and `"torsion"`.
  [Files that change](#files-that-change) says which documents open where.
- `RefinementResult.parameters` lists a parameter only when the fit could move it (WP-1999, ruled by the maintainer 2026-11-01).
  1.10.0 listed a tied parameter whatever its source did, so a cubic `b` and `c` stayed beside a held `a`, at the carried value and with no esd.
  Code that looks up a held path there now finds no row.
  Read the value from the model, or list every parameter with `Refinement.parameters()`.
  A Le Bail fit of NAC reports 2 tied rows where 1.10.0 reported 18, and a series draws no trajectory point at a pattern where the path could not move.
  The printed result does not change, and a CIF still states every cell length and coordinate.
- `lab_calibrate` and `lab_bragg_brentano` refine the axial ratio S/L and hold H/L at the value you set (WP-2012, ruled by the maintainer 2026-11-01).
  Swapping the two gives the same pattern to the last bit, so two free ratios had two mirrored minima and a fit reported whichever it reached.
  Code that read a refined `instrument.geometry.axial_hl` from either plan now reads the value it declared.
  The `refine_axial_asymmetry` suggestion names S/L alone.
  An imported GSAS-II recipe still frees both ratios from its single SH/L flag.
- `Refinement.fit` no longer raises `ValueError: array must not contain infs or NaNs` when a stage's model turns non-finite (WP-2048).
  The stage ends at its start with `status="diverged"`, the warning `STAGE_NOT_FINITE` names the stage, what went non-finite and the free set, and the fit carries on.
  Code that caught the exception reads the stage's status.
- `PeakList` refuses a line whose `q_esd` does not follow from its `two_theta_esd` (WP-2071, issue #1236), in the validator that already refuses a stale `q`.
  The engines weight lines by `q_esd`, so in 1.10.0 an edit to one line's `two_theta_esd` loaded clean and never reached the search.
  Set both together through `q_esd_of_two_theta`, or rebuild the list with `pick_peaks` or `from_positions`.
- `read_fullprof_pcr` refuses `Nor = 0` with a non-zero `Pref1`, the exponential preferred-orientation function (WP-2058).
  1.10.0 built such a file with no preferred orientation and said nothing.
- `write_topas_inp` refuses a `tie_equal` group whose members hold two values (WP-1911), at the 1e-6 bar the TOPAS reader refuses one on read.
- `SplitFamily(...)` built without `emission_line` raises (WP-1339), since a default of 0 read as an answer.
  A stored dump still loads.
- `predicted_but_absent` is a **capping** caveat (C3, issue #916, PR #941): a cell carrying it alone grades `medium`, where 1.10.0 graded it `low`; `INDEX_REFUTING_CAVEATS` no longer names it.
  Code that read the caveat as a refutation reads `supercell_refuted` instead, which is what refutes an oversized cell now.
- `LeBailValidation` gains `predicted_but_absent_uncancellable`, `predicted_but_absent_uncancellable_in_window` and `absent_source`; `SupercellCheck` gains `relation`, and its `index` is 0 when the parent is not a sublattice (schema 0.60, indexing thresholds 1.12).
  Every field is defaulted to the reading a 1.10.0 document had.
- The indexer validates each candidate by a Pawley fit, where 1.10.0 ran one Le Bail pass (WP-2011).
  `LeBailValidation.mode` records which (schema 0.60), and a 1.10.0 document reads `"lebail"`.
  The type, `CellCandidate.lebail`, `validate_by_lebail` and `lebail_rwp` keep their names.
- Under a time ceiling (`quick`, or a declared `total_budget_seconds`) the search stops 15 % of it early, where 1.10.0 stopped 8 % early, and the validation fits run cheapest first, each on what the clock holds, where 1.10.0 gave each an equal share in rank order (WP-2011).
  `rietx.indexing.engines.budget_exhausted_diagnostic` loses its `ceiling_hit` argument, since a validation fit no longer has a share of its own to run out of.
  Code that compared two candidates' `lebail.rwp` reads a different number: a cell that predicts every reflection of another now fits at least as well, so the comparison separates a wrong metric and never an oversized cell.
- `determine_extinction_symbol` now refines the cell before it screens (`refine_cell=True` is the default, issue #726).
  A caller that hands it a certified cell and wants that cell held passes `refine_cell=False`.
  A caller that reads `best_or_none()` gets `None` on a new reason as well: `ExtinctionScreen.status == "unreliable"`.
  0.60 also adds `ExtinctionScreen.prefit_rwp`, `ExtinctionScreen.reference_rwp_net` and `ExtinctionScreen.perfect_fit_rwp_net`, each defaulting to `None`.
- `SearchSpec.from_formula` sets a volume ceiling only, for every formula (WP-2030).
  1.10.0 also set `min_volume` to 0.8 × `z` formula units by Hofmann's volumes, which excluded the true cell of 15 of 16 inorganic standards; `min_volume` now stays at the 15 Å³ default unless you pass it beside the formula.
  With `z=None` the spec narrows nothing, where 1.10.0 set a floor of one formula unit.
  A search declared this way covers smaller cells and can take longer.
  `CompositionCheck.in_volume_window` tests the same ceiling alone: it read `False` on 15 of 16 true inorganic cells under the 0.8 floor.
- `INDEX_Z_NOT_INTEGER` is withdrawn, with `rietx.indexing.diagnostics.Z_INTEGER_TOLERANCE`, and `candidate_diagnostics` no longer takes `formula` or `temperature` (WP-2030).
  It fired on 12 of 16 true inorganic cells: against Hofmann's volumes a correct inorganic cell looks like a wrong Z.
  The number it judged is recorded as `CellCandidate.formula_units` when `index_pattern` is given `formula=`.
- A chemical formula whose full stop reads two ways is refused (WP-2030): `formula_unit_volume`, `SearchSpec.from_formula` and `index_pattern(formula=)` raise `ValueError` on `"CuSO4.5H2O"`, which 1.10.0 read as 4.5 O, 39 % low.
  What is refused is a decimal count of 1 or more, with no leading zero in its fractional part, straight after an element or a bracket and followed, past any whitespace, by one of 13 adduct molecules (H2O, D2O, NH3, H2O2, HCl, CO2, CH3OH, CH4O, C2H5OH, C2H6O, CH3CN, C6H6, C4H8O) that ends the part: `"CuSO4.5H2O"`, `"CuSO4.5 H2O"`, `"CuSO4.5 H2 O"`.
  Write a hydrate with `·` (`"CuSO4·5H2O"`).
  Every other decimal reads as 1.10.0 read it: `"Fe2.95O4"`, `"Li1.05Mn1.95O4"`, `"Ca9.5(PO4)6F2"` and `"Mg0.5SiO3"` are unchanged.
  A solvate whose molecule is not on the list (`"ZnCl2.2C5H5N"`) still reads as a decimal.
- A plan's last declared stage now converges at the solver's 1e-9 when a closing stage follows it, as it did before 1.10.0 (WP-2045).
  `RefinementPlan.stage_ftols()` ends `[..., None, None]` where it ended `[..., 1e-6, None]`, and that stage's `StageResult.ftol` reads `None`.
  A stage's own `Stage.ftol` still wins.
- Code that filters a joint result's `BISO_NEGATIVE`, `BISO_UNUSUALLY_LARGE` or `ADP_NOT_POSITIVE_DEFINITE` findings by the bare path of a per-histogram parameter (WP-2028).
  Such a finding's path now reads `hist.<h>.…`, where 1.10.0 wrote it bare from pattern 0.
- Code that reads a joint result's `ticks` or `tick_hkl` as one row per phase, where a phase carries a moment (WP-2028).
  A neutron pattern's magnetic phase now has its own `"<phase> (magnetic)"` row there, as a single fit's has had since issue #278.
- `SEQUENTIAL_DISCONTINUITY` is gone, with its three thresholds `DISCONTINUITY_FACTOR`, `DISCONTINUITY_SIGMA` and `MIN_POINTS_FOR_DISCONTINUITY` (WP-2003).
  A series no longer calls any step a jump: what one means depends on the sample's history, which no pattern records.
  `SeriesResult.discontinuities` is renamed `SeriesResult.steps`, and it now lists every refined path's step between consecutive patterns, in esds of the later fit (`SeriesStep.size_esd`), largest first, rather than the one flagged step per path.
  The summary's trajectory block names the largest; `rx.explain("SeriesResult.steps")` carries the reading.
  `fit(verify_discontinuities=True)` is `fit(verify_steps=k)`, which refits the k largest steps cold and writes `SeriesStep.cold_ratio`, where the diagnostic's `value` held it; a bool is refused.
  A series saved by 1.10.0 opens with its `discontinuities` dropped and `steps=None`.
- A series no longer refits a pattern because its Rwp is high (WP-2003).
  A warm fit climbs the restart ladder when it diverged or raised; `reseed_factor` defaults to `None`, where 1.10.0's 1.25 sent any warm fit above 1.25 × the median Rwp of the accepted patterns up the ladder, and `RESEED_FACTOR` is gone.
  Pass a factor to keep that fence; a bool, a non-finite or a non-positive one is refused.
  `SEQUENTIAL_RWP_OUTLIER` is gone with it, and `SeriesEntry.rwp_fence` is replaced by `SeriesEntry.rwp_over_median`, the kept attempt's Rwp over the median of the patterns accepted before it, with no threshold; `rx.explain("SeriesEntry.rwp_over_median")` says how to read it beside GoF and R<sub>exp</sub>.
  A step into or out of a high-Rwp pattern is now a row of `SeriesResult.steps`, and the trajectory plot no longer boxes such a point.
  A series saved by 1.10.0 opens with each entry's `rwp_fence` dropped and `rwp_over_median=None`.
- A warm fit carrying an `error`-level diagnostic is now rejected like a diverged one (WP-2003).
  It climbs the restart ladder, and a pattern whose kept attempt still carries one after the last rung is quarantined: it seeds no successor, joins no median, and no step starts or ends on it.
  In 1.10.0 a `converged` fit under `MODEL_FAR_FROM_DATA` seeded the next pattern, which then collapsed too unless the Rwp fence caught it.
  `SEQUENTIAL_UNRECOVERED` now says whether the kept attempt diverged or which `error` code it carries.
  On a series saved by 1.10.0, `moved_paths`, `magnetic_trajectory` and the trajectory plot leave such a pattern out as well, while what it seeded when it ran stays as it was.
  A `max_iter` fit is not rejected.
- A series no longer bounds what a warm pattern's first attempt may spend (WP-2003).
  `first_rung_factor` defaults to `None`, where 1.10.0's 3.0 capped it at three times the dearest first attempt the chain had converged, and `rietx.sequential.FIRST_RUNG_FACTOR` is gone.
  Pass a factor to keep a bound; a bool, a non-finite or a non-positive one is refused.
  A bound now caps each stage of the first attempt and is sampled from each converged attempt's dearest stage, where 1.10.0 sampled the stages' sum; an attempt with any stage stopped at it escalates even when its closing stage converged, which 1.10.0 kept as `converged`.
  Under `reseed=False` a factor bounds nothing, where 1.10.0 still escalated a first attempt it had cut.
- `SEQUENTIAL_PERSISTENT_FINDING` is gone, with its threshold `rietx.sequential.MIN_POINTS_FOR_PERSISTENCE` (WP-2003).
  A series now counts every per-pattern code over its patterns, with no threshold.
  `SeriesResult.code_counts` lists each code and parameter as a `SeriesCodeCount`: the patterns it fired on, the patterns in the series and the worst level, largest count first.
  1.10.0 reported a pair only when it fired on more than half of a series of five patterns or more, and no measurement set either number.
  On a 248-pattern ramp whose unmodelled phase appears at pattern 124, `FLOOR_HIT` fired on 63 patterns, and the half kept it silent.
  The summary's trajectory block names the three largest counts, and `rx.explain("SeriesResult.code_counts")` carries the reading.
  `summary(deliverable="series")` no longer prints a `persistent findings` row.
  A series saved by 1.10.0 opens with `code_counts=None` and its old diagnostics as written.
- `SEQUENTIAL_PATH_DEPENDENT` is gone, with its threshold `rietx.sequential.PATH_DEPENDENCE_SIGMA` (WP-2003).
  Under `direction="both"` a series now records every path's forward-backward gap at every pattern, with no threshold.
  `SeriesResult.direction_gaps` lists them as `DirectionGap` rows: the two values, the signed gap, the gap in combined esds and the attempt each chain kept, largest first.
  1.10.0 reported a path only past 3 combined esds, and no measurement set that number.
  The summary's trajectory block names the largest gap of the three paths that lead, and the `ordering artefact` row of `summary(deliverable="series")` quotes the largest.
  The three things to do about a large gap moved from the diagnostic's suggestion into `rx.explain("SeriesResult.direction_gaps")`.
  The `[path-dependent]` tag on a trajectory plot's title is now the path's largest gap as a number.
  The GUI server's series payload drops `path_dependent` and `path_dependence_sigma`, and each trajectory's `n_sigma` is read off the record.
  A series saved by 1.10.0 opens with `direction_gaps=None` and its old diagnostics as written.
- `SEQUENTIAL_PATH_CHECK_INCOMPLETE` is split in two (WP-2003).
  A comparison that did not run now fires `SEQUENTIAL_PATH_CHECK_NOT_RUN` at `warning`, where 1.10.0 fired the same code at both levels.
  `SEQUENTIAL_PATH_CHECK_INCOMPLETE` now fires only at `info`, when the comparison ran on fewer patterns or paths than the series has.
  A 1.10.0 series carrying INCOMPLETE at `warning` still reads as "did not run".
- A series ranks a pattern's attempts in a new order (WP-2003).
  An attempt that diverged or carries an `error`-level diagnostic now loses to one the first-rung bound cut short, where 1.10.0 kept the diverged one if it ran to completion.
  Between two attempts in the same state the lower full least-squares cost now wins: the last stage's `StageResult.cost_final`, which counts the background-penalty, Pawley-restraint and soft-restraint rows beside the data.
  1.10.0 compared Rwp, which sees the data rows alone.
  Where the two attempts did not minimise one objective, Rwp still decides: different σ, a different restraint count or weight, or a Pawley fit.
  On the CPD sample-1 chain with every attempt forced, the two rules kept the same attempt on every pattern.
- A series follows each phase by its name and each atom by its label, where a `prepare` hook adds or removes either part-way (WP-1991).
  Every path of a `SeriesResult` now reads one numbering, that of the structure the series was given, so `trajectory("phases.0.atoms.3.biso")` stays on one atom.
  In 1.10.0 a `prepare` that removed O3 from one pattern of a PbSO₄ series joined O4 and then O5 into that trajectory.
  `SeriesEntry.pattern_paths` and `Trajectory.pattern_paths` give each pattern's own path, and `SeriesResult.phase_names` and `.atom_labels` record the numbering.
  A series now refuses a phase name used twice, or an atom label used twice in one phase, with a `ValueError`.
  A series saved by 1.10.0 opens as written.
- A rigid body whose atoms straddle a symmetry element is now refused, `RIGID_BODY_IMAGE_OVERLAP` (WP-1807, #876).
  In 1.10.0 such a body built and fitted in silence while the cell held part of it twice: a PbSO₄ SO₄ moved 0.03 off its mirror counted S 8 and O 32 in a cell of 4 and 16.
  A model or `.rex` history holding one now refuses at the next table build, naming the pair of atoms, the operation, the distance and the doubled counts.
  A body whose atoms carry a `disorder_group`, or whose overlapping atoms and images in one place have occupancies summing to 1 or less, is not refused.
  The remedy is in the message: put the body's origin on the element and list one atom per image.
- `read_pattern` refuses a reduced total-scattering file, `PATTERN_TOTAL_SCATTERING` (issue #1240), where 1.10.0 read it as a 2θ pattern with nothing to say the axis was r or Q.
  A file is refused when an `#L` line labels r against G or Q against S or F, when its header is PDFgetX2's or PDFgetX3's, or, with neither, when it is named `.gr`, `.sq` or `.fq`.
  The exception is `rietx.io.formats.TotalScatteringRefused`, a `ValueError` carrying the record as `.diagnostic`; the record also lands on `diagnostics=` when a list is passed.
  `capabilities().reader_formats` gains the refusal `total_scattering`, directly above `xy`.
  A 2θ scan that only carries one of those suffixes opens under any other name.
- `HumpComponent.position` is required (WP-2013, ruled by the maintainer 2026-11-02), where 1.10.0 defaulted it to 0.0° 2θ.
  `HumpComponent()` and a hump dict without `position` now raise, naming the field; give the hump's apparent 2θ, e.g. `position=rx.Parameter(value=5.0, unit="deg")`.
  A stored document that omits it still opens, at the old 0.0°: a `.rex` history and an instrument profile are read under `rietx.schemas.common.STORED_DOCUMENT`.
  Every writer has always written the field, so only a hand-written document is affected.
- `ProjectFormat.reports_at` is `"build"` or `"both"` (WP-2013): its `"read"` member is gone, since no format declared it.
- `Refinement(..., history=path)` raises `FileExistsError` when `path` already holds a history log (WP-2031), where 1.10.0 appended a second tree whose node ids restarted at `n0000`.
  `RefinementTree.for_data` asks again, and a series given a history directory raises before its first fit when the directory holds a log the run would write.
  A script rerun on one path passes another path, or continues the log with `RefinementTree.load` and `Refinement.from_node(tree, "head")`.
  A file 1.10.0 doubled this way still opens: `RefinementTree.load` returns the last tree and reports each earlier one as `HISTORY_EARLIER_TREE_SKIPPED`, naming its lines.

### Numbers that move

- A stage that crawls now stops (WP-1334, ruled by the maintainer 2026-11-03).
  Under the default driver, a stage ends once another 300 residual evaluations, at the rate of the last 100, would lower χ² by less than χ²_red, the decrease one esd of joint travel buys.
  It reads `status="converged"` with `StageResult.termination` `"slow_descent"`, and the info diagnostic `STAGE_SLOW_DESCENT` names it.
  `STAGE_MAX_ITER` now names only the stages that ran out of budget again.
  Over the series tests, 6 of 184 fits in 5 chains move, by at most 0.067 esd and with fewer evaluations, and their rungs, statuses and quarantines do not change.
  `solver="trf"` has no such rule, and `rietx.optimize.lm.SLOW_DESCENT_ESD = None` switches it off.
- On the NIST SRM 660c protocol, holding H/L at the declared 0.025 moves S/L from 0.02546(357) to 0.03704(74) (WP-2012).
  The cell moves 0.36 ppm, a fifteenth of its esd, and the esds of the cell and the specimen displacement fall to 0.71 and 0.67 of their old size.
  Rwp goes from 0.087429 to 0.087431.
- A Stephens anisotropic strain block now replaces the isotropic `lor_strain` it locks (WP-1467).
  In 1.10.0 it sat on top of a frozen copy of that width, so a block declared after an isotropic fit could make no reflection narrower than the old width, and the anisotropic fit could end above the isotropic fit it contains.
  A fit that declares a block over a non-zero `lor_strain` moves, and one whose `lor_strain` was zero does not.
  `STEPHENS_STRAIN_NOT_POSITIVE` now gives the share of the phase's m·|F|² carried by the reflections the clamp left with no strain width.
- A fit keeps each site's multiplicity from its start to its answer (WP-2052, issue #1088).
  A half-occupied general atom is the usual way to write a split pair across a mirror, and where the data cannot resolve the pair the solver can stop on the mirror.
  1.10.0's next compile then counted the site at the mirror's multiplicity and it lost half its atoms: on the issue's noise-free Pnma model the default plan returned 10 O per cell for 12, χ²_red 23.2 and O1 Biso −1.64.
  It now returns 12 O and Biso 0.600, the truth.
  The new warning `SITE_MULTIPLICITY_KEPT` names a site whose returned coordinates a fresh compile would count at fewer positions, with the atoms per cell both ways.
- On a frame where no phase is seen and the residual is noise, a stage now holds the instrument terms that reach the pattern only through peaks (WP-2049, WP-2086, PR #1406): the zero shift, the displacement and the profile widths.
  1.10.0 refined them against noise and quoted an esd: on a planted series, frame 87 fitted alone gave a zero shift of −0.0129 ± 0.0015° against a truth of 0.006°.
  That frame now quotes no zero shift, and `PHASE_UNCONSTRAINED` names the instrument rows it held.
  The residual counts as noise when its Durbin-Watson d reaches Hill and Flack's Q, and with no line of any phase in range the hold applies whatever d reads.
  A scale at zero reads the same on a phase whose peaks missed, and there d stays under Q, so the instrument terms stay free and the phase can still reach its peaks.
  On a synthetic LaB6 pattern, this release reaches the cell at 1.10.0's rate: 93 of 100 noise draws from a start 2 % off, falling to 37 at 2.5 %.
  Tutorial 05's 2 % step works again.
  A blank frame with structure in its residual, a hump or rebinned noise, reads under Q and keeps its instrument terms free, as on 1.10.0.
  A fit that fails can run for minutes, because its widths walk until every evaluation covers the whole pattern.
  Two measured failed fits took 333-348 s and 390-395 s, about 100× longer than the 3.4-3.7 s of a build holding on every such frame, against 43 s and 293 s stored for 1.10.0.
- A stated prior cell no longer lifts its own lattice's grade (WP-2082, issue #1308).
  A candidate whose `found_by` holds `"prior"` and one engine reads `low`, where 1.10.0 read `medium` and counted the prior as the second engine.
  With all three engines running, no grade moved on the issue's fixture.
- The report names a one-sided low-angle residual as axial asymmetry when both axial apertures are 0 (WP-2054, #1106).
  1.10.0's report had no column to read it with, so the residual went unnamed.
  Such a fit can now get `refine_axial_asymmetry`: on #1106's script the regions below 40° read +0.020 to +0.025 at 7-9 esd, and 15 of 15 regions pass their gates, where 12 did.
  Re-run the plan with a stage freeing S/L when it fires: on SRM 660c that takes Rwp from 0.129 to 0.087, where one stage appended to the converged fit reaches 0.125.
  A fit that declares an aperture gets the same report as before.
- `split_localisation` counts a family that straddles an end of the fitted range (WP-1339).
  It can return one more `SplitFamily` per range end and emission line, so `split_share` and `n_split_families` can move on such a pair.
- A magnetic fit's moment moduli are refined on their analytic columns (WP-1327, PR #1206), so a converged fit can differ from 1.10.0's in its last digits.
  On Cr₂WO₆ 4 K (HB-2A, the acceptance protocol), against the same fit with the modulus columns forced to the forward difference: χ² agrees to 4.4e-11 relative, every value to 5.5e-6 esd and every esd to 7.2e-7 relative, with Rwp 0.10475 in both.
  On a synthetic two-site fit the same three agree to 2.1e-16, 1.0e-9 esd and 5.9e-7 (`tests/test_moment_jacobian.py`).
- A fit whose last declared stage ran away no longer stalls in its closing stage (WP-2045).
  At 1e-6 that stage could stop on a plateau of its own frozen peak windows, where a widening axial ratio pushed intensity out of the model.
  On the IUCr round-robin series carried whole from mixture to mixture, cpd-1b's warm fit stopped there with `axial_sl` at 557.8, and its closing stage ran for tens of minutes.
  It now stays on its warm attempt at `axial_sl` 0.008 and Rwp 0.140, against 0.137 for the fit from the initial model, and the two patterns take 8 s on an arm64 Mac.
  `closing_window_tol=None` is no longer needed for that series.
  On the four acceptance protocols the change costs 1.04-1.07 times the evaluations and moves no answer by 0.001 esd.
- A series with a lasting rise in Rwp costs less (WP-2003): with no default Rwp fence, the planted-events series, whose unmodelled phase appears at pattern 124, takes 3 111 evaluations and climbs no rung, where the fence spent 13 034 escalating 115 patterns, and across eight measured series the fence's escalations had moved no value by more than 7.2e-4 esd.
- `HIGH_CORRELATION` and `identifiability.top_correlations` no longer report a correlation the data does not determine (WP-2050, PR #1306).
  When the fit holds a direction the data cannot move, a correlation against one of its parameters is set by rounding, and so is a correlation between two parameters that lean on it.
  Such a pair is now computed with that direction removed, or left out when one member belongs to it.
  On the IUCr round-robin brucite pattern the Gaussian size, Gaussian strain and W are that direction, and a 1e-14 change to one start value gave 35, 36, 39 or 42 warnings.
  It now gives 35 at all eight nudges tried, where the unnudged fit gave 36.
  The warning it loses is `lor_size ~ lor_strain`, which reads −0.896 with the direction removed, under the 0.98 limit.
  A pair whose two members both belong to the direction still reads ±1 and stays a `FLAT_DIRECTION`.
- A joint fit's curves and statistics come from a compile at its answer, as a single fit's do (WP-1421).
  Under a default plan the closing stage already ends there, and the WP-1131 size pair reports the same five digits.
  With `closing_window_tol=None`, a pattern whose last stage widened its peaks moves: Rwp 0.09658 → 0.10207 on that pair, whose report stops listing 38 cut peak tails as unmatched peaks.

  A child stated at the parent is seeded off it along a direction whose stabiliser is exactly the child's group, since every amplitude outside the identity irrep has a zero column there.
  The GSAS, GSAS-II, FullProf and TOPAS project writers refuse a phase carrying `distortion_modes` with the one line that writes plain coordinates.

- `Structure.from_cif` reads a magCIF that names its parent space group under `_parent_space_group.name_H-M`, as FullProf writes it (WP-1918, issue #1063 item 2).
  1.10.0 refused such a file as stating no space group; the magnetic dictionary defines only `_parent_space_group.name_H-M_alt`, and the undefined tag can mean nothing else.
  The new info diagnostic `CIF_MAGNETIC_PARENT_TAG_UNDEFINED` names the tag that was read. A file stating both tags with different groups is refused, quoting both.

- `Structure.from_cif` reads a CIF whose structure block sits beside blocks that state nothing, no tags or only `_audit_` tags, such as an empty `data_global` ahead of it (WP-1918, issue #1063 item 1).
  1.10.0 refused such a file as "not a CIF"; the new info diagnostic `CIF_EMPTY_BLOCK_SKIPPED` names each block skipped.
  A file with two blocks holding atom sites, or one beside a block that states anything else, is still refused, and the message now names the blocks and what each states.

- A CIF using the pre-2016 draft magnetic tags (`_magnetic_atom_site_*`, `_magnetic_cell_*`, `_magnetic_space_group_symop_operation_*`) is refused by name (WP-1918, issue #1063 item 3).
  1.10.0 said "no atom sites found" where the sites were under the draft tags, and read the nuclear half of a file whose sites were under `_atom_site_`, dropping its moments with nothing said.
  Two follow-ups from the review: a line inside a semicolon text field that starts with a draft tag no longer refuses the file (nor does a modulation tag, a `kxkykz` line or an `_atom_site_moment.` line inside a text field refuse or reroute one: all four raw-text scans skip fields), and a k ≠ 0 stated only under the draft's `_magnetic_propagation_vector_kxkykz` now reaches the magnetic-supercell refusal, as the same k under `_parent_propagation_vector.kxkykz` always did (1.10.0 read such a file as k = 0); the refusal names the k tag the file actually used.

- A site within 5e-4 (fractional, per coordinate) of a special position is counted once, on the special position they collapse to, however its phase was built (#1007).
